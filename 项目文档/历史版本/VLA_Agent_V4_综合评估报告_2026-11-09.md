# 统一持续自进化 VLA Agent：综合评估与方法研究建议（修订版）

日期：2026-11-09。评估对象：《统一持续自进化 VLA Agent 研究方案 V4.0》，2026-11-06，20 页。

本版综合 V4、上一版评估、用户提供的独立审查及针对新增论点的一手文献核查。完整系统目标与论文方法主线分别评价；不沿用此前“9 族”选题。本报告是评估与候选研究建议，不是 V5 最终方案，不改写 Q01—Q23 原始决策，Q24 保持未决。

**一、总体判断：保留完整愿景，先找到决定方法身份的科学问题。**

V4 的系统组织与研究边界基本连贯，值得继续推进；目前还不能认定它已经具有明确的方法新颖性。真正缺少的是：一个在机器人持续改进中有实际代价的具体困难、一条能利用该困难结构的学习规则，以及区别于强现成方法的可检验预测。

用户提供的审查抓住了上一版报告的一项不足：提高版本管理、实验公平和统计严谨性，有助于可信地判断方法，却不会自动产生方法。下一步应把问题发现、机制构想与最小实现并行推进，避免先铺开所有组件，再寻找可以写成论文的现象。

| 维度 | 修订判断 | 决定这一判断的证据或缺口 |
|---|---|---|
| 科学问题价值 | 有潜力，本项目代价待辨别 | 持续修复、证据选择和能力交接有实际需要，但尚无本项目频率／成本证据 |
| 架构完整性 | 可保留 | 前台、后台、证据和独立验收职责合理 |
| 架构新颖性 | 有限 | 相关部件与多种组合已有直接近邻 |
| 具体方法新颖性 | 未确立 | A/B/C 表示、反馈利用与学习算子尚未裁定 |
| 选择性证据—修复方向 | 优先诊断候选之一 | 与原目标关联强，但与 VOI、记忆学习和决策聚焦取证重叠明显 |
| B 与新版 VLA 再适应 | 应平行比较的候选 | 路径较直接，与 Robo-COP 接近；简单校准可能已足够 |
| H3 元改进 | 保留为完整目标，证据难度高 | 要排除前台增强、记忆增长和更多尝试 |
| H4 权重编辑 | 保留独立条件分支 | 机制干预、正常能力保持与闭环收益须分别成立 |
| 基础工程可行性 | 较高，仍有接入工作 | 有可复用源码，尚无整个项目运行验收 |
| 六个月阶段产出 | 可规划，不保证完整愿景完成 | 取决于问题残余、模型接入与研究吞吐；不作为方向上限 |
| 论文定位 | 随实际贡献选择 | 方法、系统、评价协议和实证发现都可有价值，不能相互替代证据 |

当前建议是有条件继续：先检验候选困难与现成解法的剩余差距，再收敛算法。对证据—修复方向给予优先诊断机会，不把其他 AI 的偏好转换成用户已经选定的主算法，也不认定 A+C 天然优于 A+B 或 B+C。

**三、目标约束：统一架构不缩水，阶段主张不超出证据。**

| 完整研究要求 | 本版保留方式 |
|---|---|
| Super-agent × VLA × Meta-RSI 统一架构 | 继续作为总体系统目标 |
| A/B/C 三类关系具有可继承自进化能力 | 三类都需要在完整架构中落实；阶段只验证一部分不等于全部完成 |
| 前台稳态与后台异步改进 | 前台执行已验收版本，候选在后台产生 |
| Evidence Core 与 L0/L1/L2 | 作为可信学习和评估基础；具体采集策略未冻结 |
| 独立安全与发布边界 | 对研究代理保持受保护权限与判据 |
| 仿真系统验证、真机关键验证 | 保留角色分工；不要求现场复制全部消融 |
| H3 元改进器自身进步 | 保留完整目标和独立判据 |
| H4 局部机制修复 | 保留条件性专项与独立停止条件 |
| 六个月阶段窗口 | 用于安排依赖与优先级，不定义完整愿景上限 |
| Q24 主动机会选择 | 仍未裁定；以下取证候选不等于选定 Opportunity Manager 的算法 |

“共同进化”不要求每一轮都更新每个模块。若某轮 VLA 改善后旧 B 仍有效，保持 B 不变是合理选择；若证据不足，暂缓更新也可正确。要证明的是系统能从反馈中产生并继承有价值的改变，而非更新次数或可修改字段数量。

**四、新颖性：需要同时面对机器人近邻与通用决策／元优化方法。**

| 近邻 | 已公开覆盖 | 本研究仍需建立的差别 |
|---|---|---|
| [EmbodiedRSI，§3.2–3.3](https://arxiv.org/html/2610.10498v1) | VOI 实验选择、代码／技能联合比较、基于后续收益学习记忆动作 | 选择性执行证据的哪种失真未被其机制充分处理，专门规则带来什么额外收益 |
| [Robo-COP，§3](https://arxiv.org/html/2610.09228v1) | 部署数据筛选、按需 VLA 更新、候选验证及策略相关编排记忆修订 | 超过普通记忆修订和重新校准的职责学习机制 |
| [AdaRSI，§4](https://arxiv.org/html/2610.20474v1) | 先修 Harness，再对持续失败按需训练并验证 | 证据选择／不确定性引起的修复决策问题及其专门解法 |
| [SHAPER，§3](https://arxiv.org/html/2608.11350v1) | 共同演化技能与上下文构造代码 | 超过上下文筛选、总结和技能规则优化的作用机制 |
| [Zetta，§2](https://arxiv.org/html/2608.16590v1) | 运行时监督、恢复和工具演化 | B 的新型学习规则与长期反馈收益 |
| [PhysEvo，§3](https://arxiv.org/html/2610.08995v1) | 执行与诊断工具可继承修订 | 改进能力而非单次工具修复的独立证据 |
| [RegenHarness，§4](https://arxiv.org/html/2609.27612v1) | 证据、权限、版本发布及回滚 | 可学习关系的额外效果，而非仅工程治理 |
| [GEPA，§2–3](https://arxiv.org/html/2507.19457v1) | 通过执行反馈优化复合系统组件 | 相同字段、信息和预算下，专用协同机制的收益 |
| [EvoX，§3–4](https://arxiv.org/html/2602.23413v1)／[HyperAgents，§3、§5.2](https://arxiv.org/html/2603.19461v1) | 搜索策略或改进机制自身变化与评价 | 机器人反馈结构带来的新问题，以及共同起点的新问题考试 |
| [SEAR，§2–4](https://arxiv.org/html/2610.18792v1) | 经验库、重启、独立评判、泛化与成本对照 | 超过一般自进化评价规范的具体贡献 |
| [Robotics Weight Editing，作者原文](https://github.com/Cuzyoung/robotics-weight-editing/blob/main/site/zh/index.html) | 机制干预后近似写入权重 | 特定失效修复、能力保持、多轮兼容的独立机制 |

两个新增的关键比较对象如下。

- [Performative Prediction with Selective Labels，§3–4、§6](https://arxiv.org/html/2610.08272v1) 研究选择性标签下的反复重训，给出有条件的稳健更新分析；实验域是借贷。相关保证依赖损失结构、分布敏感性和标签概率界等条件。它不直接给出 VLA 非凸闭环系统的保证，也不等于证明稳健迭代本身收敛。
- [Certifying when decision-time information justifies adaptive experimentation，§4.1–4.2](https://arxiv.org/html/2607.27651v1) 已讨论按决策收益评价额外测量，并采用随机探索、交叉拟合及净收益下界。它进一步削弱了“修复价值取证＋保守选择”作为一般原创机制的主张；其具体实验和假设也不能直接替代机器人验证。

因此，V4 的“关系显式化、版本化、双向反馈”是实现基础，不足以单独构成新方法。新增审查提出的方向比框图更具体，但仍需跨过新颖性门槛。与 EmbodiedRSI 的潜在差别应通过“全覆盖原始证据可用时是否仍有差距”以及“选择性证据条件下何种纠正有效”等实际比较建立，不能据其未强调某术语就认定它无法处理。

**五、首先辨别现象：四种反馈问题不能混为一谈。**

上一版将“未保留视频”与“没有失败标签”靠得过近，表述需要收紧。V4 的 L0 若对所有任务保留了可靠终局判定，即使 L1 视频被选择性保存，系统仍可能准确知道总体成功率。此时缺失的是用于诊断或训练的细节，而非结果标签。

| 现象 | 实际缺失或变化的对象 | 可观察例子 | 优先比较的现成解法 |
|---|---|---|---|
| 结果选择性缺失 | 部分任务／事件没有可靠 Y | 未报警片段不被评价，未知被当成功 | 独立结果检查、随机审计、显式未知标签 |
| 诊断／训练证据缺失 | Y 已知，但关键 E 未保留 | 知道抓取失败，却缺少滑落前画面 | 循环缓冲、固定／分层保留、事件邻域保存 |
| 干预造成反事实不可见 | 接管后的结果可见，未接管会怎样不可见 | 人类救回任务，无法据此标定裸 VLA 成败 | 动作来源记录、可复位仿真分支、受限策略评价 |
| 策略引起状态分布变化 | θ／B 更新改变遇到的状态与失效 | 新策略少走旧路径，出现新边界状态 | 版本条件化、匹配回归、简单重新校准 |

这四者可以共同存在，但对应不同估计对象。视频保存概率不能自动当作结果标注概率；B 的接管又可能改变结果本身，不能仅用“缺失标签”模型解释。

一个可以检验的候选链条是：某种选择规则让高修复价值的情形长期缺乏证据；固定更新器因而选择不适当修复；模型／交接变化又强化这种遗漏，最终降低相同外部任务流下的有效改进。此链条是待证假设，既不由报警率下降证明，也不由选择偏差理论自动证明。

同时，反馈不必然有害。A 可能主动减少冗余，B 可能让系统远离高风险状态，θ 更新可能使旧故障真正消失。真正的坏现象应表现为预定义任务收益、能力保持或改进效率受损，而非“系统分布发生了变化”。

**六、三条方法路线暂按前提与证据成本比较，不按复杂度排序。**

| 路线 | 值得继续的具体前提 | 最近邻与强简单对照 | 暂停或转向的条件 |
|---|---|---|---|
| I：证据—修复协同 | 有证据缺失、修复歧义，且证据选择改变有效修复 | 随机／分层审计、普通 VOI、记忆学习、通用联合优化 | 全量／低成本保留或简单审计已满足需求，专用学习无净收益 |
| II：模型升级后的职责再适应 | 新 VLA 使原交接／接管失准，造成可测代价 | 原 B、简单重新校准、Robo-COP 式记忆修订 | 原 B 仍有效，或少量阈值／调用规则调整足够 |
| III：机制感知持续权重修复 | 有可干预内部目标，普通修复后仍有残余 | 代码／观测修复、微调、激活干预、随机编辑 | 局部干预不稳定、闭环无收益或旧能力损失不可接受 |

路线 I 与统一架构关联较强，可列为优先诊断候选；目前证据不足以把它裁定为主算法。路线 II 也可能提供更清楚的因果入口。路线 III 的技术深度不自动意味着问题价值或新颖性更高。

诊断路线 I 不要求先找出无争议的现场自然事故。受控仿真可检验机制是否可能存在，已有日志可帮助判断它是否常见、代价是否足够大。通过人为削弱报警器制造反例，只能证明所设条件下可能失效；不能证明真实系统迫切需要复杂协同算法。

**七、变量定义：保留 V4 的层次关系，通过实验区分效果。**

| 对象 | V4 对应的研究含义 | 可用于区分的干预 |
|---|---|---|
| θ | VLA 动作能力／模型状态 | 固定运行配置，替换模型 |
| φ | Runtime 的执行能力与逻辑实现 | 固定调用关系，替换某项工具／恢复实现 |
| ρA | 信息获取、保留、传递和压缩关系 | 固定下游使用者，替换证据选择 |
| ρB | 已有执行能力之间的调用、交接和接管 | 固定 Worker／技能集合，替换分配策略 |
| ρC | 改进操作的选择、顺序和预算关系 | 固定可用修复集合，替换更新决策 |
| ψ | 更广义的研究与优化策略 | 共同起点、证据与预算下，比较快照的后续改进能力 |

ρC 可以是 ψ 的子配置；φ 的执行能力与 ρB 的交接关系也可由同一策略引擎实现。工程上保持字段和写入来源可追溯，实验中只干预明确对象；不需要为了概念整齐额外建立六个网络或六个 Agent。

当采用更强的二层解释时，可以另定义 Uψ 为修订 ρ 的规则，并将 Uψ 自身的变化单独研究。但这是候选形式化，不覆盖 V4 对 ψ 的原定义。

对 H3 的判断有三条边界：

1. ψ 的有效表示可以是参数、可解释规则、提示或程序；不要求它必须改写自身源码。
2. 外层优化器固定、ψ 参数学会了更好的研究决策，也可能满足 V4 的元策略持久进化要求；仍须通过新问题上的改进能力比较。
3. 若只改变了按定义属于 ρC 的状态，而 ψ 完全固定，不能另称 ψ 已变化；若两者按定义共享参数，也不能把同一效果当作两个互相独立的贡献。

协作参数变化是 H1/H2 的对象；利用这些变化解决未见改进问题的能力提升是 H3 的证据要求。不是观察到表格、参数或程序变了就宣称三者全部成立。

**八、方法候选：修复价值是目标定义，难点在可识别的估计与闭环利用。**

独立审查提出的 Evidence–Repair Co-Adaptation 可保留为讨论用名称，不作为已确立算法。其取证价值可写成：

```text
Vrepair(q | h)
  = E[e | h,q] { max_u Ĝ(u | h,e) }
    − max_u Ĝ(u | h)
    − λ c(q)
```

h 是当前合法历史，q 是额外取证，e 是新证据，u 是修复操作。这个表达式是决策论信息价值的具体化，不是新的学习规则。

若它用来估计真实决策价值，至少需要明确：Ĝ 对应何种固定评价任务和净收益，候选修复集合是否相同，证据如何更新预测，以及取证后是否还来得及改变决定。纯信息、可忽略、无成本的理想设定下，真实最优信息价值非负；实际机器人复测可能改变状态、消耗时间或引入风险，必须在结果与约束中计入。

不能直接最大化一个未校准的 Ĝ 然后把最大值当成收益。选择操作 max_u 可能放大预测噪声；若过往只试过少数取证／修复组合，对未试组合的高预测值尤其不可靠。更多证据引起“模型更自信”，也不等于独立验证更好。

| 方法环节 | 可先比较的直接实现 | 专门研究可能需要解决的残余 | 必须声明的条件 |
|---|---|---|---|
| A：选择额外证据 | 固定／分层采样、异常触发、普通 VOI | 哪些证据能纠正有害修复选择 | 合法输入、成本、保留／标注概率 |
| C：估计修复价值 | 经验收益表、回归、简单 Bandit | 选择性反馈与跨版本变化下的可靠估计 | 覆盖、可比状态、反馈来源与外推范围 |
| 不确定时暂缓 | 固定阈值、校准区间和回退规则 | 有限预算下避免错误更新与长期停滞 | 区间依据、被选择后的覆盖、暂缓代价 |
| 升级后再适应 | 固定审计加简单校准 | 哪些 A/B 变化必须依赖新的反馈 | 触发条件、漂移度量与旧版本适用性 |

已知随机化概率时，可研究加权估计；具有适用结果模型时，可比较双重稳健估计；跨版本时，可比较简单重置、滑动窗口或版本条件化。它们都是现成工具候选，不能预设总能校正偏差。只知道样本被保存的概率，还不能识别未实施修复的收益；修复操作本身也需要适用的覆盖、可比假设或受控验证。未观测区域概率为零、缺失依赖未记录变量，或策略把状态分布改变到不重叠区域时，仅靠权重不足以识别反事实修复收益。

若存在可验证的窄问题，理论工作可针对有限修复集合、给定覆盖和受限分布变化，研究取证误差如何传到修复决策遗憾或错误发布概率。不能将借贷 RRM 的强凸／敏感性条件直接套到神经 VLA；也不必为整套系统先证明全局收敛。

真正值得形成方法身份的，是针对已确认困难的一条专门更新／估计规则和不同预测。例如：在相同审计预算与证据覆盖下，纠正某种跨版本反馈失真后，减少错误修复且提高后续收益。若“随机审计＋校准阈值＋简单优化”已经达到相同效果，应使用该组合，而非增加包装。

方法提案可以先围绕以下预测收敛，而不是先确定名称或网络结构：

| 待验证预测 | 对应的区别性比较 | 会削弱候选解释的结果 |
|---|---|---|
| 证据的价值集中在修复选择有歧义的情形，而非异常分最高的情形 | 固定修复集合与取证预算，对比异常排序和决策价值排序 | 各类情形有同一最佳修复，额外证据不改变有效选择 |
| 同时存在选择性反馈与跨版本变化时，估计失真比其中单项更难处理 | 分别控制缺失和版本变化，比较简单校正与拟议规则 | 收益只来自更多审计，或与指定失真是否存在无关 |
| 旧数据的适用性需要版本相关判断，而非一律丢弃或一律复用 | 相同历史数据下，对比全保留、窗口／重置与候选规则 | 简单窗口或重置以相同成本达到同样保持与修复收益 |
| 提高有效改进的证据反馈应改善下一轮取证，而不只是本轮决策 | 固定证据反馈接口，比较独立优化与受控联合更新 | 反馈切断后结果不变，或收益仅来自优化次数增加 |

这些预测也有现成方法可能满足。未来算法应明确哪条估计／更新规则产生了超过它们的结果；若尚不能写出该规则，应如实停留在问题与方法候选阶段。本版没有通过命名一套常用组件来代替算法发明。

**九、第一组诊断：先证明证据选择影响了什么，再研究跨轮错误反馈。**

将独立审查的实验一分成两个层次，可以减少混杂和启动成本。

**固定执行轨迹的证据诊断。**在同一模型、B、任务和轨迹上，离线施加不同保留规则，检查它们遗漏哪些结果／诊断证据。随后让同一个修复决策器读取这些子集，比较其候选选择与受控修复效果。它回答证据选择是否改变决策，不证明完整长期闭环。

**允许系统变化的闭环诊断。**从共同初始模型与运行配置出发，各证据策略使用相同的更新规则、修复集合和总预算，持续执行同一个外部任务序列。后续 θ 与遇到的状态可以不同，因为它们正是待测中介；“同更新器”指同一更新规则，不是要求每轮模型参数都相同。

| 证据条件 | 用途 | 公平性要求 |
|---|---|---|
| 全量详细记录 | 机会／信息上界参考 | 若超出资源限制，标为 oracle 参考，不算同预算获胜基线 |
| 固定随机或分层保留 | 检查简单覆盖是否足够 | 与可部署方法匹配详细证据预算 |
| 异常触发保留 | 检验事件依赖采样的后果 | 使用合理调优的检测器，避免故意做弱 |
| 带独立基础审计的自适应保留 | 检验有成本的自适应价值 | 基础审计不能被学习器削弱，单列其成本 |

完整诊断记录可由仿真评价侧持有，用于检查遗漏；必须禁止被评估策略读取。评价侧成本与算法侧可用资源分别记录，所有组采用一致口径。不能一边宣称同存储预算，一边让某个可部署组免费使用全量视频。

| 指标 | 有效分母／解释 |
|---|---|
| 真实任务失败率 | 全部被指派任务的独立结果；技术无效与未知另列 |
| 被保留样本中的失败比例 | 只描述选择后样本，不直接估总体失败率 |
| 失败检测／证据覆盖率 | 评价侧确认的实际失败中，有多少被检测／保留 |
| 各类问题的覆盖率 | 需有独立类别标注或承认未识别类别；不能仅用学习器自己的分类 |
| 有效修复与错误修复 | 由独立回归与目标任务收益判定 |
| 净改进成本 | 包含取证、未采用候选、训练、验收与人工 |

报警减少而实际失败不降，只是线索。通过替换保留策略、保持检测器或修复规则不变，才可逐步缩小原因。若固定随机审计已消除重要代价，应结束“必须专门协同学习”的论证，或转向另一个仍有残余的问题。

**十、第二组辨别：分别测量组合效应、反馈作用和专用规则价值。**

| 条件 | A | C | 能回答什么 |
|---|---|---|---|
| 固定基线 | 固定 | 固定 | 基础起点与固定协作能力 |
| A-only | 学习 | 固定 | 取证学习是否有独立价值 |
| C-only | 固定 | 学习 | 更新决策学习是否有独立价值 |
| A+C 分别优化 | 学习 | 学习 | 两类更新并存但不利用指定跨模块学习反馈的效果 |
| 通用联合优化 | 学习 | 学习 | 普通优化器是否已足够利用同一可修改空间 |
| 专用协同候选 | 学习 | 学习 | 针对选择性反馈／跨版本失真的规则是否有额外价值 |

这是一组候选比较角色，不是要求首次探索同时运行六臂。现象筛查可先比关键的两三种直接解法；存在残余后，才扩展到能够支撑具体主张的条件。

“分别优化”不能简单写成两个优化器。应声明切断的反馈通道。例如，A 使用固定参考修复器来评价证据，C 使用冻结的参考证据生成机制训练；测试时再组合。该设计与端到端优化目标不同，必须明示。也可用有限的历史交叉／顺序比较研究依赖，避免把信息量和算法同时改变。

GEPA 适合文本／配置组件，EvoX 适合搜索策略。它们不是无条件必跑的标签；适用时应提供相同可修改字段、输入、修复权限、预算和独立结果接口。更强硬件、更大模型或额外真实标签均需单列，不能混入方法收益。

V4 的 I_AC=J(A+C)−J(A)−J(C)+J(0) 可保留为预定尺度上的交互统计量；它不等于“联合反馈组减分别优化组”。正交互也可能来自两个固定能力互补，或来自双份预算。对应 H2 的核心证据，是利用所定义反馈的规则在可比条件下更有效，并经受限通道干预支持。

common-data 与 interactive 必须分开解释：前者给定共同证据，可检验 C 的决策、A 的证据加工或反思能力；它不能完整评价 A 主动改变未来观测的价值。后者允许主动取证与状态分布变化，评价总效应，但仍需固定外部任务流，防止只选择容易任务获得高成功率。

**十一、第三组辨别：新版 VLA 是否真的使 A/B 需要再学习。**

先确认新 θ 在预定任务上获得真实收益，而非只在训练场景改善。然后固定新 θ 和可调用技能，对比旧 A/B、简单校准 A/B 与可学习 A/B；分别记录误接管、漏接管、完整任务收益、证据覆盖和代价。

早期不必同时学习 A 与 B。可先只替换 B，保持 A 为固定基础审计；再检查 B 改变后证据分布是否有重要变化。否则一个成功率差异很难定位到交接还是取证。

若旧 B 保持有效，结论就是该类更新下无需改 B。若简单校准足够，采用简单校准。只有存在稳定残余，才能继续研究与能力边界变化相关的学习规则。安全允许的接管阈值与底层硬限制应分开，研究者不能通过放松保护制造任务收益。

涉及“若没有接管会失败吗”的问题，需要仿真分支或额外假设；现场接管后的成功只能证明组合系统成功，不能直接给裸 VLA 贴失败标签。

**十二、H3：保留完整目标，使用独立的改进能力考试。**

H1/H2 证明协作学习有效，H3 证明改进策略本身更有效，两者不同。有限的几个修复任务可能不足以训练或检验 H3。应把问题种类、开发历史和考试难度列为实际缺口，不能只增加演化轮次。

建议将 ψ 的产生阶段与考试阶段分开。快照在开发问题上形成和选择；考试在未见改进问题上，重置当前系统、可用证据与预算，冻结该快照的定义对象，比较它产生有效改进的能力。

| 对照 | 排除的解释 |
|---|---|
| 早期／后期 ψ，共同起点与证据 | 更强初始 VLA 或不同信息输入 |
| 相同晚期记忆，固定 ψ | 只是记忆增长 |
| 同预算重启／搜索 | 只是更多尝试与挑选 |
| 适用的现成优化器 | 一般搜索或配置优化已经足够 |
| 独立演化历史 | 单条幸运历史 |

记忆与策略存在兼容性时，可用有限交叉进一步区分。快照选择只能使用开发证据，不能从最终考试中挑最好的晚期版本。只换 seed 主要测试新初态，不自动证明新问题的研究能力。

快照考试中的 ψ 可以继续修改被研究的系统，并按事先协议使用工作记忆；被冻结的是被考试的研究策略表示。如果要测在线改变 ψ 的能力，应另列 interactive 协议，不能混为一个结果。

结果至少分开报告：共同预算内的最终净收益、达到预定改进所需成本、错误修复／旧能力损失、未完成与拒绝发布。总成本包含失败候选；从来不更新的策略不能因“发布成功率高”而被误判为最会改进。

**十三、H4：保留模型机制深度，不让它替代协作问题。**

局部权重编辑可形成独立贡献，但需要：特定失效、可干预目标、干预有效性、权重写入后闭环收益、正常与旧任务保持，以及有限多轮兼容。改动参数少或表示拟合误差低都不足以替代这些证据。

V4 候选拟合目标中的 ΔY* 必须来自可靠干预或明确教师；干净观测输出不能自动当作所有扰动下的正确动作。还要固定或记录策略噪声、生成步数和执行时序，避免将速度／chunk 协议变化归因于内部编辑。

作者 Weight Editing 页面提供了简单代码修复对照，并说明任务及重复范围有限；这支持条件探索，不支持局部编辑普遍优于代码修复。优先比较观测／代码修复、正规微调和内部干预，前提不成立即停止相应编辑分支。[作者原文](https://github.com/Cuzyoung/robotics-weight-editing/blob/main/site/zh/index.html)

**十四、证据与统计：按探索阶段选择深度，不把最终要求一次性前置。**

| 阶段 | 此时最必要的证据 | 此时不必自动展开 |
|---|---|---|
| 现象筛查 | 合理起点、清楚分母、一次可解释干预、主要成本 | 全部 A/B/C 学习与完整 H3 考试 |
| 机制探索 | 与直接解法比较，固定关键变量，负结果 | 所有跨平台、跨模型组合 |
| 方法辨别 | 适用强基线、反馈消融、独立重复与保持 | 与主张无关的穷举 |
| 正式结论 | 按实际效应与相关性定规模，封存测试与完整费用 | 把初筛算例当统一样本量 |

探索阶段也需保留失败、定义成功与未知、避免评价泄漏；这些是结果能否解释的基础。扩大规模则由观察到的效应、方差、任务异质性和拟作结论决定。上一版“约 400 独立样本”的例子不构成本项目的最低样本量，本版不将其用作启动条件。

正式研究的重复单位应是独立演化历史、任务流或场景，而非轨迹帧。任务宏平均与部署频率加权二选一或分别报告；只对成功轨迹报耗时会有幸存者偏差。安全拒绝、未知结果、技术失败和任务失败要区分，且预先说明主分母处理。

结果至少同时包含任务能力、有效任务吞吐、逐旧任务保持、人工介入和研究总成本。物理安全红线不与任务收益线性抵偿。小规模现场零事故只能支持所测条件下的观察，不等于证明低概率风险被排除。

发布回归集可以反复使用，但它会参与适配。最终测试要在版本冻结后使用，和开发／发布反馈分开。若每轮用显著性判断发布，应处理反复检验；工程阈值不应写成统计保证。SEAR 的经验库和匹配重启对照可参考，其隔离和预算本身也有局限。[SEAR §2.4 与局限](https://arxiv.org/html/2610.18792v1)

选择性反馈理论中，有限样本、覆盖与分布假设仍是问题；本报告不将某种加权、置信区间或保守下界自动称为可信保证。判断哪类校正有效，必须先辨别第五部分中的具体缺失机制。

**十五、系统设计：以 RPent 为运行骨架，研究方法保持独立。**

| 项目／模块 | 建议职责 | 重要边界 |
|---|---|---|
| RPent | 前台 Planner、Toolkit、会话、VLA／环境服务 | 主运行骨架候选，不是完整 Meta-RSI |
| 自研研究控制层 | A/B/C、ψ、证据策略、候选及实验组织 | 这里实现所选机制，当前算法未裁定 |
| ENPIRE | 后台实验协议与记录参考 | 只复用适用部分，机器人侧公开范围有缺口 |
| GEPA | 配置／文本优化及强基线 | 与本方法使用可比输入和权限 |
| SkyDiscover/EvoX | 元搜索参考和适用基线 | 不因接入它就获得新的 H3 方法 |
| openpi／RLinf／LeRobot | 选定模型的原生训练与推理 | 一个明确模型入口，服务化衔接，避免重复维护同一训练链 |
| lerobotv6 | Piper 设备、采集、安全执行与部署 | 保留项目既有执行边界，尚需本项目验收 |
| OpenETA | 证据与经验审查参考、备选骨架 | 不要求与 RPent 同时成为两套主 Runtime |
| ReinFlow／DOMINO | 适用离线工具、策略基线与仿真资产 | 按实际依赖复用，旧 R4 数值规格不强加给新接口 |

RPent 已有轨迹与动作来源记录、导出 LeRobot 数据并交给 RLinf 训练的路径，但独立 Gate、A/B/C 学习与 ψ 考试仍需设计。[Flywheel](../RPent/docs/source-en/rst_source/guides/flywheel.rst)

OpenETA 的 rollout 与工作记忆分离设计有用，但其记录为 best-effort；采用时要明确 L0 缺失如何标记及哪些结果不能进入发布证据。[记录合约](../OpenETA/docs/rollout-data-contract.md)

ENPIRE 对 reset、verifier、安全与评价规则设置研究边界，部分真机桥接需使用者提供。[研究协议](../ENPIRE/enpire/policy/autoresearch_instruction.md)、[公开范围](../ENPIRE/enpire/env/docs/REAL_WORLD_WORKFLOWS.md)

GEPA 有组件更新及轨迹接口，EvoX 有演化搜索程序的实现；它们的已有能力应成为参考与对照，不应被重新命名为研究原创。[GEPA](../gepa/src/gepa/core/adapter.py)、[EvoX](../skydiscover/skydiscover/optimize/search/evox/controller.py)

运行时发布应处理模型、归一化、相机映射、动作语义、内部历史与未完成动作队列的兼容，不能只替换 checkpoint。环境和训练进程通过接口隔离；LIBERO 的末端命令与 Piper 的关节目标不能因同为 7 维就直连。RLinf 的 Piper 说明当前仅覆盖硬件检查。[Piper 专门说明](../RLinf/docs/source-en/rst_source/examples/embodied/piper.rst)

研究者对安全和最终判据的只读约束应由实际运行边界支持。初期可以限制为少数配置、规则或 Adapter 的候选修改；不需要为了“自进化”立即开放全代码库写入。现场操作仍由独立授权与设备执行服务控制。

**十六、资源与推进：最小研究闭环服务于问题发现，之后再扩大。**

若沿用此前记录的两张共享 RTX 4090D、单臂 Piper、每周约 12–16 小时现场条件，则小规模工具链与有限 VLA 改进有实施路径，但不宜把大型全量训练或多模型并发当作前提。这是继承的规划条件，不是本轮实时资源读数。

openpi 官方估计推理超过 8 GB、LoRA 超过 22.5 GB、全量微调超过 70 GB；所选 checkpoint、输入尺寸、优化器与感知服务会改变实际占用，两卡显存不会自动合并。[官方要求](https://github.com/Physical-Intelligence/openpi#requirements)

真实约束往往是一轮取证—修复—验收的总时长，而不只是单次训练。应计入无效交互、候选生成、模型调用、失败训练、回归、机器人复位和操作员时间。与旧能力保持有关的现场成本也不能省略。

存储量级同样重要：两路 640×480 RGB 20 Hz 未压缩画面约 132.7 GB/小时；若各按 4 Mbit/s 编码，则约 3.6 GB/小时，后者是码率假设。此前本会话检查磁盘约余 131 GB，不能视为长期资源保证。因此自适应证据有工程动机，但工程节省是否需要新算法仍应比较。

| 里程碑 | 可交付结果 | 扩展依据 |
|---|---|---|
| 问题辨别与最小闭环并行 | 合理 VLA 起点、可靠结果记录、一项证据／交接干预 | 现象不是明显接口错误或人为弱基线 |
| 强直接解法比较 | 固定审计／校准／简单优化的效果与成本 | 存在重要且可重复的剩余代价 |
| 专门机制提案 | 状态、动作、估计、学习规则与不同预测 | 规则针对残余，能被现成方法反驳 |
| 有限方法辨别 | 关键消融与 common-data／interactive 适用结果 | 净收益与机制解释均得到支持 |
| 完整协作及元改进扩展 | B、θ、ψ 的继承与快照考试，Piper 关键闭环 | 问题多样性、资源和前置证据支持 |
| 成文与迁移验证 | 依 V4 要求补必要模型类型、保持与外部条件 | 与拟作结论直接相关 |

六个月可用于优先完成前几项并争取方法证据，不要求按月份机械推进，也不预先删去完整 A/B/C 和 H3。P0 的可复现能力与机制探索可以并行；完整 Dashboard、多平台迁移和所有候选优化器不应先于问题残余成为依赖。

**十七、论文与评审：用科学问题组织叙述，用完整架构检验适用性。**

若路线 I 的前提成立，可采用以下论证结构：机器人中的具体证据失真及代价 → 合法观测与修复决策建模 → 专门学习规则 → 对直接解法的差异预测 → 机制与同预算结果 → 跨轮、B 再适应和真机关键验证。主线不应以四个子系统逐个介绍来代替问题论证。

若前提不成立，路线 II 或 III 可按其剩余问题重新构造，而非给路线 I 增加模型复杂度。无论选择哪条路线，H1/H2、完整 A/B/C、H3 和 H4 的证据分别报告。

| 评审视角 | 核心追问 | 有效回答所需证据 |
|---|---|---|
| 机器人学习 | 指定失效是否常见／代价大，动作能力实际改变了吗 | 合理起点、本域完整任务、修复及保持 |
| Agent／元学习 | 不是普通 VOI、GEPA 或搜索策略学习吗 | 可区分规则、适用强基线与快照考试 |
| 因果／统计 | 是证据影响修复，还是更多信息、不同状态或预算 | 具体缺失机制、受控干预及独立重复 |
| 系统／安全 | 更新与验收边界是否实际有效 | 运行记录、兼容发布、回滚和执行限制 |
| 使用者／负责人 | 自动化是否节省总体维护成本 | 有效吞吐、人工人时、停机和失败候选费用 |

若提出新的学习机制并超越强对照，可形成方法贡献；若揭示稳定的新失效规律并给出可信评价，也可能形成实证贡献；可靠、可复用且解决真实问题的平台可形成系统贡献。系统论文不天然低于方法论文，但单纯集成已有功能也不自动构成高质量系统研究。

“应该发明什么”目前不能由审查文字直接决定。可把证据—修复方向细化到方法提案，但在确认前提、估计可识别性和现成方法后残余前，不宜宣布新算法或预期发表层级。
