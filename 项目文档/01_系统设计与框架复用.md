现行设计更新：2026-11-17；实现映射含 F00—F14 与本批仿真范围集成，历史基线 V5.1。目标与术语见 [00](00_项目总纲与研究边界.md)，验收见 [03](03_实验设计与验收协议.md)。本文区分当前代码入口与完整系统目标；运行完成度见 [04 §1.23](04_实施路线与执行状态.md#123-第四批仿真验收与准备2026-11-17)，初始源码判断及版本范围见 [05 §4](05_决策映射与审查复核.md#4-关键源码判断的复核)。

## 1. 最小职责拓扑

采用 **RPent 执行底座 + core 研究与治理 + Autoloop 事件驱动 + Host 作业监督**。RPent 是当前主 Runtime，出现具体瓶颈再评估替代；架构选择不定义项目能力上限。详细取舍见[框架设计](../项目辅助文档/02_框架设计与实施方案/02_项目框架设计方案_复核与定稿_2026-11-17.md)，施工细节见[实施方案](../项目辅助文档/02_框架设计与实施方案/03_项目框架详细实施方案_框架优先_2026-11-17.md)。

| 职责平面 | 组成与产物 | 权限边界 |
| --- | --- | --- |
| 控制 | Coordinator 保存意图、pending 与操作接续；Host/Broker 准入、监督、计量；Autoloop 唤醒 | 按外部总授权推进，不改研究、评价或发布域的业务事实 |
| 智能决策 | Runtime Planner 选择目标、监督和恢复；Research/ψ 选择问题、实验及候选 | 两类上下文与工具/数据权限独立，LLM 不授予自己硬额度或发布权 |
| 执行与学习 | Toolkit/Skill、VLA、环境/设备服务及匹配原生 trainer | 只有机器人执行链发送动作；core 不打开设备，不重写原训练循环 |
| 独立评价与发布 | Evaluator、固定协议 Gate、Release 生成结果、资格与 active | 受保护协议独立评分，Research 不能读隐藏结果或写正式发布域 |

原始事件、派生证据、成本账和版本引用是共同基础。四个平面是逻辑职责，可由少量本地模块与受控进程实现，不要求四套服务或数据库。前台与研究者可复用同类 Planner 适配器；当前 Research 实际入口为有界 text-only 单请求，不能据逻辑图声称常驻自由工具 Agent 已运行。

状态按对象确定权威：Coordinator 拥有工作流，Host 拥有准入与作业监督回执，Research Store 拥有机会/实验/候选，Evaluation 域拥有独立结果和 Gate 依据，Release 域拥有有效版与激活历史。原始执行事实来自执行侧，费用由原 owner 测量后汇总；派生索引不取得第二份裁决权。

执行服务和设备控制器按实际周期承担动作校验与停止。Toolkit 的进程内调度、工具后观察和仿真预算不等于真机硬实时安全；现场保护、急停与失联行为需独立验收。

### 3.1 midterm16 的监督、数据与原生训练接口

[`midterm_host.py`](../core/src/rsi_vla/midterm_host.py)将新任务的固定业务操作接到既有Autoloop事件、定时器和角色消费者。宿主消费同一scope、UTC期限、阶段账与全局账，按当前operation物化permit；独立supervisor持有完整命令和进程清理，回执驱动后继。宿主重启先核对原operation、进程出生身份和费用。业务结果与完整监督回执分别归档；宿主控制开销应纳入全局账，计量版本和未知费用按实际证据记录。本批运行边界与人工介入统一在[04 §1.23](04_实施路线与执行状态.md#123-第四批仿真验收与准备2026-11-17)维护；历史动态批次仍见 §1.17。

四臂共同执行契约由[`execution_arms.py`](../RPent/robots/libero/execution_arms.py)和Toolkit消费：每次VLA预测执行五步并记录一次，A的长逻辑段也按这一节奏采集，每次预测占用工具额度；动作入口统一为`vla_execute`。S/R按task映射选择已登记程序，R只使用公开EEF/夹爪信号；D保留原生任务指令。冻结B0时保存实际程序、提示、检索和职责引用，θ及processor资产另行绑定。

[`libero_public_data.py`](../core/src/rsi_vla/adapters/libero_public_data.py)固定公共示范revision、episode与来源，[`libero_teacher.py`](../core/src/rsi_vla/adapters/libero_teacher.py)使用显式授权的教师几何和原生动作服务采集；教师来源在创建时登记。新数据准入引用原始manifest、全帧质量/隔离审核和原生batch。有限学习入口继续复用[`pi05_training.py`](../core/src/rsi_vla/adapters/pi05_training.py)及安装的RLinf SFT：只更新action expert，冻结VLM，核对scope、P1、独立数据准入、配方及实际资源reservation。资源pilot与学习候选分开登记，原生更新、完整保存、实际加载与任务收益分层验收。已安装SFT路径会主动关闭activation checkpointing，不能由配置开关推定实际启用；资源包络由真实pilot确定。

能力声明按实际实现提供：内部特征、固定噪声、控制步干预、任意中间状态 snapshot/restore 都不能由统一接口名称推定已经支持。

实际调用的技能在现有技能配置中声明输入与返回语义、完成依据、已验证起态与场景、交接限制，以及模型/工具版本和验证记录引用。技能记录由接入配置与实验记录提供，供 Planner、ρB 和诊断过程使用；与 BackendSpec、RunBundle 共享权威引用，不另建技能数据库。成功样例只证明所测条件下的表现，未验证条件明确标注，不能外推为完整适用域或模型不变性。

模型、处理器、工具或控制协议改变后，保留旧验证记录及其版本归属，按实际依赖确认受影响调用建议对新版本的适用性。未确认不等于已失效；检查范围由具体变化和现有证据决定。

## 5. 动作级证据和 L0/L1/L2

### 5.1 记录分层

| 层级 | 内容 | 可变范围 |
|---|---|---|
| L0 基础事实 | 任务/阶段/时间/版本、动作源、建议与发送映射、反馈、监督和结果来源、缺失 | 由执行侧记录；ρA 无权选择性隐藏 |

| L2 专项证据 | 完整对照轨迹、精细标签、内部表示、干预试验 | 按研究需要和实验权限启用 |

L0 的“全覆盖”是采集目标，故障时必须显式记录间隙与未知。模型建议、经过滤后发送、控制器实际应用量、测得运动是不同事实；拿不到应用量就标未知。结果至少区分 success / failure / unknown，并独立记录技术无效、拒绝执行、人工接管和未完成。

关键关联字段包括 run、episode、事件序号、active_bundle、父研究决定、捕获/接收/推理/发送/反馈时间及其时钟域、proposal 索引和实际执行掩码。记录媒体保留概率、结果标注概率和修复动作选择概率；三者分别定义，未知概率不补成 1。

受保护基础审计、自适应取证和专项实验共享总预算，但研究者不能削弱基础审计。底层安全监测不由可学习取证策略控制。

### 5.3 任务状态与完成证据

任务状态是依据合法执行证据更新的派生记录。原始工具返回保留其语义；分别记录工具调用的结束状态、子目标完成结果和整任务结果，不能把同名 `success` 字段直接作为统一完成标签。当前 RPent 的 `pi0_pick` 采用运动与夹爪阈值，`pi0_doubled` 的 `success/task_success` 对应整任务终止；静态依据见 05 §7。

对实际影响后续动作的状态，保留对象/子目标、状态值、来源事件、判定依据、适用回合及有效性。工具结束只确认调用已结束；符合该子目标预定完成判据的合法证据成立后，才更新对应阶段、关系或计数。同一完成事件只提交一次。证据缺失或冲突尚未消解时，相关状态保持 unknown。仅供评价方使用的特权状态不能用于运行状态更新，除非实验明确允许并对比较组采用相同信息条件。

历史事实与当前关系分别维护：曾完成抓取不代表当前仍持物；新证据否定当前关系时更新其有效性，保留原事件。历史可提供对象身份、顺序和次数，当前动作坐标仍由当前合法观察确定。未知状态按既有权限、预算和安全规则选择补充观察、合法恢复，或停止依赖该事实的后续动作；不得用无新增证据的重复调用或 LLM 叙述代替缺失证据。

初期仅比较研究取证的 ρA 实验，执行所需即时观测、任务状态更新规则及其证据访问条件保持一致。任务状态更新沿现有事件与工作记忆实现；规则的运行检查和效果评价见 03 §3.5，来源见[旧资产复用 §2.1](../项目辅助文档/04_旧资产复用/复用分析.md#reuse-2-1)。

## 6. ρA/B/C 与 ψ 的实现边界

| 策略 | 输入 → 输出 | 最简起步 | 能力验收 |
|---|---|---|---|
| ρA | 合法事件/缓存 → 保留、压缩和路由 | 固定/分层审计、少量优先级 | 能从反馈产生候选并跨轮继承 |
| ρB | 任务阶段、Worker 与监督状态 → 调用/交接/恢复 | 现有路由、阈值校准 | 在固定能力集合下可单独干预 |
| ρC | 证据、修复集合、预算 → 实验/更新/暂缓 | 固定顺序、简单收益表 | 更新选择和资源分配有真实反馈 |
| ψ | 研究历史与可信结果 → 研究决策或规则修订 | 可保存、冻结的研究协议 | 支持共同起点的新问题考试 |

首版复用有界规则、经验均值和 contextual ρC，先完成一种具体反馈更新与继承路径；实际媒体保留出口属于 F06，ψ 规则修订属于 F08。代理目标如引用覆盖或筛选通过率分别记录，不能重命名为机器人收益。

学习算法可先用参数搜索、规则优化或适用通用优化器。目录和可编辑字段不是学习算法，实际规则必须说明状态、动作、目标、更新与反馈。φ 的恢复程序与 ρB 的选择策略分开引用，Planner 提出意图、ρB 选择授权 Worker、执行服务发送动作，保持唯一发送入口。

技能交接失败时，将顺序/切换错误、起态或场景变化、后继技能能力不足作为可并存的竞争解释。先核对后继技能在已验证起态上的证据，再检查前驱留下的状态与之有何差异；只使用现有合法观察，不能隔离变量时保留未决。诊断应对应保持技能、修正调用语义或切换、补充实际起态数据等可执行决定，不凭失败标签认定原因。局部恢复、交回续程与 reset 重试按 03 §3.5 分别记录和评价。来源见[旧资产复用 §2.2—2.3](../项目辅助文档/04_旧资产复用/复用分析.md#reuse-2-2)。

ψ 可表示为参数、规则、提示或程序。更新 ψ 不必改写源码；参数变化也不自动证明 H3。ρC 与 ψ 共享实现时，实验保存具体冻结范围。

当前ρA保留事件覆盖与引用数量的经验目标，引用消费、SDK payload、持久媒体存储和诊断质量分开记录已知值与unknown。新ρC由 [relation_learning.contextual_research_policy](../core/src/rsi_vla/relation_learning.py) 显式初始化，按任务、算子、证据、执行版本和数据条件划分上下文；`ResearchTools.research_relation_admission` 保存选择及探索预留，`record_contextual_research_feedback` 保存技术有效、筛选、任务收益、旧能力和成本。未取得的反馈保持unknown，技术无效不计成任务筛选奖励，探索额度在冻结继承中保留；技术、数据、预算和权限准入先于探索。旧筛选快照及反馈按原语义读取，[合法历史回放](../artifacts/framework15-20261115/state/research/relation_replays/framework15-historical-v1.json)与离线反例分别提供其证据。

有效ψ由 [effective_psi.py](../core/src/rsi_vla/effective_psi.py) 的 `freeze_effective_psi/consume_effective_psi` 绑定实际程序、提示、ρC、检索和依赖，并记录修改来源、开发成本及预留任务族/机制。事实保存在独立 `fact_memory_snapshots`，研究请求通过 `domain_policy.effective_psi_ref` 消费快照。初始策略与合法事实起点见[物化回执](../artifacts/framework15-20261115/state/research/policy_materialization/framework15-initial-complete.json)；仅增加事实而未改变策略不生成后期ψ，预留划分也不抹去外部先验或历史暴露。

## 7. 机会发现与自主研究

研究入口覆盖失败、成功但低效/高接管、能力边界与领域内新需求。每项机会保留“外部价值、已有证据、竞争解释、预期代价、可区分试验”；进入队列不等于获得实验额度。

初期用规则和简单优先级完成最小服务，具体机会选择学习算法保持开放。Meta-RSI 在已授权预算内可以选择补证、实验、代码/技能修复、训练 VLA、修订关系或暂缓。新能力目标先按预定规则检查领域相关性、权限与可检验性，在预算内自主学习，随后由独立任务验证真实价值；该流程不要求人逐项挑选领域内目标。学习目标可由系统选择，论文外部考试任务流保持独立。

目标研究接口可复用 Planner 适配器与独立 Toolkit，工具范围为合法证据查询、版本比较、实验、训练配方及候选；当前真实 SDK 仍为下述无工具短请求。研究 Toolkit 应返回作业状态和记录，不通过标注全部 `readonly` 跳过状态管理。RPent 的该标记服务于工具调度，不是安全 ACL。

[research_transport.py](../core/src/rsi_vla/research_transport.py) 的 `readable_v1` 输入将原始事件、来源、选择、遗漏及unknown呈现为可读 JSON；`bounded_runner.child` 保存业务输入到实际 `thread.turn` 的参数关联。Research当前为text-only，媒体路径和图像字节分开，视觉内容保持unknown。模型可在defer中返回有界 `evidence_requests`，由宿主经 `consume_evidence_requests` 读取合法开发事件，再由 `prepare_evidence_followup` 生成独立身份的新请求；SDK单次调用保持无工具。

[task_continuation.TaskContinuationBackend](../core/src/rsi_vla/task_continuation.py) 按原角色回执的字段选择预登记有限后继，复用 `Coordinator`、`TaskCompletionBackend` 和隔离 `run_role`。补证、Research反馈、试验和暂缓/结束进入同一operation/pending/receipt/reconcile链；资源等待有界重查，提交未知先核对原操作。Autoloop的固定 `core_consumer="task_continuation"` 接到同一CLI。配置、准入与permit由宿主在当前scope内物化，命令及接口见 [core README](../core/README.md#从回执选择后继)。

ENPIRE 的[研究契约](../ENPIRE/enpire/policy/autoresearch_instruction.md)可作记录参考；其 [autoresearch.py](../ENPIRE/enpire/policy/autoresearch.py) 是控制请求客户端。本项目协调建立在现有core与角色消费者之上；新的研究目标和算子按实际接口接入，运行范围统一见04。

### 7.1 有界自主计划与候选产生

Research 返回计划或候选，可信消费者在总授权内校验操作、输入依赖、费用和停止条件，物化既有 operation/有限后继；模型输出不携带任意宿主命令权限。计划修订产生新版本，保持正在执行的 pending 身份；提交未知先核对原回执/进程/效果，不重放动作。当前预登记有限图适合受控批次，有界新提案消费者仍按 F07 补齐。

每次更新只走适用分支，普通运行不必触发 Research，执行修订不必训练 θ，普通候选不必元考试。策略依据输入改变选择、事实积累、可继承策略改变和研究能力改善分别判断。需要视觉判断而实际只有文本证据时补合法输入或保持未决，不能用媒体路径替代模型看图。

### 7.2 主动目标的真实物化

首版使用支持场景/对象/谓词的有界组合，至少能消费未在当前清单中列出的合法目标。固定外部规则先筛领域价值、权限与可检验性，再由可信物化器绑定任务定义、指令、初态、原生成功判据和学习/评价指派。现有 `goal_value.py` 只提供目录目标的符号价值依据，不能替代新目标物化或物理可行性。

F 阶段完成解析与内部接线，P 验证真实环境初始化和判据消费，V 独立比较起点和学习后能力。选择旧题、生成新题、获得新能力和组合迁移分别报告。新目标/评分协议由受信消费者版本化，按相同新协议评价必要参考版；Research 不能改当前考试分母或权重。

## 8. 训练到运行的真实往返

首条链优先沿 RPent 当前 π0.5 服务使用的 RLinf 加载器，选择相匹配的原训练配方。RPent [依赖声明](../RPent/pyproject.toml)指向特定 RLinf release 与 openpi/LIBERO 分支，各个已克隆目录不等于已兼容环境。

[RLinf 示例配置](../RLinf/examples/sft/config/libero_sft_openpi.yaml)使用 `pi0_libero`，不能只改路径便当作 π0.5 配方。需核对模型类型、字段、图像处理、归一化、精度、chunk 和解码。

```text
原始执行/示教 → 合法训练数据与 exporter
→ 原 trainer + 起点模型 + 完整配置
→ checkpoint + processor/归一化 + 实际成本
→ 前台实际加载器 → 解码动作 → 任务评价
```

分别确认 batch 可读、实际梯度更新、完整保存、原生加载/动作、θ 独立收益和系统资格/继承。首版一条配方不限制未来模型学习范围；参数、processor、normalization 和动作合约以真实消费版本为准。

接口往返通过只证明可用性；能力改善需要独立任务结果。训练数据的实际来源、可用规模与目标技能覆盖需要在启动前确认：已有示教、合法执行数据或获授权的新采集分别标明；筛出的成功片段不足时先记录数据缺口，不把失败片段自动当作正确示范。TrainingBackend 只负责启动原训练器、监督预算并返回产物与退出状态，不重写训练循环。

当前 [prepare_cpu_demonstrations](../core/src/rsi_vla/adapters/pi05_training.py) 与 `scripts/prepare_pi05_training.py --cpu-pipeline` 消费固定来源公共示范、原生LeRobot子集和匹配RLinf/OpenPI dataloader。[准备回执](../artifacts/framework15-20261115/training-preparation/readiness.json)确认真实CPU batch通过，数据仍为 `not_admitted_interface_batch_only`、训练步数为0；动作单位、processor/归一化和评价隔离分别附来源。自主轨迹保留 `autonomous_execution/not_admitted`，原生batch不代替正式示范准入。

[theta_b.py](../core/src/rsi_vla/theta_b.py) 冻结B0/B1内容与实际θ/processor，经 `prepare_runtime` 生成评价单元，明确θ不存在、适用性unknown及fallback的实际B身份。[接口回执](../artifacts/framework15-20261115/training-preparation/theta-b-interface-check.json)只证明准备和版本交接；新θ的训练、加载、能力变化和B适配须取得各自证据，并继续经过独立生产Gate。

官方 openpi 另走适配器和匹配环境。本地 [Policy.infer](../openpi/src/openpi/policies/policy.py)有 `noise` 参数，[WebSocket 客户端](../openpi/packages/openpi-client/src/openpi_client/websocket_client_policy.py)公开 `infer(obs)` 不提供同名参数；远程固定噪声要额外核验。不能据本地模型能力推定远程实验已支持。

## 9. 候选、独立验收与继承

```text
proposal → bounded experiment → candidate
→ independent evaluation: accept / reject / inconclusive
→ eligible release → task-boundary activation → regression / rollback
```

Candidate 记录基准 RunBundle、真实修改范围、模型/代码/配置产物、数据与开发实验、总成本、兼容条件、算法新颖类型与审批状态。负结果和拒绝候选保留。

正式发布使用一个受保护写入入口。基准已过期的候选先重新确认适用性并验收；不直接叠加。执行侧激活处理模型、处理器、归一化、相机映射、动作语义、内部历史和未完成队列；ψ 的新版本在研究作业边界激活，已启动作业保持原版本。拒绝或未决维持当前有效版。

第一次在仿真中激活研究候选，也需要预先固定适用于该任务范围的硬约束、综合评分、缺失处理与三态 Gate；具体要求见 03 §3。开发结果和允许反馈的发布回归结果可进入研究证据，最终封存测试的隐藏标签不能回流用于修订候选。

现有单写发布路径核对基准并原子替换 active；F13 沿原 intent 对账激活记录与 active 之间的崩溃，并核对 stale revision 和实际加载身份。资格、active 期望版、服务实际加载与后续任务继承分别记录，指针更新不能代替模型加载。

开发、允许反馈的发布回归和最终封存/元考试分开。读写隔离分别落地：Research/可执行候选不能通过共享文件、日志、环境或开放 RPC 读隐藏标签；Evaluator 的私有参考不得回流运行决策。正式作业仍由 Host 准入资源，评价任务和评分由独立协议拥有。

## 10. 开放式候选与治理

允许在隔离环境探索新损失、数据构造、更新规则、技能、模块组织与 Meta-RSI 程序。先开放具体、有限的补丁/插件范围，随实际研究需要扩展；不先建设任意结构搜索平台。首版实现一个明确接口，候选内容允许由系统产生，不能全部退化为开发者逐项预写选项。

候选运行限制网络、文件、设备、依赖、时间和资源权限。按其修改范围执行静态/接口检查、有界动态试验和任务回归。治理资源、硬安全、最终评价与发布门槛由外部可信角色保护。

| 操作 | 条件 |
|---|---|
| 生成与隔离验证算法/结构候选 | 已授权的修改范围、实验环境和预算 |
| 已批准方法的常规真机试验 | 在已有预授权的任务、参数、设备与安全窗口内 |
| 此前未验证的新算法首次真机 | 仿真通过、独立安全检查通过、人工审批后进入授权测试 |
| 正式版本发布 | 独立 Gate 通过并具备相应设备/部署许可 |
| 修改治理边界 | Meta-RSI 无权自行修改；外部修订需新协议版本 |

H3 与机制创造均保留实质研究努力。人编写的策略用于设计对照，系统从反馈自主提出并实际继承的修订才进入自主元改进证据；仅保存 ψ 或产生代码文件不算完成这项研究。独立考试与机制试验分别见 03，真实来源和人工介入进入成本记录。

“配置调整还是新算法”的分类依据实际改变的学习/控制语义和原审批范围，不能通过重命名绕过人工审批。首次真机批准绑定候选、实验及约束范围；发生范围外变化重新判断。

工程方案与运行授权分别管理；实际实验的资源、设备和算法审批范围随实验记录，推进状态与待办集中在 04。


## 11. LIBERO 执行消费者

动态A沿用v9分工：Planner负责目标/子目标选择、执行段监督、工具切换、恢复和停止；`vla_execute(instruction, max_chunks)` 负责有界连续预测执行，不要求每个 chunk 返回 Planner。`max_chunks` 必填且为 1—24，每个 chunk 保留原生五步语义。额度用尽但原生未成功时仅表示任务未完成。旧抓取/接触/几何工具及 WAM 语义保留；不增加持物、阶段成功或停滞判定器。

[execution_arms.py](../RPent/robots/libero/execution_arms.py) 定义 `libero-execution-arm-v1`，由 `runtime.prepare_runtime` 检查并绑定到context。D/S/R经现有Flash robot hook调用 `run_execution_arm`，直接消费Toolkit/VLA链；A继续由Codex Planner驱动。D固定原始任务指令，S执行冻结阶段顺序与参数，R按冻结的complete/timeout/unknown边选择后继或停止。S/R条件实际读取公开EEF/夹爪状态，独立评价私有真值不回流。

四臂沿用匹配模型、processor、动作时序、原生结果及资源计量；D/S/R关闭ρB路由和在线Planner，程序用尽而缺少原生终态时保持unknown。D的实际消费者、原始指令、零模型请求和原生success已有[独立验收](../artifacts/framework15-20261115/state/evaluation/audits/framework15-D-base-s0-recovery1-zero-request-v2.json)；各臂的完整尝试和当前状态仍见04。

实际链为 `LiberoPrimitives._last_obs → _vlm_chunk` 的调用局部任务文本 → `Pi05VLAClient.encode_obs` → 原生 `vla.predict` / `Pi05VLAFacade.predict` → 已有 processor 与 `predict_action_batch` → 原 action chunk / 单位 → `rsi_chunk_step` → `LiberoEnvFacade.chunk_step` / RLinf → 最新观测。新工具只循环既有链，不复制推理或使用 WAM 接口。总步数 owner 含 setup/reset；余量不足五步时不再预测，保留原生 chunk 语义。时间、取消、存储及其它监督继续有效。

Planner 的可选精简反馈只省略额外 policy 视图，保留有标定的全局/腕部图与相机、步骤、分辨率对应关系；`view_env_state(image_detail="full")` 可回退。VLA 图像、processor、磁盘原始媒体及独立评价输入不改。startup-v2 默认使用相关记忆原文节选并保留条件、证据强度和全文入口，不注入其它场景绝对高度。旧漏抓经验适用于 Planner 负责放置时的抓取恢复，不构成新路径的全任务提示禁令。

Toolkit 在原生成功及状态落盘后发布身份绑定的 `native_completion.json`；RequestGate 阻断后续模型转发，Codex 以成功控制收口而非外部取消结束。原始 SDK 状态保留；仅已证实的本地成功准入拒绝归入正常收口，其它错误保留。每次推理、建议/发送/反馈和清理仍有独立记录；客户端 RPC 反馈不代表控制器测得运动。自动 finalizer 沿用既有原生/服务/监督证据要求。当前版本、实际运行与停止状态见 [04 §1.17](04_实施路线与执行状态.md#117-5a-数据经验有限往返与资格准备2026-11-13)；首次离线接线记录见 core/OFFLINE_CHECKS.md §7，后续证据沿其相应批次引用。


## 12. Piper 接入与工程交付边界

Piper 按已确认实际 API 的既有设备副本接入 RPent RobotSpec、Env/VLA 和 owned/borrowed 生命周期，保持唯一设备发送入口。当前本项目尚无 `robots/piper/` 的完整接入证据；设备副本拥有者、可修改范围和底层动作/停止语义在 F00/F15 核定。

已读本地驱动的连接会使能并标定，断连/停止路径包含回位或标定调用。因此读状态、使能、停止、回位和清理分别处理，不能在异常退出中隐式触发未经许可的运动；离线替身不得实例化有硬件副作用的驱动。实际单位、坐标、时钟、停止/失联和人工恢复逐项沿真实代码确认，不能照搬 LIBERO 七维动作或模拟器 reset。
