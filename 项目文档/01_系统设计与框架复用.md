# 系统设计与框架复用

方案基线：V5.1（2026-11-09）；实现映射维护：2026-11-13。目标与术语见 [00](00_项目总纲与研究边界.md)，验收见 [03](03_实验设计与验收协议.md)。本文区分当前代码入口与完整系统目标；运行完成度见 04 §1.17，初始源码判断及版本范围见 [05 §4](05_决策映射与审查复核.md#4-关键源码判断的复核)。

## 1. 最小职责拓扑

采用 RPent 主 Runtime、独立轻量研究 core、按需接入的训练和优化后端。RPent 是当前工程首选，其适用性由实际接入验证；出现具体瓶颈时再评估替代。

| 职责域 | 生产什么 | 消费什么 | 最终权限 |
|---|---|---|---|
| 前台执行 | 任务状态、动作建议、实际发送与反馈、监督事件 | 已发布版本、实时观测、外部任务 | 仅调用已授权 Worker；硬安全由执行服务控制 |
| 证据与数据 | 执行事实、媒体引用、缺失及成本、合法视图 | 执行与实验生产者的原始记录 | 保护历史事实与基础审计 |
| 研究与学习 | 机会、假设、实验、候选、ψ 修订 | 合法证据、开发反馈、剩余预算 | 可提交实验和候选，无正式发布写权限 |
| 独立验收与发布 | accept / reject / inconclusive、有效版本 | 候选与受保护协议、评价资源 | 判断发布资格并控制激活 |

这些是职责边界，可以由少量进程实现。前台和研究者可复用同一种 Planner，但使用不同工具和数据视图。Gate 优先使用确定性检查、环境判据与固定评价程序，不要求新增大型 Agent。

## 4. 运行、动作与模型合约

每个后端声明观测/动作规格、坐标系、单位、控制频率、动作前缀、队列、时钟与 reset 语义。LIBERO 末端命令和 Piper 关节目标分别定义；相同维数不代表动作可互换。

| 对象 | 最小内容 | 生产者 → 消费者 |
|---|---|---|
| BackendSpec | 图像/状态字段、坐标与单位、动作时序、可用能力 | 环境/设备服务 → 模型与执行适配器 |
| RunBundle | θ、处理器/归一化、φ、ρ、ψ、合法记忆与协议引用 | 发布端 → 前台/实验器 |
| ExecutionEvent | 身份、时间、动作源、建议/发送/反馈、缺失 | 事实发生侧 → 证据视图/评价 |
| Opportunity | 机会来源、领域关联、证据、价值假设与成本范围 | 发现过程 → 研究协调器 |
| ExperimentResult | 起点、干预、数据范围、判据、结果和全成本 | 实验器 → 研究者/验收 |
| Candidate | 基准版本、修改对象、产物、开发证据和审批适用范围 | 研究者 → 独立验收 |
| GateDecision | 协议版本、三态结论、理由、兼容性与发布资格 | 独立验收 → 发布端 |

运行记录使用可定位的版本或文件标识，保存代码版本及实际差异、配置、起点模型和数据引用。共享实现只保存一份权威产物，RunBundle 中各职责引用该产物，避免 ψ/ρC 等同一对象出现两个不一致版本。

能力声明按实际实现提供：内部特征、固定噪声、控制步干预、任意中间状态 snapshot/restore 都不能由统一接口名称推定已经支持。

实际调用的技能在现有技能配置中声明输入与返回语义、完成依据、已验证起态与场景、交接限制，以及模型/工具版本和验证记录引用。技能记录由接入配置与实验记录提供，供 Planner、ρB 和诊断过程使用；与 BackendSpec、RunBundle 共享权威引用，不另建技能数据库。成功样例只证明所测条件下的表现，未验证条件明确标注，不能外推为完整适用域或模型不变性。

模型、处理器、工具或控制协议改变后，保留旧验证记录及其版本归属，按实际依赖确认受影响调用建议对新版本的适用性。未确认不等于已失效；检查范围由具体变化和现有证据决定。

## 5. 动作级证据和 L0/L1/L2

### 5.1 记录分层

| 层级 | 内容 | 可变范围 |
|---|---|---|
| L0 基础事实 | 任务/阶段/时间/版本、动作源、建议与发送映射、反馈、监督和结果来源、缺失 | 由执行侧记录；ρA 无权选择性隐藏 |
| L1 详细媒体 | 循环缓存、关键帧、多相机片段、压缩与路由 | ρA 在预算内选择；基础随机/分层审计受保护 |
| L2 专项证据 | 完整对照轨迹、精细标签、内部表示、干预试验 | 按研究需要和实验权限启用 |

L0 的“全覆盖”是采集目标，故障时必须显式记录间隙与未知。模型建议、经过滤后发送、控制器实际应用量、测得运动是不同事实；拿不到应用量就标未知。结果至少区分 success / failure / unknown，并独立记录技术无效、拒绝执行、人工接管和未完成。

关键关联字段包括 run、episode、事件序号、active_bundle、父研究决定、捕获/接收/推理/发送/反馈时间及其时钟域、proposal 索引和实际执行掩码。记录媒体保留概率、结果标注概率和修复动作选择概率；三者分别定义，未知概率不补成 1。

受保护基础审计、自适应取证和专项实验共享总预算，但研究者不能削弱基础审计。底层安全监测不由可学习取证策略控制。

### 5.2 RPent 接入位置

| 入口 | 当前职责 | 仍需按主张补足的范围 |
| --- | --- | --- |
| [机器人发现](../RPent/rpent/robots/base.py)与 [LIBERO RobotSpec](../RPent/robots/libero/robot_spec.py) | 发现工厂、运行配置、Runtime 上下文与工具接入 | 新机器人沿薄适配接入，不复制整个 Runtime |
| [Toolkit](../RPent/rpent/tools/toolkit.py)与 [LIBERO Toolkit](../RPent/robots/libero/toolkit.py) | 工具调度、状态记录、采集与收尾 | 工具后记录不等于 chunk 内监督 |
| [动作工具](../RPent/robots/libero/tools.py)、[运行证据](../RPent/robots/libero/runtime_evidence.py) | 推理、proposal/send/RPC反馈、执行段及预算事件 | RPC反馈不等于控制器应用量或实测运动 |
| [环境服务](../RPent/robots/libero/env_server.py)与 [结果](../RPent/robots/libero/result.py) | 环境步数、原生成功来源、独立结果及技术状态 | 未返回转移、setup全轨迹与任意中间态恢复未验收 |
| [EpisodeWriter](../RPent/rpent/flywheel/episode.py)、[采集适配](../RPent/robots/libero/flywheel.py)与 [exporter](../RPent/rpent/flywheel/export.py) | 原始/分批采集、对齐与诊断/示范导出 | 自主 schema-2 数据仍 `not_admitted`，训练需单独示范准入 |
| [core Runtime](../core/src/rsi_vla/runtime.py)及 [adapters](../core/src/rsi_vla/adapters/) | 绑定版本、许可与预算，监督进程/传输并独立收尾 | 具体比较只消费适用身份和来源，不靠文档声明取得发布资格 |

`chunk_step()` 在一次 RPC 内执行整段动作；工具返回后的 Watcher 不代表 chunk 内监督。改变控制时序时重建受影响的等价基线，硬实时安全留在执行服务。

离线 EvidenceView 可以比较信息选择；只有接管真实 L1 写入出口并计量全部持久媒体，才能声称节省实际存储。初期 ρA 只改变研究取证，控制所需即时观测保持相同；研究在线路由时另行声明输入变化。任意中间态 snapshot/restore、内部特征和固定远程噪声按后端实际能力声明。

### 5.3 任务状态与完成证据

任务状态是依据合法执行证据更新的派生记录。原始工具返回保留其语义；分别记录工具调用的结束状态、子目标完成结果和整任务结果，不能把同名 `success` 字段直接作为统一完成标签。当前 RPent 的 `pi0_pick` 采用运动与夹爪阈值，`pi0_doubled` 的 `success/task_success` 对应整任务终止；静态依据见 05 §7。

对实际影响后续动作的状态，保留对象/子目标、状态值、来源事件、判定依据、适用回合及有效性。工具结束只确认调用已结束；符合该子目标预定完成判据的合法证据成立后，才更新对应阶段、关系或计数。同一完成事件只提交一次。证据缺失或冲突尚未消解时，相关状态保持 unknown。仅供评价方使用的特权状态不能用于运行状态更新，除非实验明确允许并对比较组采用相同信息条件。

历史事实与当前关系分别维护：曾完成抓取不代表当前仍持物；新证据否定当前关系时更新其有效性，保留原事件。历史可提供对象身份、顺序和次数，当前动作坐标仍由当前合法观察确定。未知状态按既有权限、预算和安全规则选择补充观察、合法恢复，或停止依赖该事实的后续动作；不得用无新增证据的重复调用或 LLM 叙述代替缺失证据。

初期仅比较研究取证的 ρA 实验，执行所需即时观测、任务状态更新规则及其证据访问条件保持一致。任务状态更新沿现有事件与工作记忆实现；规则的运行检查和效果评价见 03 §3.5，来源见[旧资产复用 §2.1](旧资产复用/复用分析.md#reuse-2-1)。

## 6. ρA/B/C 与 ψ 的实现边界

| 策略 | 输入 → 输出 | 最简起步 | 能力验收 |
|---|---|---|---|
| ρA | 合法事件/缓存 → 保留、压缩和路由 | 固定/分层审计、少量优先级 | 能从反馈产生候选并跨轮继承 |
| ρB | 任务阶段、Worker 与监督状态 → 调用/交接/恢复 | 现有路由、阈值校准 | 在固定能力集合下可单独干预 |
| ρC | 证据、修复集合、预算 → 实验/更新/暂缓 | 固定顺序、简单收益表 | 更新选择和资源分配有真实反馈 |
| ψ | 研究历史与可信结果 → 研究决策或规则修订 | 可保存、冻结的研究协议 | 支持共同起点的新问题考试 |

学习算法可先用参数搜索、规则优化或适用通用优化器。目录和可编辑字段不是学习算法，实际规则必须说明状态、动作、目标、更新与反馈。φ 的恢复程序与 ρB 的选择策略分开引用，Planner 提出意图、ρB 选择授权 Worker、执行服务发送动作，保持唯一发送入口。

技能交接失败时，将顺序/切换错误、起态或场景变化、后继技能能力不足作为可并存的竞争解释。先核对后继技能在已验证起态上的证据，再检查前驱留下的状态与之有何差异；只使用现有合法观察，不能隔离变量时保留未决。诊断应对应保持技能、修正调用语义或切换、补充实际起态数据等可执行决定，不凭失败标签认定原因。局部恢复、交回续程与 reset 重试按 03 §3.5 分别记录和评价。来源见[旧资产复用 §2.2—2.3](旧资产复用/复用分析.md#reuse-2-2)。

ψ 可表示为参数、规则、提示或程序。更新 ψ 不必改写源码；参数变化也不自动证明 H3。ρC 与 ψ 共享实现时，实验保存具体冻结范围。

## 7. 机会发现与自主研究

研究入口覆盖失败、成功但低效/高接管、能力边界与领域内新需求。每项机会保留“外部价值、已有证据、竞争解释、预期代价、可区分试验”；进入队列不等于获得实验额度。

初期用规则和简单优先级完成最小服务，具体机会选择学习算法保持开放。Meta-RSI 在已授权预算内可以选择补证、实验、代码/技能修复、训练 VLA、修订关系或暂缓。新能力目标先按预定规则检查领域相关性、权限与可检验性，在预算内自主学习，随后由独立任务验证真实价值；该流程不要求人逐项挑选领域内目标。学习目标可由系统选择，论文外部考试任务流保持独立。

Research Agent 复用 Planner 和独立 Toolkit，工具限于合法证据查询、版本比较、提交实验、训练配方和候选。研究 Toolkit 应返回作业状态和记录，不通过标注全部 `readonly` 跳过状态管理。RPent 的该标记服务于工具调度，不是安全 ACL。

ENPIRE 的[研究契约](../ENPIRE/enpire/policy/autoresearch_instruction.md)可作记录参考；其 [autoresearch.py](../ENPIRE/enpire/policy/autoresearch.py) 是控制请求客户端。本项目已有有限研究、假设与预算消费者；完整的机会学习、多轮研究及关系进化按实际目标继续实现，当前范围见 04。

## 8. 训练到运行的真实往返

首条链优先沿 RPent 当前 π0.5 服务使用的 RLinf 加载器，选择相匹配的原训练配方。RPent [依赖声明](../RPent/pyproject.toml)指向特定 RLinf release 与 openpi/LIBERO 分支，各个已克隆目录不等于已兼容环境。

[RLinf 示例配置](../RLinf/examples/sft/config/libero_sft_openpi.yaml)使用 `pi0_libero`，不能只改路径便当作 π0.5 配方。需核对模型类型、字段、图像处理、归一化、精度、chunk 和解码。

```text
原始执行/示教 → 合法训练数据与 exporter
→ 原 trainer + 起点模型 + 完整配置
→ checkpoint + processor/归一化 + 实际成本
→ 前台实际加载器 → 解码动作 → 任务评价
```

接口往返通过只证明可用性；能力改善需要独立任务结果。训练数据的实际来源、可用规模与目标技能覆盖需要在启动前确认：已有示教、合法执行数据或获授权的新采集分别标明；筛出的成功片段不足时先记录数据缺口，不把失败片段自动当作正确示范。TrainingBackend 只负责启动原训练器、监督预算并返回产物与退出状态，不重写训练循环。

官方 openpi 另走适配器和匹配环境。本地 [Policy.infer](../openpi/src/openpi/policies/policy.py)有 `noise` 参数，[WebSocket 客户端](../openpi/packages/openpi-client/src/openpi_client/websocket_client_policy.py)公开 `infer(obs)` 不提供同名参数；远程固定噪声要额外核验。不能据本地模型能力推定远程实验已支持。

## 9. 候选、独立验收与继承

```text
proposal → bounded experiment → candidate
→ independent evaluation: accept / reject / inconclusive
→ eligible release → task-boundary activation → regression / rollback
```

Candidate 记录基准 RunBundle、真实修改范围、模型/代码/配置产物、数据与开发实验、总成本、兼容条件、算法新颖类型与审批状态。负结果和拒绝候选保留。

正式发布使用一个受保护写入入口。基准已过期的候选先重新确认适用性并验收；不直接叠加。执行侧激活处理模型、处理器、归一化、相机映射、动作语义、内部历史和未完成队列；ψ 的新版本在研究作业边界激活，已启动作业保持原版本。拒绝或未决维持当前有效版。

第一次在仿真中激活研究候选，也需要预先固定适用于该任务范围的硬约束、综合评分、缺失处理与三态 Gate；具体要求见 03 §3。开发结果和允许反馈的发布回归结果可进入研究证据，最终封存测试的隐藏标签不能回流用于修订候选。

## 10. 开放式候选与治理

允许在隔离环境探索新损失、数据构造、更新规则、技能、模块组织与 Meta-RSI 程序。先开放具体、有限的补丁/插件范围，随实际研究需要扩展；不先建设任意结构搜索平台。

候选运行限制网络、文件、设备、依赖、时间和资源权限。按其修改范围执行静态/接口检查、有界动态试验和任务回归。治理资源、硬安全、最终评价与发布门槛由外部可信角色保护。

| 操作 | 条件 |
|---|---|
| 生成与隔离验证算法/结构候选 | 已授权的修改范围、实验环境和预算 |
| 已批准方法的常规真机试验 | 在已有预授权的任务、参数、设备与安全窗口内 |
| 此前未验证的新算法首次真机 | 仿真通过、独立安全检查通过、人工审批后进入授权测试 |
| 正式版本发布 | 独立 Gate 通过并具备相应设备/部署许可 |
| 修改治理边界 | Meta-RSI 无权自行修改；外部修订需新协议版本 |

“配置调整还是新算法”的分类依据实际改变的学习/控制语义和原审批范围，不能通过重命名绕过人工审批。首次真机批准绑定候选、实验及约束范围；发生范围外变化重新判断。

工程方案与运行授权分别管理；实际实验的资源、设备和算法审批范围随实验记录，推进状态与待办集中在 04。


## 11. 当前执行分工：bounded-vla-v1

v9 的 Planner 负责目标/子目标选择、执行段监督、工具切换、恢复和停止；`vla_execute(instruction, max_chunks)` 负责有界连续预测执行，不要求每个 chunk 返回 Planner。`max_chunks` 必填且为 1—24，每个 chunk 保留原生五步语义。额度用尽但原生未成功时仅表示任务未完成。旧抓取/接触/几何工具及 WAM 语义保留；不增加持物、阶段成功或停滞判定器。

实际链为 `LiberoPrimitives._last_obs → _vlm_chunk` 的调用局部任务文本 → `Pi05VLAClient.encode_obs` → 原生 `vla.predict` / `Pi05VLAFacade.predict` → 已有 processor 与 `predict_action_batch` → 原 action chunk / 单位 → `rsi_chunk_step` → `LiberoEnvFacade.chunk_step` / RLinf → 最新观测。新工具只循环既有链，不复制推理或使用 WAM 接口。总步数 owner 含 setup/reset；余量不足五步时不再预测，保留原生 chunk 语义。时间、取消、存储及其它监督继续有效。

Planner 的可选精简反馈只省略额外 policy 视图，保留有标定的全局/腕部图与相机、步骤、分辨率对应关系；`view_env_state(image_detail="full")` 可回退。VLA 图像、processor、磁盘原始媒体及独立评价输入不改。startup-v2 默认使用相关记忆原文节选并保留条件、证据强度和全文入口，不注入其它场景绝对高度。旧漏抓经验适用于 Planner 负责放置时的抓取恢复，不构成新路径的全任务提示禁令。

Toolkit 在原生成功及状态落盘后发布身份绑定的 `native_completion.json`；RequestGate 阻断后续模型转发，Codex 以成功控制收口而非外部取消结束。原始 SDK 状态保留；仅已证实的本地成功准入拒绝归入正常收口，其它错误保留。每次推理、建议/发送/反馈和清理仍有独立记录；客户端 RPC 反馈不代表控制器测得运动。自动 finalizer 沿用既有原生/服务/监督证据要求。当前版本、实际运行与停止状态见 [04 §1.17](04_实施路线与待决事项.md#117-5a-数据经验有限往返与资格准备2026-11-13)；首次离线接线记录见 core/OFFLINE_CHECKS.md §7，后续证据沿其相应批次引用。
