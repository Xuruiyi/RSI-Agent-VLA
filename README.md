# RSI-Agent-VLA

面向机器人操作的持续自进化研究项目。目标是在有限交互、计算和人工预算下，让 Super-agent 与 VLA 完成任务，从执行证据中发现研究机会、开展实验，并经独立验收发布和继承新版本。

**研究主线采用 RPent + 自研 core + 匹配的 RLinf/OpenPI 模型链。** 持续开发重点是 `RPent/` 的执行与证据能力，以及 `core/` 中的研究机制；其他项目按实验需要接入或作为设计参考。

当前处于离线补件与后续实验准备阶段，已有 RPent–VLA 执行链和部分开发回合的运行证据。完整自主更新、真实训练—加载—独立评价往返、正式发布与跨轮继承尚待验证，主科学问题仍待选定。研究进展和待决事项以[实施路线 §1](项目文档/04_实施路线与执行状态.md#1-当前状态与证据)及其中最新的 §1.16 为准。

## 核心项目

### RPent：主要工程底座

[`RPent/`](RPent) 承担 Planner、工具调用、VLA 执行、监督恢复、会话和机器人接入，为研究产生真实执行证据。它是任务运行与机器人交互的主要载体。

本项目在现有执行链上补充动作级记录、结果来源、版本关联和研究工具接入。工具调用结束、子目标完成和整任务成功分别记录，研究与评价消费实际执行事实。

### core：自研研究主体

[`core/`](core) 是本项目维护的自研模块，后续原创机制主要在这里实现。它负责把执行证据转为研究机会、实验和候选，再交给独立评价与发布流程。

| 研究职责 | 具体内容 |
| --- | --- |
| 证据与机会 | 合法证据视图、缺失与技术有效性、机会发现与诊断 |
| 实验协调 | 起点与候选关联、预算账本、有界作业及结果消费 |
| 协作与研究策略 | ρA：取证与信息路由；ρB：职责分配与交接；ρC：更新对象、方法和预算；ψ：诊断、实验设计与研究策略 |
| 独立验收与继承 | 候选提交、固定协议评价、accept / reject / inconclusive、安全点激活、版本继承与适用回滚 |

当前代码已提供相关合约、离线状态机及 Runtime、研究、训练适配入口；固定 ρ 与初始 ψ 仍是基线。学习策略、真实模型更新和动态发布闭环需要各自的实验与验收证据。实现入口见 [core README](core/README.md)，检查记录见 [OFFLINE_CHECKS](core/OFFLINE_CHECKS.md)。

### RLinf 与匹配 OpenPI：模型加载与更新链

当前 π0.5 加载使用匹配的 RLinf/OpenPI 实现，模型更新优先沿匹配的原生训练器接入。近期模型链工作的重点是验证数据读取、训练、模型与处理器保存、实际加载及独立任务评价的完整往返。

**项目能力的使用与同级源码目录的使用分别管理。** 当前环境中，RLinf 0.4.0 和 `rpent-openpi` 0.2.2 来自 `RPent/.venv` 的 `site-packages`；训练适配器也沿这条安装链调用。同级 `RLinf/` 与官方 `openpi/` 源码用于参考和按需适配，切换实现前需要核对版本、模型配置及动作合约。

安装来源与维护边界见[实施路线 §1.1](项目文档/04_实施路线与执行状态.md#11-首条链资产与匹配环境2026-11-09-更新)，当前训练桥接见 [`pi05_training.py`](core/src/rsi_vla/adapters/pi05_training.py)。

## 各项目的接入定位

| 项目目录 | 当前定位 | 用途与接入边界 |
| --- | --- | --- |
| [`RPent/`](RPent) | 确定使用，主要工程底座 | 执行、监督恢复、工具与机器人接入，产生研究证据；持续开发重点。 |
| [`core/`](core) | 确定使用，自研研究主体 | 证据、研究机会、实验协调、ρA/B/C 与 ψ、独立验收及继承；主要原创机制的实现位置。 |
| [`RLinf/`](RLinf) | 确定使用匹配实现 | 当前 π0.5 加载和原生训练器接入依赖 RLinf；同级源码目录目前不是运行时导入来源。 |
| [`openpi/`](openpi) | 模型技术栈使用，官方目录按需使用 | 当前使用匹配安装的 `rpent-openpi`；官方源码用于原生训练推理参考或需要内部干预的实验，不额外维护并行主链。 |
| [`gepa/`](gepa) | 有明确研究用途，按实验接入 | 文本、提示或配置优化及强基线；研究 ψ 改进时具有对照价值，接入取决于优化对象与评价接口。 |
| [`skydiscover/`](skydiscover) | 条件使用 | 关注 EvoX 等搜索策略演化机制，作为方法参考或基线；接入取决于元搜索科学问题。 |
| [`ENPIRE/`](ENPIRE) | 当前主要参考 | 借鉴研究契约、实验记录和权限设计，适用时复用任务后端；其 `autoresearch.py` 控制请求客户端不承担本项目 Meta-RSI 总协调。 |
| [`OpenETA/`](OpenETA) | 当前主要参考，保留备选 Runtime 身份 | 借鉴证据与工作记忆分离设计，必要时评估替代 Runtime；当前主 Runtime 为 RPent。 |

GEPA 和 SkyDiscover 在比较机制与评价接口明确后接入。ENPIRE、OpenETA 当前不承担主系统职责，未来是否使用由具体实验需要决定。完整分工见[系统设计 §2](项目文档/01_系统设计与框架复用.md#2-代码和仓库分工)。各项目目录保留原许可证。

## 仓库历史与本地文件

`main` 保存本地工作区的上传快照，包含首次上传时尚未在各子项目提交的源码修改。原项目历史通过合并父提交连接到 `main`，原有提交 ID、作者和提交信息保持不变。

`history/<项目名>/main` 提供原项目分支入口，历史提交中的路径沿用原仓库布局；RPent 上传时记录的上游分支保存在 `history/RPent/remotes/origin/main`。

```bash
git log history/RPent/main
git log --all --graph --oneline
```

总目录跟踪本仓库的 `origin/main`，各子项目仍保留本地原有 Git 配置。更新本仓库时，在总目录执行提交与推送。

下载数据、模型权重、运行日志、实验输出、虚拟环境、缓存和本机凭据配置排除上传；原项目已跟踪的示例资源、测试输入和数据处理代码随源码保留。`config/models.local.sh` 在运行机器上单独配置，实验原始产物需结合本地记录查阅。
