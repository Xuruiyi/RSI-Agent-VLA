# RSI-Agent-VLA 框架优化与分阶段实施计划

日期：2026-11-15。依据：[本地复核](04_本地复核与研究判断.md)、原有01—03及项目当前实现。近期执行指令见 [06](06_近期框架优化执行提示词.md)；近期交付后的Autoloop前置验收及中期一指令见 [07](07_中期任务执行提示词.md)。

总体安排：近期完成可信的最小实验框架，中期取得真实学习与协作适应证据，中长期验证长期成长、研究策略与关键物理机制。F2 是有条件的候选主线；项目完整目标不由单个研究假设的成败决定。

## 1. 目标与阶段验收

| 层次 | 完成含义 | 本计划的安排 |
| --- | --- | --- |
| 工程实现 | 实际生产者、消费者、版本、结果与资源能联通 | 近期主要交付 |
| 真实集成 | 现有匹配模型链在有限仿真条件下实际消费新接口 | 近期有界验证；缺前提时明确剩余项 |
| 有效学习 | 新 θ 有独立能力收益及旧能力评价 | 中期首项实质任务 |
| 科学机制 | 超过强简单方案，具有区别预测与独立比较 | 随依赖逐项展开 |
| 完整系统 | 达到项目 SC1—SC8，覆盖长期变化与Piper关键闭环 | 长期责任 |

近期不承担真实训练、训练收益、正式大矩阵、现行部署更新或真机。必须实施的工程工作不能仅以草案替代；未取得的动态证据也不能由离线通过代替。

## 2. 近期工作包

### N0 确定实际起点与本轮边界

读取聚合项目与RPent的适用指令、实际工作树、解释器和依赖来源，核对已有模型、数据及当前占用。确认文件所有权、新任务身份、本轮有限预算和有效期。

RPent已有改动必须保留。当前聚合基线和独立仓HEAD不是同一种来源；使用干净副本或worktree时，不能丢失当前集成。优先按文件分工减少重叠，不强制创建新开发平台或全量源码归档。

**交付与验收：** 实际起点、可用资产、写域和差异可定位；已有历史任务不变；本轮预算与单次监督限制能够被真实消费者执行。

### N1 接通D/S/R/A实际执行消费者

入口：`RPent/robots/libero/{tools,toolkit,task_input,runtime_evidence,result}.py`、`core/src/rsi_vla/runtime.py`及现有执行/评价脚本。

- D由确定性程序完成整回合，固定原始指令，使用最新合法观测、同一VLA与动作前缀；无在线Planner和隐含动态路由。
- S执行冻结技能顺序、参数和切换规则，不重新规划。
- R执行冻结条件策略，允许预定观察、恢复和停止分支。
- A复用现有动态Planner；新接口应与其实际消费者对齐。

先支持一个任务族，再按集成需要增加第二情形；共用模型、动作、结果和预算实现。为每臂声明合法信息、实际感知入口、控制时序、终止、unknown与开发/运行成本。S/R的能力重叠按真实行为解释。

**交付与验收：** 四臂有实际消费者，D没有隐藏Planner，S不在线改计划；离线测试覆盖停止、预算、失败与未知；有界真实贯通证明所运行臂确实可跑，不要求靠成功视频验收。

### N2 对齐Research输入与诊断任务

入口：`research_transport.py`、`bounded_runner.py`、`research_tools.py`及实际SDK输入消费者。

增加可读结构化正文，保留原始事实引用、所选范围、省略和unknown。区分业务请求与实际模型输入；保留决定诊断边界所需的输入身份、媒体及回执。合法开发证据可由宿主按请求补读并形成新的有界请求，不必开放任意工具执行。

视觉诊断需要图像时，核验当前SDK支持并传入实际合法媒体。仅有路径或文字摘要时保持text-only语义；不能从Planner能看图推断Research也能看图。媒体不可得只限制相关诊断，独立工作继续。

**交付与验收：** 请求与实际输入能关联，已选/未选/缺失可区分；同一事实的可读表示与原始引用不互相矛盾；补证、有限候选和defer有真实消费者。

### N3 改善关系反馈与研究准入

入口：`relation_learning.py`、`cooperation.py`、`relation_consumption.py`、`research_tools.py`及开发结果消费路径。

ρA保留当前引用压缩基线，分别记录引用量、实际payload/存储及后续诊断评价。近期不以新名字包装现有压缩规则，也不为产生学习标签训练新网络。

ρC保留旧screening基线；为新任务增加按算子、证据类别、版本和必要数据条件区分的上下文及反馈分项。提供有限探索或重新评估入口，解除“未再尝试所以无法更新判断”的闭环；探索仍满足技术、数据与预算准入。旧快照继续按其历史语义消费，不重标旧反馈。

先用合法历史回放定位决策分歧；有界真实验证只针对会改变后续动作的重要分歧。回放不提供未执行分支收益。

**交付与验收：** 能说明实际选择为何改变、消费了哪个快照及反馈；低通过率不会未经条件判断代表所有研究方向无价值；技术准入未被探索逻辑绕过。策略是否更有效留待独立比较。

### N4 实现新任务结果驱动续程

入口：`task_completion.py`、现有coordinator/backend接口、`task_policy.py`及`autoloop_bridge.py`。

在现有core上实现薄的阶段选择和事件适配，串联证据、Research、开发试验、反馈、候选和结束。复用pending、operation、receipt、reconcile与账本。补证、继续实验、暂缓/结束等至少两个合法后继应能由真实结果选择。

资源等待自动有界复查；技术错误、有效failure、reject、研究停滞、人工暂停和到期分别处理。先用故障注入验证重复事件、重启、延迟/丢失回执和未知提交，再做一条有界真实链。保留Autoloop接入点，只有确实需要时启动完整服务，不改造上游平台替代业务接线。

**交付与验收：** 事件→准入→唯一派发→回执→下一步可追溯；重复触发不会重复副作用或结算；暂时技术停止可按本轮规则恢复；人工暂停与终止仍阻止派发。

### N5 训练准备与有效ψ起点

入口：`adapters/pi05_training.py`、`training.py`、`scripts/{prepare_pi05_training,run_pi05_training}.py`、RPent flywheel及模型client/server。

核对合格示范的来源、许可、动作单位、processor、归一化和评价隔离，优先以现有匹配安装链完成小型真实数据原生CPU batch。缺少主体时只下载许可、来源与契约已确认的小型必需资产，受本轮下载上限约束。自主轨迹不通过改`source_kind`变成教师示范。

训练、checkpoint、load与评价交接按已有原生链准备，提供未来θ×B受控绑定的最小设计及必要离线检查；保留版本准入，明确fallback。实际训练和收益在下一阶段完成。

定义有效ψ的程序、提示、ρC和检索归属，事实记忆单列；保存初始策略、依赖、合法事实及开发成本，预留未参与开发的机制/任务族。后续修改保留模型/程序/人工来源，无实际更新不生成伪晚期ψ。

**交付与验收：** 数据资格、真实batch、训练准备与实际训练状态分别可见；未来加载/评价交接具体；初始ψ可追溯、可比较。资产缺失明确阻断相应节点，不以合成batch冒充真实数据。

### N6 验证、文档与收尾

按变更选择core离线测试、RPent相关单元测试和必要跨模块检查；共享接口变化覆盖调用方。准备PR时完成CONTRIBUTING要求的全量检查；Sphinx内容/构建输入变化时做双语构建。复用仍有效的结果，相关修改后只补受影响检查。

离线通过后，依次做D及S/R/A必要贯通，再验证Research→反馈→下一步。首次运行验证整臂消费者，新增运行必须回答新的具体缺口；不把本批预算消耗成正式E1矩阵。

当前执行进展归`项目文档/04`；设计与决策进入相应owning文件；验证记录沿用现有入口。原有历史、原始产物、暂停和failure保留。

**交付与验收：** 列出实现、离线通过、真实仿真、受阻与未验证状态；清理本任务进程和锁，保留回执、成本与unknown；给出中期第一项任务及前提。动态验收缺失时不能宣布全部完成。

## 3. 顺序与协作

```text
N0 → N1执行消费者 ──────────────┐
   → N2证据 → N3反馈 → N4续程 ─┼→ N6集成与交付
   → N5数据/训练准备、ψ起点 ───┘
```

接口先协调，文件可并行，动态作业由主代理统一调度。并发GPU推理/训练不作为近期实现前提。

| 角色 | 默认负责范围 |
| --- | --- |
| 主代理 | 接口、资源与派发、共享文件集成、验收、权威状态和最终交付 |
| 子代理A | RPent执行消费者与对应测试，N1为主 |
| 子代理B | Research输入、关系反馈、有效ψ，N2/N3为主 |
| 子代理C | 新任务调度与恢复、训练准备，N4及N5部分 |

主代理可调整或串行处理。`runtime.py`、`task_completion.py`、`research_tools.py`、`cooperation.py`等共享文件需指定唯一编辑负责人，不能按工作包让多人同时修改。无需固定设立审查代理。

## 4. 近期资源与授权设计

本节对应06的近期包；07单列后续新包，不续用旧余额和期限。用户已委托主代理合理把握资源、分工和目标范围内异常。近期执行提示词将其落实为以下有限外层包，主代理可锁定更小的本轮预算并调整阶段软分配。

| 维度 | 外层上限 |
| --- | --- |
| 有效期 | 新终端接受实施任务起72小时；暂停不续期 |
| 编程并发 | 主代理＋最多3个活跃子代理，嵌套计入 |
| Runtime实际启动 | 最多20次，含技术恢复 |
| Planner/Research实际模型请求 | 共最多200次，其中Research最多4次，含失败与不确定提交 |
| GPU占用包络 | 累计8 GPU·小时，按设备分别相加 |
| 累计新增逻辑产物 | 最多20 GiB，按既有口径去重，删除不退累计额度 |
| 下载 | 累计最多1 GiB，仅必要小型公共资产与锁定依赖 |
| 资源等待 | 累计最多60分钟 |
| Runtime技术恢复 | 全轮最多4次，每逻辑槽最多1次，包含在各总额内 |

VLA预测次数与动作/RPC单列，受GPU、单次时长、环境步等实际监督限制；不将其混同为Planner/Research请求。编程平台额度另记。普通只读/离线检查的有界重试不占Runtime恢复次数，但保留实际成本。

资产和单位成本尚未在本轮重新测定；上述值是工程集成上限，不是资源存在声明或统计样本量。主代理在外层包内确定各次运行的任务、指派分母、单次限制和停止条件，不为用完额度增加试验。

包内允许必要代码/文档、离线验证、隔离环境必要修复、小型合法下载、CPU batch与仿真集成。真实训练、真实机器人及其外设、现行active、采购、系统级修改和凭据变更不在包内。仅越过硬上限/期限、目标/验收或权限边界时询问用户；平台权限由真实宿主入口处理。

## 5. 中期与中长期任务

以下按证据依赖推进，不由06的近期任务自动启动。用户明确执行07后，仅启动其规定的Autoloop前置验收和中期一；其余阶段继续使用各自进入条件。E1—E3沿用本目录原02的建议实验包含义，不替换`项目文档/03`原有E0—E7编号；实际实施使用独立新协议ID，保持映射。

| 阶段 | 核心交付 | 继续、简化或转向 |
| --- | --- | --- |
| 中期前置：Autoloop无人值守验收 | 一次总启动，真实定时/回执唤醒、重启核对、资源等待及合法结束；宿主在总授权内准备作业和permit | 主代理仍逐节点代办、只改开关或仅有CPU替身时未通过；资源恢复不解除人工暂停或到期 |
| 中期一：真实学习与E1 | 合格数据→原生训练→新θ→加载→裸VLA收益与旧能力；分层比较D/S/R/A | 先解决无效训练或接口问题；动态Agent无净收益时简化稳定执行层 |
| 中期二：E2再适应 | 同一冻结B0/B1四格、简单校准/记忆修订、无θ变化等预算适应对照 | 旧B适用则继承；简单方法足够则采用；有重要残余才深入 |
| 中长期一：E3机制 | 用技能入态/交接/调用结构预测失配，比较均匀、窗口、普通VOI及候选方法 | 分别检验结构、预测及真实决策收益；只改善辅助指标不自动升级贡献 |
| 中长期二：主动与多轮 | 新目标环境/终止/评分一致，固定外部需求，课程/失败优先/学习进步/机会选择比较 | 测新增能力、组合解锁、保持及累计效用，保留拒绝、停滞和全部成本 |
| 中长期三：H3实考 | 真实早晚有效ψ、共同起点/事实、固定搜索对照、预留机制/家族与独立历史 | 记忆或搜索解释收益则收窄；迁移成立才扩大主张 |
| 后期：有限迁移与Piper | 第二动作类型验证关键机制；Piper数据与控制合约、关键更新闭环及真实复位/人工成本 | 共享机制与各自合约分开；现场规范与新算法真机审批继续适用 |
| 成文与最终确认 | 冻结候选、强基线及评价设计，使用未参与选择的新确认材料 | 按实际支持范围写一篇论文，保留负结果和未决 |

2026-11-15任务划分补充：下一实施批次采用[07](07_中期任务执行提示词.md)，完成Autoloop前置验收及中期一，并补齐数据正式准入、共同记录/控制条件、充分开发的S/R、原生训练资源试测、新θ加载和隔离仿真继承。中期二另开后续批次：它依赖真实θ1和能力变化，还需独立的B1适应预算、四格及无θ变化同预算对照；本轮同时调试会混淆学习与适应效果。07只保存真实B0、θ0/θ1和E2必要证据，不提前执行适应开发，也不把初始S/R包重标为B1。

工程安排按近期一个实施批次、中期若干学习/比较批次推进。具体周/月排期在真实吞吐、数据与现场资源明确后确定；不能用历史六个月规划输入推定当前有效期限。

## 6. 长期目标与条件分支

长期完整目标沿项目00及03的SC1—SC8：真实执行与证据、失败/正常机会、自主研究、规则与θ更新、独立采用继承和回滚、三关系反馈学习、连续复合变化、Piper关键物理闭环。

研究目标是在固定外部需求与有限物理/计算/人工资源下，形成可重复的能力成长或学习效率收益；主科学机制超过强简单方案，并有区别预测、独立比较和有限外推证据。H3开展实质考试；受约束机制创造继续探索；H4在机制前提成立时进入。

单体/Adapter/专家池、全量belief state、任意中间态恢复、复杂研究模型及全面结构演化保留为条件分支。出现真实遗忘、路由、观测、反事实或表达瓶颈后再扩展，不能把平台规模当作进度。

## 7. 状态维护和下一终端交接

本计划给出实施安排，不覆盖`项目文档/04`的当前运行事实。下一终端执行06后，应在里程碑更新 owning 状态与证据，保留本计划的原始安排；若用户或新证据改变目标，明确记录变化。

新终端交付应逐项说明N0—N6的实现、检查与动态证据、实际资源、受阻部分、清理及中期第一任务。代码完成、动态验收和科学结论分别判断，不用“本轮收尾”代替未完成目标。
