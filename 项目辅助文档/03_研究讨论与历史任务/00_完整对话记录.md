## 2. 你已经接入了什么，证据到哪里？

### 已经存在的接线有实际意义

`autoloop_bridge.py` 已做事件身份与来源校验、重复消费检查、回答卡片绑定，以及向 core 的 `event / reconcile / advance` 转换。`protocol10_coordinator.py` 则负责操作意图、原操作核对、一次触发至多推进一个操作，以及暂停、终态和提交不确定性的处理。[桥接实现](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/autoloop_bridge.py)；[`Coordinator.advance`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/protocol10_coordinator.py#L356)。

这里最有价值的选择是：**外部触发器负责叫醒系统，core 保留实际业务状态与派发权威。** 因而重复消息、服务重启或 Agent 忘记上下文，不应自然变成第二次物理执行。

但上游采用的是至少一次交付语义，不能由此推出整个机器人系统“恰好执行一次”。机器人端仍要依靠稳定操作身份、执行回执、费用结算和不确定提交核对。

### 已有验证主要证明工程连通性

`OFFLINE_CHECKS` §29 报告过真实 Autoloop 服务、command adapter、文件 RPC、受限 host、CLI 和隔离 CPU Runtime 的端到端检查，包括重复事件、重启和回答续程；其中模型与机器人执行边界使用替身。

同节的生产入口记录则是**真实生产状态查询**：Runtime/Research 均为零，`allow_advance=false`，之后服务结束。因此：

- 支持“外部事件到 core 的受限接线做过端到端检查”。
- 支持“重复与恢复分支有离线验证记录”。
- **尚不支持“Autoloop 已无人值守地完成真实 GPU 研究与多轮继承”。**
- completion11 的闭环成果，也不能自动归因于 Autoloop。[检查记录 §29](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/OFFLINE_CHECKS.md)。

其有效性目前应评价为：**有工程理由，也有局部验证；尚无量化的研究效率或人工介入减少证据。**

## 3. 当前缺口具体在哪里？

### 第一，已有“推进一个操作”，还缺新研究任务的通用“下一步选择”

`protocol10_backend.py::observe` 对应特定协议的阶段次序。较新的 `TaskCompletionBackend` 有注册操作、`execute` 和 `reconcile`，但文件明确由 operator 持有注册序列；在这条调用链上，我没有看到通用的“消费结果、选择后续操作、持续推进”的对应消费者。[protocol10 backend](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/protocol10_backend.py)；[task_completion.py](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/task_completion.py)。

因此，仅把 `allow_advance` 改成 `true`，不足以得到新任务的持续研究闭环。

### 第二，定时与事件能力尚未完整映射到业务续程

当前桥接的 `render()` 主要输出 `ask`，没有把完成事件、下一次资源复查等系统性地表达为 `events / later`。同时，多类 `waiting` 会被组织成提问卡片。[`render` 与等待处理](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/autoloop_bridge.py#L169)。

未来启用通知时，需要区分：

- 等 GPU、等待已提交作业完成：程序探测。
- 不确定请求是否已执行：核对原请求。
- 缺少研究证据：由研究策略选择合法补证。
- 需要扩大范围、突破预算或恢复人工暂停：保留相应人工边界。

另外，现有 `_signal` 会精确验证已注册事件。增加 `later/events` 时，必须一起接通事件登记和身份映射，不能只修改回执文本。

### 第三，Research 当前是受限的一次请求消费者

实际 SDK 入口 `bounded_runner.child` 使用提供的证据完成一次结构化请求，并明确禁止模型直接读文件、调用工具、联网或启动实验。host 可以补读开发证据，再准备另一条有独立预算与身份的请求；这还不等同于模型具有交互式研究工具循环。[实际 SDK 入口](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/bounded_runner.py#L123)。

这并不妨碍先建立自主研究：**host 串联多个受限请求，也可以形成闭环。** 关键是下一次请求应由前次结果决定，而非人工重新整理全部输入和指定下一步。

### 第四，发布与继承需要进入自动续程路径

现有独立评价、升级桥和实际继承已经提供基础。剩余工作是把：

> 候选结果 → 是否具有部署资格 → 是否激活 → 下一任务实际绑定哪个版本

接到统一作业状态里。比较 Gate 接受后仍可能拒绝部署，relations12 就是实际例子。新任务必须通过正式 active/deployment 入口取版本，才能证明继承；手动把候选 bundle 填进一次测试，只证明候选可运行。

## 4. 分工建议：让“决定什么时候运行”和“决定研究什么”各得其所

| 角色 | 应承担的职责 |
|---|---|
| 确定性调度与 host | 状态机、时间与事件、资源探测、预算和权限核验、原操作核对、稳定身份、费用与停止 |
| 执行 Agent | 在当前任务内理解目标、选择技能、观察、交接、恢复；可以选择让 VLA 连续完成任务 |
| Research Agent／ψ | 提出竞争解释，选择区分实验和更新对象，预测结果，判断研究分支是否值得继续 |
| 独立验收与发布 | 消费固定协议和真实结果，判定有效性、旧能力、候选资格、激活与回滚 |
| Autoloop | 持久接收事件、定时唤醒、调用受限命令、展示需处理事项 |

这些角色可以由少量进程和明确接口实现。独立验收优先使用确定性规则和环境原生判据，并不需要再增加一个负责“相信或不相信研究结果”的 LLM。

三层循环中的时间尺度也应不同：

- **任务循环**仍由 RPent/VLA 执行，Autoloop 不参与动作 chunk 的实时监督。
- **系统更新循环**由任务完成、有效证据、资源就绪、评价结束等事件推进。
- **元改进循环**由研究历史和独立考试触发；新 ψ 在研究作业边界启用，在途作业继续绑定原策略。

## 5. 还应借鉴什么，哪些部分需要改造？

**适合直接复用**的是事实日志、确定性内核、稳定事项标识、结构化回执、到期表、command worker 和恢复机制。

**需要机器人化改造**的主要是：

1. **副作用语义**：模型请求、机器人动作、训练启动都可能在响应丢失时已经发生；租约过期不能直接成为重做理由。
2. **资源等待**：等待 GPU 使用命令探测，探测本身记录时间与资源成本；条件就绪后再启动昂贵研究。
3. **版本切换**：模型与执行规则在任务边界切换，研究策略在研究作业边界切换。
4. **业务失败分类**：原生任务失败、候选拒绝、技术错误和研究停滞分别进入不同分支。
5. **长期循环边界**：上游的因果链深度限制用于阻止事件自激，不能冒充科学预算，也不宜通过不断重置深度来绕开；跨阶段应使用明确的新业务事件并继续受 core 总账约束。

**不宜照搬**的是通用失败自动重试、把 GitHub 交付成功等同于模型可部署、让长会话承担权威状态，以及每遇到等待就询问用户。

还应保留一个强竞争方案：**薄的 core 事件守护程序**。如果近期只有单机、少量作业、少数事件来源，它可能比完整 Autoloop 更容易维护。两者应共用同一个 core 状态机，比较恢复正确性、人工命令次数和维护负担。调度平台的选择本身不必承担论文创新。

## 6. 从现状出发的最小执行方案

以下适用于后续合法的新执行范围，不意味着恢复已经关闭或人工暂停的历史任务。

| 阶段 | 最小改动和产出 | 验收条件 |
|---|---|---|
| A. 接通结果到下一阶段 | 在现有 TaskCompletion 外增加阶段选择适配器；保存完成事件及待发送记录；区分各种等待 | 重复事件、服务重启、丢回执、资源不足不会产生重复派发或重复结算；暂停保持有效 |
| B. 接通真实研究分支 | 复用受限 Research 请求和已有算子，让前次结果选择下一次补证、实验、候选或结束 | 至少存在两个合法后继，且真实结果改变选择；不是预写好的单一路径 |
| C. 接通验收与继承 | 评价结果自动进入资格判断，成功激活后由正式入口启动下一任务 | 接受、拒绝、未决都能闭合；继承绑定和任务成功分别验收 |
| D. 接通研究策略更新 | 记录决策历史，加载独立 ψ 快照，安排新问题考试 | 证明实际后续研究行为改变，再判断是否有收益 |

阶段 A 先用 CPU 替身和故障注入验证，成本较低。阶段 B 只需一条受限真实研究链，不必同时开展多个长周期任务。

处理异常的原则应具体到行动：

- **资源等待**：低成本探测，不反复调用 Research。
- **技术故障**：先核对原请求和副作用，再按既定恢复规则处理。
- **有效任务失败或候选拒绝**：作为研究反馈；不按网络故障重试。
- **研究停滞**：改变实验或假设，必要时结束当前分支。
- **人工暂停、期限或预算边界**：停止新派发，并按原规则闭合在途工作。

这一阶段应首先报告**每条研究链所需人工操作次数、恢复正确率、等待开销、未闭合请求数**。这些指标可以验证 Autoloop 的运行价值；机器人性能提升则需要后面的研究对照。

## 2. 与当前项目条件存在几项实质差异

第一，当前先导是 `base_salad`、`position_swap_salad`、`old_milk`、`old_drawer` 四个任务条件，其中前两个还共享任务目标；它们不能代表四十个任务，更不能当作四个独立任务族。

第二，所读 protocol10 配置使用 `libero_type=pro`，还加载公开上游任务记忆。`06` 已提示，这类记忆可能包含相关任务配方。**新 seed 可以检验新初态，但不自动意味着任务知识未见。** [06 先导协议](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/06_首批任务先导协议.md)。

第三，控制参数需要区分清楚：

- 模型 action horizon 为 10。
- 每次实际执行前缀为 5 个动作。
- flow 推理步数为 5。
- 一次 `vla_execute` 可以连续执行 1—24 个预测 chunk。
- 每次 VLA 预测读取最新观察；Planner 通常在整段返回后再决策。

因此，24 chunk 可对应至多 120 个动作，但不能解释为一次盲目的 120 步开环控制；也不能认为 Planner 每 5 步都监督了一次。[`vla_execute`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/tools.py#L422)。

第四，配置记录的加载器是安装版 RLinf 0.4.0 与 `rpent-openpi` 0.2.2。仓库有安装来源记录，但没有实际 `.venv`；同级 `RLinf/`、`openpi/` 源码不能直接代替这些安装版本，更不能代替历史运行快照。[运行依赖记录](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/config/runtime_observed_v1.json)。

还有一个更直接的问题：**在我核对的标准 Runtime 路径上，尚未看到独立的纯 VLA 正式执行入口。** Runtime 通过 RPent Planner 启动；`relation_skill_start` 也是给 Planner 的指令，要求先调用指定技能，然后继续观察、恢复或停止。因此，new14 文档中的“VLA 控制臂”，在未读取其冻结配置和轨迹前，不能认定为无 LLM 的纯 VLA。[Runtime 启动](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/runtime.py#L138)；[技能比较输入](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/task_input.py#L187)。

## 3. 熟悉任务：应检验净收益，而不只统计救回多少次

可以用一个简单模型说明误干预的代价。设：

- \(p\)：直接 VLA 的成功率。
- \(r\)：原本会失败的任务中，被 Agent 救回的比例。
- \(h\)：原本会成功的任务中，被 Agent 干预破坏的比例。

则成功率变化为：

\[
\Delta p=(1-p)r-ph.
\]

以 \(p=0.953\) 作示意，需要 \(r/h>20.3\) 才有正收益。即使救回一半原有失败，只要破坏约 2.47% 原本成功的任务，成功率收益就会被抵消。这里是推导示例，不是已测到的项目参数；计算与时间成本还会进一步提高引入 Agent 的门槛。

因此，我建议熟悉任务采用这样的默认定位：

> **让 VLA 获得足够连续执行空间；在有证据表明目标、状态或进展存在问题时，再引入监督与恢复。**

可能有收益的机制包括目标重定向、识别未完成状态、局部恢复、补充观察、调整起态、调用更合适的工具。但每种机制都有对应的简单竞争解释：

- 多给几次尝试是否已经足够？
- 固定“停滞后重观察”的规则是否同样有效？
- 收益是否来自新增工具或更好的几何信息？
- 静态程序是否已经能实现同样的分阶段执行？
- Agent 是否只是弥补了较弱的 VLA 推理配置？

**“Agent 调用之后任务成功”不能单独证明该干预有益。** 需要比较整个干预策略与对照策略；当前若没有可靠的任意状态克隆与恢复能力，不应声称得到了同一中间状态的严格反事实。

## 4. 条件泛化：Agent 能修复哪类能力下降？

建议按瓶颈划分，而不要把所有扰动统称为泛化：

| 变化或失败机制 | Agent 可能的贡献 | 需要保留的上限 |
|---|---|---|
| 目标指代、任务语义、目标位置变化 | 重新定位对象、改写局部目标、调用现有工具 | 需先确认目标理解确实是瓶颈 |
| 当前信息不足或状态过时 | 补充可用观察、核对历史事实与当前状态 | 尚未实现的视角或传感器不能算已有能力 |
| 局部技能能做，但起态不合适 | 利用现有运动工具调整起态，再调用 VLA | 调整过程本身必须可靠，不能引入新的控制盲区 |
| 新接触方式、明显不同动力学或动作能力缺口 | 诊断、选择数据与更新路径 | 语言规划通常不能替代缺失的动作能力 |
| 多因素混合变化 | 先选择区分实验，确定主要瓶颈 | 不能一次同时改提示、工具和 θ 后宣称机制已明确 |

同一种“新物体”可能分别属于语义、视觉、几何或接触动力学问题。Agent 能否缓解下降，要看它是否拥有有效的信息通道或可执行替代手段。第二轮问题 5 会进一步核对这些通道是否真实可用。

## 5. 任务迁移：重点区分组合能力和底层技能缺口

Agent 有机会将已有局部能力组成新任务，例如改变操作顺序、增加中间检查、使用外部工具完成原 VLA 不承担的环节。这可以形成真实的**组合系统能力扩展**。

但至少应区分三类“新”：

1. **新初态**：任务与技能已知。
2. **新组合或新目标关系**：基本技能已知，但组合方式未见。
3. **新的底层动作能力**：现有执行器不能可靠实现关键接触或控制过程。

前两类很适合研究 Agent；第三类往往需要 θ 更新、新技能或新的执行工具。是否处于 checkpoint 训练范围之外，应依据实际训练任务清单确认，不能只依据测试名称或 seed。

这里还需要一个强基线：**学习后冻结的程序**。ASPIRE v2 在 LIBERO-Pro 上用 seeds 51—65 学习，再将每个任务的一份生成程序用于 seeds 1—50 的评价。这提示，在线逐段推理应与经过充分开发的固定程序比较，而非只与裸 VLA 比较。[arxiv.org](https://arxiv.org/html/2607.00272v2?utm_source=chatgpt.com)

若固定程序能达到相近能力且成本更低，可以让 Agent 在开发与异常处理阶段发挥作用，把稳定执行交给程序。这仍然保留了完整系统目标。

## 6. 学习效率与其它作用：即使 Runtime Agent 收益小，Research Agent 仍可能重要

Agent 的研究价值可能体现在：

- 把失败分解为有区分力的解释。
- 选择能够排除错误解释的实验。
- 识别哪些数据值得采集、哪些轨迹只能用于诊断。
- 选择更新 φ、θ 或协作关系。
- 预测收益、成本和旧能力风险。
- 将成功修复整理为可复用策略。

这些价值要通过**达到相同独立能力所需的交互、计算和人工成本**来验证。当前真实训练往返尚未完成，因此暂时只能先检验规则、关系和数据选择环节，不能声称已经减少了 VLA 训练样本需求。

相关机制也已有近邻。EmbodiedRSI v2 使用假设图、实验价值选择、代码与技能更新，以及根据下游收益训练的记忆管理器；其机器人基础模型在演化试验中保持冻结。因此，“物理反馈驱动外围改进”与“实验选择提高效率”本身已不足以建立新颖性，后续需要比较具体机制和控制条件。[arxiv.org](https://arxiv.org/html/2610.10498v2?utm_source=chatgpt.com)

其它可验证作用包括长时序依赖管理、外部知识和工具调用、必要的人机澄清、异常解释，以及覆盖纯 VLA 输入接口无法表达的任务。相应指标应是任务覆盖、约束违反、澄清次数、完成成本和人工时间，而不是推理文本长度。

## 7. 一个近期可做、能改变决定的四臂先导

首先补一个薄的确定性直接执行入口，复用现有 VLA client、processor、动作执行、原生终止与账本，不另造模型栈。

| 组别 | 执行方式 |
|---|---|
| D：直接 VLA | 全任务原始目标，连续根据当前观察执行，无在线 LLM 规划 |
| S：固定计划 | 开发阶段冻结的技能顺序与程序；允许当前观察定位和底层闭环 |
| R：简单监督 | S 加预定的停滞、重观察、重试或恢复规则 |
| A：动态 Agent | 使用相同可用工具与信息，根据反馈决定后续行动 |

一个与当前规模相称的起点是：

**4 个已有任务条件 × 3 个新登记初态 × 4 组 = 48 个 episode。**

它能检查基线是否成立、发现大的条件差异，并估计后续实验需要多少样本。每组只有 12 次，单个 episode 就改变 8.3 个百分点，**不能用它检验 95% 附近的小提升，也不能把未见差异当作等效。**

控制重点是：

- 同一 θ、处理器、动作时序、flow 步数和终止规则。
- 同一初态分配、总环境步数及重置预算。
- S、R 得到合理开发和调参，开发成本另计。
- A、S、R 拥有相同的**可用**信息与工具；主动观察是研究对象时，不强迫实际观察轨迹完全一致。
- D 对 A 测组合系统总价值；S/R 对 A 更接近测动态编排价值。
- 如收益仅来自额外工具或观察，再做针对性的接口消融。

主要报告原生成功、有效失败、技术无效、unknown，以及环境交互、模型请求、时间和人工成本。所有已分配试验保留，技术可靠性与有效任务表现分别报告。

结果会直接改变路线：

- D 已稳定够用，A 没有实际净收益：熟悉任务优先直接执行。
- R 与 A 相当：优先使用简单监督，把 Agent 留给异常与研究。
- A 只在位置或语义扰动上有优势：聚焦 grounding、起态调整或交接机制。
- A 的优势来自额外工具：贡献首先归到接口能力，继续验证动态推理是否必要。
- A 能组合已有技能，但持续卡在同类接触：将研究重点交给问题 4 的 θ 更新与内化。
- A 只靠更多重试获益：与同预算重试基线比较后再判断价值。

项目评价最终应分开四层：**组合系统能力、冻结 θ 下的编排能力、去掉 Agent 后的裸 VLA 能力、固定起点下的研究能力。** 一个层面的提升不能替代另一个。

# 四、问题 3：如何实现并证明“改进改进机器人的方法”？

## 1. 三种进步需要三种不同证据

| 观察到的变化 | 能支持的主张 |
|---|---|
| 同一任务中，Agent 发现失败后恢复成功 | 任务执行能力 |
| 自动修改提示词、技能或模型，经独立评价后后续任务更好 | 系统版本改进 |
| 后期研究策略在新改进问题上，以相同考试条件得到更大收益或更低成本 | 元改进 |

自动做实验、存记忆、改代码，都是可能的实现手段；它们不单独决定属于哪个层级。

例如，修改“如何抓取”的提示词通常属于执行策略变化；修改“怎样区分感知错误和动作能力缺口”的研究程序，可以属于 ψ。**归属取决于它控制的行为，而非文件格式，也不要求必须训练 LLM 权重。**

仓库 `03` §6 已经提出相当正确的 H3 验收原则：共同起点、可比较记忆、新问题、同预算、独立历史，以及固定 ψ 加晚期记忆的对照。当前重点应是把这些原则接到可执行快照和真实问题集上。[H3 验收协议](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/03_实验设计与验收协议.md#L134)。

## 2. 当前 ψ 与 ρC：已有学习部件，但奖励含义需要调整

### 当前静态实现支持的准确结论

初始化的 ψ 仍是 `fixed / initial / learned:false`，策略是检查合法证据、受限实验、提交或延后。我没有在所核对调用链中看到完整的独立 ψ 学习与新问题考试消费者。[初始化代码](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/__main__.py#L52)。

与此同时，ρC 已有实际学习和使用路径：

1. 从已加载的开发试验读取 `screening_checks`。
2. 对有效任务分配，使用这些检查全部为真的结果作为 0/1 反馈。
3. 以 `task_key` 为状态，记录 `bounded_experiment` 的经验收益。
4. 消费者在经验均值不高于 0.5 时，可以选择 `defer`。
5. 该准入既影响候选准备，也接到了实际开发派发前。

相关实现见 [`learn_relations`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/relation_learning.py#L177)、[`fixed_research_step`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/cooperation.py#L24)、[实际派发消费](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/task_completion.py#L569)。

所以，不能因为 `psi_ref` 没变就说研究行为完全没变。按照项目定义，ρC 可以是有效 ψ 的组成部分。准确判断是：

> **当前存在狭义的、基于开发筛选反馈的研究准入学习；尚未证明研究策略在未见问题上的改进能力。**

### 我对当前反馈的主要质疑

`screening_checks` 包含原生成功、技术有效、干预加载、关键进展和采集完整性。这是一组试验筛选信号，与“这次研究是否值得做”并不等价。[筛选来源](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/research_cycle.py#L225)。

可能出现两个问题：

- 一个技术有效但候选失败的试验，可能排除了重要竞争解释，具有研究价值。
- 同一任务上的不同假设、算子和模型版本，被压到一个任务级收益统计中，可能相互遮蔽。

按当前规则，一个失败反馈就可能使该状态的经验均值落到延后区间。这有可能阻止下一种更合适的实验，也可能形成对容易通过筛选的修改的偏好。

最强的竞争解释是：**这种保守门控确实能节省无效试验。** 我不认为应该凭直觉删除它。应比较“节省了多少浪费”和“错过了多少有效改进机会”，在同预算下决定。

## 3. ψ 应学习什么？先选能真实改变研究行为的部分

我建议把 ψ 表示为一个带版本的决策程序或参数化策略：

\[
(\text{证据、系统版本、竞争假设、历史、剩余预算})
\rightarrow
(\text{下一项取证或更新、区别预测、成本估计、停止条件}).
\]

其中，ρC 负责更新对象、方法、顺序和预算等选择；ψ 还可包含诊断、假设生成、证据需求、收益校准及停滞处理。共享部分保留唯一版本引用，避免同一次变化同时被算成“ρC 创新”和“ψ 创新”。

近期可以只学习两项，其他部分固定：

1. **选择最有区分力的下一次实验。**
2. **根据诊断和历史选择更新对象或算子。**

这比同时开放所有代码与组织结构，更容易知道究竟学到了什么，也不会取消后续开放式探索。

### 一个可实施的第一版机制

沿现有关系学习存储扩展即可，未必需要新的大模型训练器：

- 状态从单纯任务名扩展为“失败证据类别 × 候选算子 × 适用版本 × 数据条件”。
- 分开记录资格、技术有效性、独立性能收益、旧能力代价和资源成本。
- 为少样本估计保留不确定性；一次失败不自动代表该任务所有研究方向都无价值。
- 保留有界探索预算，比较未尝试的合法方案。
- 对诊断性失败，依据预先记录的竞争预测与实际观测评估其区分作用，避免让模型自行打“信息量很高”的分数。
- 将新策略真正接入请求构建、实验选择或派发消费者，而不只保存一份总结。

反馈学习可以先用小型经验模型、规则参数搜索或上下文选择策略。是否采用更复杂算法，应由简单方案是否足够决定。

如果有限算子确实成为瓶颈，再允许 ψ 提交新的诊断或候选生成程序，在隔离开发环境中接受检查和考试。**治理规则与独立评价口径应继续留在其可修改范围之外。** 这样才为开放式机制创造保留了实际入口。

## 4. 相关工作已经把元策略问题推进到哪里？

这里需要提高新颖性门槛。

**Hyperagents v2** 将任务 Agent 与修改 Agent 的元程序共同纳入可编辑对象，并通过跨域迁移及任务组件／元组件分离来分析收益来源。其机器人部分是 Genesis 中的四足机器人奖励设计，不是 VLA 持续更新；论文也明确没有证明无限或自加速改进。它说明“元程序可修改”和“元能力可迁移”已有直接近邻。[arxiv.org](https://arxiv.org/pdf/2603.19461v2?utm_source=chatgpt.com)

**EvoX v2** 将搜索策略本身作为演化对象，根据一段搜索过程的进展决定策略更新。它可作为停滞监测和研究方法调整的机制参考；机器人场景还需处理物理成本、不可重放状态及执行器版本变化。[arxiv.org](https://arxiv.org/html/2602.23413v2?utm_source=chatgpt.com)

**GEPA** 提供基于反馈的提示词演化和 Pareto 候选选择，是合理的固定优化器基线。用固定 GEPA 得到更好的执行提示词，首先证明优化有效；若要证明元改进，仍需检验优化策略自身的变化。[arxiv.org](https://arxiv.org/html/2507.19457v2?utm_source=chatgpt.com)

因此，本项目更值得验证的具体问题是：

> 面对带有部分观测、物理试验成本和版本依赖的机器人失败，后期研究策略能否更早选中有效的诊断与更新路径，并把这种优势迁移到新问题？

这是本轮提出的候选问题，尚不是论文主线定案。

## 5. 元改进考试怎样排除“只是经验更多”？

### 先固定每一道“改进问题”的定义

每个问题至少包含：

- 被改进系统的共同起点。
- 合法初始证据和可用工具。
- 允许的更新范围。
- 物理、计算及其它预算。
- 开发反馈与独立考试分界。
- 固定评分和旧能力要求。

仅换 seed 不足以构成新的改进问题。更有力的是未见故障机制、任务族，或已有机制的新组合。

可用下面的量表达研究能力：

\[
M_B(\psi)=
\mathbb{E}_{q}\!\left[
J_q\!\left(\hat S_B(\psi;q,S_q^0,M_q)\right)-J_q(S_q^0)
\right].
\]

其中，\(\hat S_B\) 是策略在预算内依据合法开发信息选出的最终系统；没有产生合格更新时保留起点。最终考试只评分，不帮助挑选候选或 ψ 快照。

### 策略与记忆至少需要这样的比较

| 比较 | 主要回答什么 |
|---|---|
| 早期 ψ + 早期记忆，对比晚期 ψ + 晚期记忆 | 整体历史积累是否有用 |
| 早期 ψ + 相同合法晚期记忆，对比晚期 ψ + 相同记忆 | 收益是否超出“只是知道得更多” |
| 兼容时做策略与记忆交叉 | 是否存在强耦合 |
| 固定研究策略／固定优化器 + 相同证据与预算 | 是否优于普通搜索或调参 |

有四点尤其容易做错。

**第一，不要求早晚策略拥有相同的训练历史。** 学习本来就需要历史。应匹配考试条件，并另外报告产生晚期 ψ 的开发成本。

**第二，共同记忆是相同可访问事实库，不必是相同的实际检索结果。** 如果 ψ 学习的是选证据，强迫两者看到完全相同的最终上下文，会删除被测机制。可以另做 common-data 消融与允许主动取证的总效应实验。

**第三，记忆中若包含可执行诊断规则，它可能属于 ψ。** 应先划分事实与策略内容。若两代表示不兼容，允许比较“策略＋记忆联合系统”，但不能声称已完全隔离策略贡献。

**第四，ρC 若属于 ψ，就应随快照变化。** 一边比较 ψ，一边固定其核心决策子模块，会使考试失去意义。

### 还必须控制哪些替代解释？

考试应固定初始 θ、φ、工具、非被测执行配置、Agent 模型与设置，并控制任务顺序和服务版本变化。所有尝试都计入成本，不能只保留最终成功候选。

主要指标包括：

- 同预算的独立终点收益。
- 改进收益随物理成本变化的曲线。
- 达到目标能力所需成本。
- 错误修复、旧能力损失、拒绝与未完成。
- 研究策略的开发成本及其可能的长期摊销。

独立重复单位应是**改进问题或演化历史**。一条历史中有很多 episode，并不等于很多次独立元改进证据。策略“从不更新”也不能只凭没有错误发布而胜出。

## 6. 当前应先做什么规模的实验？

现在最适合先完成两步。

**第一步：审查 ρC 的决策含义。** 用已有合法开发记录回放固定准入、当前学习准入和一个区分上下文的简单方案，查看哪些情况下会作出不同选择。回放可以揭示分歧，但无法告诉我们未执行分支的真实收益；那些分歧才是后续实际试验的候选。

**第二步：在形成真实早晚策略快照后，进行小型元考试。** 例如选择 3 个未见改进问题，比较早期 ψ、晚期 ψ、一个充分调试的固定研究基线，统一合法记忆，每题最多 2 次开发运行。这样最多是 18 次开发运行，**独立评价和旧能力检查成本必须另列**。

这只适合验证考试链、发现大差异、估计方差。正式 H3 仍需要更多问题和独立演化历史。

首个考试可以限定于当前可执行的 φ／ρ 更新。若成功，结论应限定为该范围内的研究策略改进；随后仍需真实 θ 更新、版本变化或新的机器人问题来支撑完整项目目标。当前 H3 的状态应是**尚未检验**，不能写成已经成立，也不能写成已被否定。

## 7. 长期停滞时，系统应改变什么？

建议把停滞分成五种：

| 停滞类型 | 合理的下一步 |
|---|---|
| 资源或技术停滞 | 等待、修复、核对原请求；不当作科学失败 |
| 证据停滞 | 选择更有区分力的观察或诊断试验 |
| 候选停滞 | 更换假设、算子或更新对象 |
| 能力停滞 | 取得合格数据，验证 θ 更新或新执行技能 |
| 方法停滞 | 改变诊断、实验选择或预算策略，并进行新问题考试 |

重复候选应按**实际干预对象、预期机制、适用版本和区别预测**识别，不能只看文字相似度。负面知识也应带条件：某方案在旧 θ 上失败，不等于更新 θ 后永远不值得再试。

停滞窗口应按有效研究尝试和已消耗预算定义。GPU 等了一晚，不应被解释为研究方法无效。反过来，连续生成不同措辞、相同机制的候选，也不应算持续探索。

当没有可解释的净价值时，结束当前分支是合理研究决策。新形成的“何时换路”策略，仍须在未参与形成它的机器人问题上接受考试。

## 四、更新对象：怎样判断该改 Agent、VLA，还是二者的协作关系？

### 4.1 当前偏向规则和提示，首先是可执行路径不对称

从最新状态看，completion11 的 φ 候选已被接受、升级并实际继承加载；relations12 的三 ρ 候选通过了比较 Gate，但因绝对旧能力门槛未满足，没有发布。与此同时，5B 的自主数据仍是 `not_admitted`，没有完成 θ 训练与能力评价往返。这里的运行结果是**仓库文档对历史实验的报告**，我没有取得对应原始产物重新计算。[当前状态：04 §1.17](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/04_实施路线与待决事项.md#L43)

源码揭示了更直接的原因：

- Research 当前可选响应主要是 `prepare_rule_trial`、`defer`，按配置加入 `propose_goal`。
- 有限规则算子覆盖任务提示、交接提示、完成条件、调用预留和 chunk 设置等。
- 当前候选提交明确标记 `theta_frozen=True`。
- θ 的准备、训练和加载由独立脚本承担，尚未成为 Research／TaskCompletion 中一个完整的生产调度动作。

因此，**现在不能从“系统主要改了 φ／ρ”推出“它经过比较后发现改 φ／ρ 更划算”。** 它还没有对称地获得这些选择。[Research 动作集合](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/research_tools.py#L1048)、[候选提交](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/research_tools.py#L649)、[规则更新](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/rule_updates.py)

我建议先让各种更新提案使用共同的描述结构：**要改变什么、竞争解释是什么、需要什么证据、最低数据资格、预估成本、什么结果支持它、由哪个真实消费者执行。**

其中 θ 路径暂时不可用时，应记录为“缺数据／配方／资源”，而不是“已判断无收益”。否则，ρC 或 ψ 学到的可能只是现有工具菜单的偏好。

### 4.2 不要把失败名称直接映射成更新对象

“没抓起来”“放错了”“抽屉没打开”都是结果描述，不能直接决定该改哪里。一次失败可能同时涉及目标理解、可观测性、起态、动作能力和交接。

更有用的是让每个诊断对应一个**能改变下一步选择的干预**：

| 竞争解释 | 最小区分实验 | 结果主要支持什么 |
|---|---|---|
| 指令与执行者能力的表达不匹配 | 固定 θ、起态、动作额度，只改变任务表述 | 静态调用修复或 φ 更新 |
| Agent 不知道关键状态发生了变化 | 增加合法的新观测或明确的状态证据，保持执行工具相同 | 优先补信息接口或状态维护 |
| 后继技能被放在不适合的起态 | 固定后继技能，比较标准起态和实际交接起态 | 改交接，或采集真实交接分布的数据 |
| 在适用起态、正确目标下仍动作不可靠 | 重复验证后，比较针对性示范与 θ 更新 | 支持执行者学习路径 |
| 实际完成了，但监督或收口错误 | 用独立局部判据和原生整任务判据复核 | 改完成判断与监督协议 |
| 技术故障或 processor／动作语义不一致 | 修复技术链并重新建立有效基线 | 暂不进入机器人能力归因 |

这张表有两个限制。

第一，**某个修复有效，不意味着其他解释已经被排除**。补观察之后成功，可能是因为选对了工具，也可能是因为增加了时间或重试。后续仍要匹配这些资源。

第二，φ 与 ρ 的文件归属不一定对应不同机制。例如，在 task hint 中写“这种情况改用 `pi0_pick`”，与修改路由表，可能产生相同执行行为。科学比较应明确：

> 谁获得了什么信息，在什么时刻，选择哪个工具，传什么指令，执行多少动作？

仅比较“改了 φ 文件还是 ρ 文件”，容易把实现位置误当成科学差异。

为避免一直偏向便宜修改，我建议给 θ 路径保留一个**资格完成后可执行的探索份额**，并比较三种简单策略：

1. 先尝试外部修复，再考虑训练；
2. 固定周期或固定数据量触发训练；
3. 根据区分实验选择更新对象。

三者应使用相同的数据质量要求、独立评价和采纳规则。这样才能判断自适应选择本身是否有价值。

### 4.3 “外部修复—验证复用价值—选择性内化”值得做，但应把内化定义得严格

适合长期由 Agent 承担的，主要是用户意图解释、外部知识获取、开放任务排序、跨工具选择，以及低频但复杂的异常处理。

值得考虑写入 θ 的，则是高频、重复、能够由 VLA 当时输入识别的局部感知—动作规律，例如稳定接近、特定接触、常见漏抓恢复，以及某类反复出现的交接起态适应。

这里有一个容易忽略的前提：

**教师的修复行为必须能由学生获得的信息决定。**

如果 Agent 依靠额外相机、此前的任务历史或用户补充信息决定动作，而 VLA 只获得固定两路图像和当前指令，那么直接模仿可能遇到信息不足。此时应该比较补充执行者输入、加入必要历史，或者保留外部判断，而不能把训练失败直接归结为 θ 的容量不足。

我建议采用以下过程：

1. **先确认外部修复可重复有效。** 在独立初态上测介入频率、恢复成本和失效边界。
2. **判断是否值得内化。** 看未来任务流中出现的频率、覆盖的任务族，以及长期节省的调用与物理成本。
3. **取得合格监督。** 重点覆盖实际会访问的失败附近和交接起态。
4. **减少或关闭该外部补救后评价新 θ。**
5. **重新校准编排。** 新 θ 已会的部分，旧规避策略可能变得多余，甚至妨碍它发挥。

**只有移除相应补救后，执行者仍保留增益，才有充分理由把这部分收益称为内化。** 如果组合系统更强，但 Agent 调用、恢复和额外工具依赖没有减少，那仍然可以是有价值的系统增强，只是证据支持的主张不同。

是否值得内化，也不宜只看一次成功率增量。一个简单决策依据是：未来部署节省的执行与编排成本，是否足以覆盖采集、训练、回归评价和维护成本，并满足旧能力约束。部署频率和节省幅度需要在后续任务流中校准。

#### 相关工作已经覆盖了大框架

**AdaRSI v1（2026-10-14）**已经采用先改执行框架、再通过保存状态的诊断决定子步骤训练，并比较新程序配旧权重以分离贡献。其条件是 GR00T N1.5、RoboCasa365 仿真，并能使用保存状态和开发期特权信息。因此，“按需从外部修复转向权重训练”本身不足以构成新贡献；本项目应重点检验在观测、干预和物理预算受限时，诊断是否仍能支持正确选择。[arxiv.org](https://arxiv.org/html/2610.20474v1?utm_source=chatgpt.com)

**Robo-COP v1（2026-10-06）**进一步覆盖了自主轨迹中的技能片段筛选、训练／等待决策、候选验证和更新后的记忆修订。它使用 DROID π0.5，训练与动作接口不同于本项目。其固定训练基线还同时取消了验证，因此不能把全部差距归因于“何时训练”；你的对照应保留相同验证器，单独比较触发策略。[arxiv.org](https://arxiv.org/html/2610.09228v1?utm_source=chatgpt.com)

### 4.4 θ 的当前入口适合验证兼容性，尚不适合比较学习路径优劣

当前 `pi05_training.build_recipe()` 明确限定：

- 单设备、micro/global batch 为 1；
- 最多 **3 个优化步骤**；
- 最多 **900 秒**设备与墙钟预算；
- 只更新 action expert，冻结视觉、VLM 和 token embedding；
- `is_lora=False`；
- 不复现原 fullshot 训练配方。

这是一项**真实训练兼容与资源测量试点**。用它验证“梯度确实更新—checkpoint 保存—原生加载—动作输出”很合理；用“三步后没有能力提高”否定 θ 更新不合理。[训练配方与限制](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/adapters/pi05_training.py#L81)

还需要精确区分两类 batch 证据：检查记录报告过实际安装的数据工厂读取**合成诊断导出**；最新状态中的真实自主数据诊断 batch 尚未执行。这两个事实不冲突。[OFFLINE_CHECKS 的原生 CPU consumer 记录](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/OFFLINE_CHECKS.md#L241)

后续能力试验应把 θ、归一化、图像方向、动作变换和 tokenizer 作为明确绑定的系统依赖。若训练同时重算 normalization，应报告为 θ＋processor 更新，不能把收益全部记在权重上。当前加载检查的权重 probe 和单次有限动作输出，只能排除部分保存加载问题，不能替代任务评价。[加载检查与部署交付](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/adapters/pi05_training.py#L565)

同样，仓库记录的 RLinf／rpent-openpi 安装 commit、同级源码和历史运行快照仍是三种材料。本轮读取到了声明和验证逻辑，没有读取原机器虚拟环境，不能把它们视为完全相同。[运行时依赖记录](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/config/runtime_observed_v1.json)

### 4.5 单体、Adapter、专家池：先保留选择，不急着建设池

| 方案 | 主要优势 | 必须付出的代价或主要风险 |
|---|---|---|
| 单体持续更新＋replay／正则 | 能力共享，部署简单，组合时无需选模型 | 更新干扰、遗忘、回归范围较大 |
| 共享基座＋少量 Adapter | 部分隔离更新，存储较小，容易撤销 | 插入层和路由需要验证；中间态可能不属于任何训练分布 |
| 多个完整 VLA 专家 | 旧专家可保留，训练相对独立 | 显存、存储、加载、路由与维护成本；共享学习不足 |
| 技能程序＋共享 VLA | 最接近现有结构，容易解释和复用 | 可能长期依赖昂贵外部补救 |

**保存旧 checkpoint 供回滚，不等于采用运行时专家池。** 此外，π0.5 的 action expert 是网络子模块，也不表示项目已有多个可路由技能模型。当前训练配方关闭 LoRA，运行入口使用单一 model path，不能从 `lora_rank` 字段推断 Adapter 已接通。

我建议下一阶段采用**一个在役 θ＋旧版本可回滚**完成真实学习闭环。只有当新增能力与旧能力出现可复现干扰，而且单体 replay／正则仍不能以合理成本解决时，再加入 base＋一两个 Adapter 的对照。

CLARE v2（2026-05-15）提供了“按需扩展 Adapter＋实际路由”的直接参照，但其基座约 200M、使用 DiT 与冻结编码器，实验有明确的新任务阶段和示范数据，不能把结论直接搬到本项目 π0.5。它也提醒我们：应比较有 replay 的强单体基线，并区分理想路由上限与真实路由收益。[arxiv.org](https://arxiv.org/html/2601.09512v2?utm_source=chatgpt.com)

### 4.6 θ 改变后，应保留历史事实，重新确认依赖策略的经验

当前 ρB 已检查 `theta_ref、processor_ref、phi_ref、code_ref` 的精确签名。不匹配时回到允许的 requested worker。这是已有保护，不能笼统说旧路由会无条件沿用；但回退并不等于获得新 θ 下正确的路由。[`fixed_route`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/cooperation.py#L5)、[版本字段](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/relation_learning.py#L20)

建议按依赖处理：

| 资产 | θ 更新后的处理 |
|---|---|
| 原始轨迹、历史结果 | 原样保留，绑定原版本 |
| 工具定义、静态场景规则 | 依赖未变即可沿用 |
| 技能成功率、适用起态、持续时间 | 对受影响范围重新校准 |
| 路由、交接、恢复阈值 | 保守回退后做小规模验证 |
| “不要用这个技能”等策略建议 | 标为对新版本未确认，保留出处 |
| ρA 取证偏好、ρC 更新收益统计 | 检查其是否依赖旧失败分布与旧训练配方 |
| 独立评价与硬门槛 | 保持固定 |

当前训练 bundle 提案主要替换 θ／processor，继承其他引用；尚未看到对所有这些依赖的完整再资格机制。[训练 bundle 提案所在模块](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/adapters/pi05_training.py)

这里最值得研究的竞争解释是：**所谓长期协同进化收益，是否其实只需要一次简单版本校准就能获得？** 只有复杂再学习在相同调优预算下超过简单校准，才值得增加机制。

### 4.7 近期最小实验：先诊断，再做一次能分离贡献的真实更新

我建议分两步。

**第一步：两个失败族的小型区分实验。** 每族选基线和两种最有区分力的干预，每臂先做 3 个匹配初态，共约 18 个回合；资源更紧时先做一个失败族。位置互换和抽屉可以作为入口，但不能从任务名直接认定根因。

固定 θ、底层控制参数、动作额度与判据，比较信息补充、静态重述、交接修正或替代技能中的两项。测局部目标、整任务成功、误干预和成本。当前没有验证任意中间态恢复，因而这些是匹配初态实验，不能称为同一中间态的反事实分支。

**第二步：完成训练兼容试点后，对一个有证据的薄弱技能做真正的能力更新。** 训练预算由真实数据与资源试点决定，不能继续沿用“三步试点”来评价学习效果。至少做以下 2×2，保持其他关系与资源条件一致：

|  | 原 φ | 修复后的 φ |
|---|---|---|
| 旧 θ | 原始基线 | 单独外部修复收益 |
| 新 θ | 权重在原调用方式下的收益 | 完整组合收益 |

另用统一执行程序关闭待内化的补救，测裸执行者或相关局部能力。

- 新 θ 在减少补救后仍有效：支持内化。
- 只有新 φ 有效：支持编排改善，θ 贡献未建立。
- 新 θ 裸执行有效，旧编排组合无收益：检查旧策略是否遮蔽了新能力。
- 简单校准足够：采用简单方案。
- 新技能上涨、旧技能下降：先比较 replay，再决定是否需要 Adapter。
- 三步兼容试点没有提高成功率：不作上述科学判断。

## 五、具身协作接口：Agent 是否获得了足够、及时且可操作的信息？

### 5.1 当前最重要的信息差异：Planner 能看图，Research 主要看字符串证据

我沿实际消费者核对后，得到以下边界：

| 角色 | 当前可获得的信息 | 不应据此推断的能力 |
|---|---|---|
| VLA | 当前策略图像、状态和本次指令；每个执行 chunk 后更新观测 | 自动知道 Agent 的完整历史、外部知识或独立评分真值 |
| 执行 Planner | MCP 图片附件、末端／夹爪等文本状态、工具结果、允许读取的记忆 | 自动拥有物体真值位姿、连续在线监控或完整信念状态 |
| Research Agent | `model_prompt` 中的结构化事件、文本摘要、编码证据和媒体引用 | 已经查看所选图片、理解全部物理失败细节 |
| 独立评价侧 | 原生结果，以及注册的私有局部观测和判据 | 这些信息已经合法地提供给 Planner |

Planner 的图片链是明确的：`view_env_state` 读取保存图片，放入 `ToolResult.images`，MCP 服务转换为 `type=image` 的附件。[图片工具](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/tools.py#L1643)、[MCP 图片传输](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/rpent/planner/utils/http_mcp_server.py#L57)

Research 的 bounded 路径则把 `research_transport` 生成的字符串交给 SDK，没有相应图片附件和图像读取工具。因此，`selected_media` 被消费可以证明选择及引用进入请求，不能证明视觉信息进入了模型。[Research 输入构造](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/research_transport.py)、[实际 SDK 调用](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/bounded_runner.py#L123)

**这会直接影响问题 4 的归因。** 如果 Research 未看到能区分漏抓、遮挡、滑落和交接失败的证据，那么错误更新选择首先可能是信息问题。增加推理强度未必有效。

此外，可逆编码保证内容可以还原，也不保证模型在相同预算下同样容易利用它。可用同一证据比较当前编码输入、可读结构化输入和真正媒体输入，分别检查诊断变化与成本；这是一个便宜的接口辨别实验。

### 5.2 语言子目标的粒度，应由执行分布和交接证据决定

强任务级 VLA 可能熟悉“把调料放进篮子”，却未必同样熟悉任意拆出的“移到物体左后方”“在夹爪半闭合时继续抬升”。分解改变了至少三件事：

1. 指令分布；
2. 每段调用的起始状态；
3. 后继技能面对的观测与物体关系。

BOSS 的技能组合研究直接考察了组合造成的状态分布变化，例如前一技能改变容器内容后，后一技能面对的条件与单独训练不同。其模型与本项目 π0.5 不同，因此它支持我们检验这一机制，不能直接证明当前模型必然发生同样退化。[arxiv.org](https://arxiv.org/html/2502.15679v1?utm_source=chatgpt.com)

我建议先为少数实际技能建立可检验的调用约定：

> **版本、适用起态、指令／工具、动作预算、合法完成证据、退出条件、后继可接受状态。**

其中“适用起态”应通过执行校准。例如“抓取技能适用”不能只写目标可见，还应明确目标是否已被移动、夹爪是否占用、是否存在干涉，以及哪些条件当前只能标为未知。

最小实验是比较：

- 完整任务指令；
- 自然阶段指令；
- 更细的技能指令。

在标准起态和常见交接起态上分别测局部成功、整任务成功与错误交接。如果细分只在标准起态有效，就应比较较大的自然片段和交接分布训练，而不是继续增加语言步骤。

### 5.3 需要一个可失效的任务状态表示，先不必建设完整世界模型

`TaskState` 已有关系、事件来源和判据约束，但本轮检索没有发现其进入当前 Runtime 的在线更新链；`critical_progress.py` 还明确将 bounded 路径中的 `TaskState.update` 和 completion commit 标为不适用。因此，“关键过程检查通过”不能被解释为系统已正确维护在线抓持或放稳状态。[`TaskState`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/evidence.py#L48)、[实际路径的检查范围](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/critical_progress.py#L188)

近期更合适的是一个小型任务关系表，每条事实包含：

- 成立／不成立／未知；
- 来源图像或事件；
- 采样步骤与时间；
- 适用场景和对象；
- 哪些动作会使其失效。

例如，“曾经抓起过杯子”是历史事件；“现在仍握着杯子”是可失效状态。夹爪打开、物体再次运动或证据过旧，都应触发重判。对象身份可以跨时间保留，旧位置不能无条件当作当前位置。

SimpleARM v1（2026-09-29）已有明确区分历史信息与当前几何依据的相关设计。它采用特定子目标预测器和冻结 π0.5 的组合，不能直接套用其表现，但支持把“历史可复用、当前状态需重新落地”作为接口原则。[arxiv.org](https://arxiv.org/html/2609.36595v1?utm_source=chatgpt.com)

还必须分清四种结束：

| 事件 | 合理解释 |
|---|---|
| 工具调用返回 | 一段调用结束 |
| 局部判据成立 | 某个子目标获得证据支持 |
| 原生整任务成功 | LIBERO 任务目标满足 |
| 本次尝试闭合 | 能确定本次成功、失败或仍有未知 |

当前 `vla_execute` 达到 allowance 只表示执行段结束；`pi0_pick` 的部分成功信号是末端／夹爪启发式；活跃执行中的 native false 也不是正式失败。现有结果协议对此已有区分，应在增加状态表示时保留。[工具结束语义](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/tools.py#L422)、[结果与闭合判据](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/result.py)

环境侧的私有抓取／抽屉观测可以用于评价公开状态识别器，却不应直接回流为 Planner 的免费真值。这样才能知道收益来自合法观测上的推理，还是额外状态权限。[私有技能观测](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/skill_routing.py#L108)

### 5.4 当前是“VLA 按 chunk 闭环，Planner 按执行段闭环”

这是本轮对控制时序最重要的确认。

当前基线配置是预测 horizon 10、执行前缀 5；`vla_execute` 可在一次工具调用内循环 1—24 个 chunk。因此，在没有提前终止时，一次 Planner 调用可能覆盖 **120 个环境动作**。VLA 中途会用最新观测继续预测，Planner 则通常等整个工具调用结束才获得返回。规则可以改变执行前缀，实际运行仍须绑定具体配置。[基线配置](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/config/run_profile_v9_resultfix.json)、[`_vlm_chunk` 与 `vla_execute`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/tools.py#L216)

已有取消、预算检查和原生成功锁存；但这些管理机制不等于自主语义监督。工具调度与环境 RPC 存在串行锁，正在执行的 chunk 不能被另一次普通观察调用穿透；也没有发现已接通的“语义取消当前 chunk 并交回最新状态”接口。[工具调度](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/rpent/tools/toolkit.py#L76)、[RPC 锁](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/rpent/utils/rpc/rpc_facade.py#L112)

另外，`view_env_state` 读取已保存的工具步骤；重复调用不会重新采样。在当前串行仿真中，最新保存末态可能仍是当前状态，但它没有为持续变化的物理环境提供 freshness 保证。后端已有 render 基础，增加明确的新采样观察工具是可考虑的扩展；并发采样、是否推进物理时间和移动视角的代价，需要另行验证。

因此我建议按两个时间尺度分工：

- **执行层**负责低延迟限制、原生终止、廉价进展事件和动作边界检查。
- **Agent**负责较慢的目标解释、异常判断、工具选择与恢复策略。

先在现有 chunk 边界加入可控的“事件触发交回”，比立即建设完整异步多 Agent 监督更容易辨别收益。

DynaHarness v1（2026-09-30）支持这种分工，但其 LIBERO grounding 使用模拟器状态，并提供解析控制技能。其表现不能直接当作本项目仅凭当前视觉与 VLA 接口就能取得的收益。[arxiv.org](https://arxiv.org/html/2609.40306v1?utm_source=chatgpt.com)

### 5.5 怎样区分推理、信息、时序、权限和执行者瓶颈？

建议按下面顺序做诊断，避免一次增加所有能力：

| 比较 | 保持不变 | 改变项 | 结果如何影响决定 |
|---|---|---|---|
| 当前输入 vs 更完整合法观测 | 同一模型、工具和决策节点 | 新视角、时间绑定、结构化状态 | 改善则先补观测接口 |
| 同信息下 Agent vs 可靠参考判断 | 相同可见信息 | 决策方法 | 明显差距支持研究推理或策略 |
| 相同判断，较早 vs 较晚交回 | 底层 VLA 前缀与恢复动作 | 监督时机 | 只有早交回有效，支持时序改造 |
| 相同信息与时机，有限 vs 扩展恢复工具 | Planner 和执行者 | 干预权限 | 支持补工具，不能归功于推理 |
| 相同调用方式，旧 θ vs 新 θ | 信息、时序和工具 | 执行者 | 支持底层能力解释 |

私有状态 oracle 可以作为隔离的诊断上界，但不能进入正式成绩。如果只有 oracle 有帮助，说明合法感知或 grounding 仍不足；这不能证明更强文字推理能解决问题。离线判断正确也只证明决策质量，后续仍须实际执行确认。

对于监督频率，建议保持底层执行前缀为 5，比较较长 segment、较短 segment，以及事件触发交回；在相同接口机会下比较简单规则与 Agent。再加入经过校准的不确定性触发，避免直接把 LLM 自报信心当成可靠概率。

公平性需要两种口径分别报告：

1. **相同物理动作预算**下，能力提高了多少，额外花了多少 API 和墙钟时间；
2. **相同总墙钟／API 预算**下，实际完成了多少任务。

同时固定所有成本是不现实的，不能用一句“等预算”掩盖差异。若同时把执行前缀从 5 改成 1，又增加 Agent 调用，就无法判断收益来自哪一层的反馈频率。

评价重点应是：救回、误伤、错过恢复窗口、额外成本和决策到执行的延迟。**故障检测准确，不代表干预有正收益。** RESCUE v1（2026-10-09）正是通过相同状态、相同剩余预算的继续／恢复比较研究这一问题。[arxiv.org](https://arxiv.org/html/2610.13516v1?utm_source=chatgpt.com)

当前配置把 snapshot/restore 标为未验证，π0.5 服务也没有对应完整会话恢复接口。因此，先验证仿真、随机数、策略状态和待执行动作的恢复保真，再考虑同状态分支；现阶段可用匹配初态、随机分配执行策略的回合级实验。[服务接口限制](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/rpent/robots/components/pi05_vla_server.py#L183)

**改变我当前建议的证据很明确：** 如果短段规则监督已解决主要问题，就采用它；如果增加反馈只有成本，就保留长段；只有动态 Agent 在相同信息、工具和时机下仍有额外收益，才支持进一步投入复杂语义监督。

## 六、主动能力成长：没有明显失败时，系统该研究什么？

### 6.1 当前 `goal_value` 是有用的规格筛查，还不是能力价值估计

你明确要求在没有明显失败时继续研究，并在指定领域内发现新需求。代码确实保留了这个目标：即使当前 J 已满，效率、鲁棒性、新能力等分支仍可开放。这是已有分支消费者，不应说全部停留在设计。[研究分支策略](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/task_policy.py#L64)

但需要明确 `evaluate_goal_value()` 的分数含义。它主要检查：

- 目标是否为受支持、符号一致的 BDDL 组合；
- 场景和对象是否符合范围；
- 是否不同于当前协议的原目标；
- 公开 catalog 中是否有完整、类型和共享对象关系一致的功能目标；
- 指定 primitive 名称是否存在。

其输出明确保留：

- 物理可行性未测；
- 能力增益未知；
- 任务成功未知；
- 不具备发布资格。

所以 **`domain_functional_value=1` 表示有独立功能规格见证，不表示价值、可行性、成功率或预期学习收益等于 1。** 这比任意文本自评分可靠，但还不是用途价值学习器。[`evaluate_goal_value`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/goal_value.py#L281)

当前独立评价消费者能生成 measurement 与 review；不过 `propose_goal` 不能携带开发执行槽，审查确认后仍要求新实验协议，尚未找到把确认结果转成目标排序、新协议和 Runtime 派发的完整生产链。[独立价值审查消费者](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/task_completion.py#L462)、[机会准入](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/task_policy.py#L235)

这层隔离应该保留。新增目标必须与环境实例化、独立成功判据和运行时终止语义一致。仅把新目标文本放进原任务，继续使用原任务 native success，会产生错误评价；仅更换末尾评分也可能被旧目标的提前终止干扰。

在你已授权的领域和预算内，未来可以由确定性模板实例化这些协议，无需每个目标重新由人挑选。但该消费者目前需要补齐。

### 6.2 “新于当前四任务”与“系统新学会”必须分开

本轮进一步读取了配置固定的公开记忆：

`RLinf/RPent-memory@47f301ef33bf8d0e8c770342f16b3c39c6a0e8c1`

其索引已有两物体入篮、接触技能、恢复与放置等经验。因此，新于当前项目任务列表的目标，可能已有公开先验支持。这不是对某个候选发生泄漏的断言，而是评价新能力时必须区分的来源。[RLinf/RPent-memory at 47f301e](https://huggingface.co/datasets/RLinf/RPent-memory/blob/47f301ef33bf8d0e8c770342f16b3c39c6a0e8c1/libero/README.md?utm_source=chatgpt.com)

同时，完整语料可用不等于整份语料进入模型。当前启动路径默认使用部分 global 摘录，其他内容按需读取，并标记为外部先验、非项目学习；历史实际读了哪些内容，还需对应 `task_input` 和读取记录。[启动输入的实际选择](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/task_input.py#L114)

建议分别标记：

- 新于当前协议；
- 新于项目开发经历；
- 新于公开程序记忆；
- 新于已知微调任务；
- **当前系统更新前不会，更新后学会。**

前几项有助于解释覆盖与先验；最后一项才直接支持能力获得。

能力表也应按条件和版本维护，而不只存“已掌握”：

| 状态 | 需要的证据 | 合理下一步 |
|---|---|---|
| 已验证适用 | 限定条件下重复成功，成本与不确定性明确 | 抽检新条件 |
| 证据不足 | 次数不足、结果 unknown 或条件未覆盖 | 最小探测 |
| 可以组合但未证实 | 子技能可能匹配，缺完整交接验证 | 验证关键组合 |
| 需要学习 | 区分实验支持执行能力缺口 | 选择数据与训练路径 |
| 当前不可实现 | 缺硬件、工具、可观测条件或预算 | 暂缓并记录解除条件 |

每条都应分别记录裸 VLA 与组合系统结果，并绑定 θ、φ、ρ、工具和起态。技术 invalid 不应计为能力失败；两次失败也不能证明绝对不可实现。现有 `experience` 查询已经保留“仅该版本观测、未建立因果、不是技能晋升”的边界，可在此之上构造能力表。[经验消费者](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/experience.py#L143)

### 6.3 没有失败时，仍有四类值得研究的机会

我建议从可核验需求中产生候选：

1. **成功但昂贵。** 反复依赖大量观察、重试或 Agent 调用，可能值得内化或简化。
2. **成功但脆弱。** 已有条件下成功，轻微视角、位置或交接变化尚未验证。
3. **有未来用途的能力缺口。** 外部任务流需要，而当前只能部分完成。
4. **研究过程效率低。** 反复产生相似候选、收益预测失准、实验无法区分解释，适合改 ψ。

这里应区分三个量：

- 学会的概率与成本；
- 实验的信息价值；
- 学会之后的实际用途价值。

最不确定的目标未必有用；最有用的目标未必当前可学；最容易成功的目标可能原来就会。

一个可实现的用途估计可以写成：

\[
\widehat V(g)
=
\sum_{t\in\mathcal T_{\mathrm{future}}}
w_t\,\widehat{\Delta U_t(g)}
-
\lambda^\top \widehat C_{\mathrm{learn}}(g).
\]

这里的任务权重来自外部规定的需求分布；增益包括成功与执行成本变化；学习成本包括物理交互、教师、人时、计算和评价。Research 可以估计这些量，但不能修改最终评分权重或私有测试任务。

“解锁更多后续任务”可以作为预测特征，却不能直接按技能图可达节点数计分。每条组合边都隐含起态和交接要求，必须用独立组合任务验证。若声称减少未来学习成本，就要测下一批任务实际需要多少数据、交互和计算。

现阶段不必先训练复杂价值模型。优先比较固定课程、失败优先、轮转／随机、实测学习进步，以及增加后续用途预测的方法。没有失败时，失败优先基线也应有预定义 fallback，不能让它原地停住形成弱对照。

SAGG-RIAC 的一手研究早已使用实测能力进步选择参数化目标，说明“学习进步”是需要认真比较的基线；其任务空间与开放语言目标不同，适用条件需要重新建立。[pyoudeyer.com](https://www.pyoudeyer.com/ActiveGoalExploration-RAS-2013.pdf?utm_source=chatgpt.com)

本轮补读的 **EmbodiedRSI v2（2026-11-12）**进一步收窄了第一轮的新颖性边界：它已有基于物理比较结果的假设更新、按信息收益／成本选择实验，以及按后续改进收益学习记忆操作；演化期间底层 VLA 冻结。因此，“主动实验＋物理反馈＋可学习记忆”已有直接先例。本项目仍需证明更具体的区别，例如 θ 会改变时，旧诊断与价值预测怎样再校准，以及信息收益是否真的转化为外部任务用途。[arxiv.org](https://arxiv.org/html/2610.10498v2?utm_source=chatgpt.com)

### 6.4 从能力缺口推导数据需求：失败轨迹首先告诉你“哪里需要监督”

不同问题需要不同数据：

| 已有诊断 | 优先数据 | 不足以解决它的数据 |
|---|---|---|
| 正确目标下接触动作不可靠 | 失败附近起态的可靠纠正和成功示范 | 只增加标准起态成功轨迹 |
| 常见交接起态退化 | 真实前驱产生的起态与后继成功片段 | 单独 reset 后的理想技能演示 |
| 状态识别错误 | 带独立状态标签的合法观测 | 没有标签的更多动作 |
| 目标表述不匹配 | 经过执行验证的指令—行为对应 | 任意语言改写 |
| 新底层能力缺失 | 合格教师示范、纠正或适用学习信号 | 把失败动作直接当 BC 正标签 |

ThriftyDAgger 将新颖性和失败风险用于决定何时请求教师，支持“在哪里缺数据”和“正确动作是什么”需要分别解决；它依赖教师和风险估计，不能直接当成本项目已有能力。[proceedings.mlr.press](https://proceedings.mlr.press/v164/hoque22a.html?utm_source=chatgpt.com)

当前采集实现已经保留了有价值的链条：预测前输入和局部指令、完整 proposal、发送子集、返回槽及对应下一观测。它也明确承认动作是已发送且收到对应返回的命令，不是独立测得的执行器实际运动，RPC 异常还可能留下未知转移。[采集 writer](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/rpent/flywheel/episode.py#L309)

这不意味着命令动作不能训练：如果学习目标本来就是该控制接口的命令，经过验证的命令—观测对可以适用。但不能把 proposal、发送命令和真实执行器运动混为一谈，也不能把未知执行片段补成连续可靠样本。

另一个实质缺口在导出：当前 LeRobot 帧使用整条 episode 的原始任务语言；局部指令、segment、动作来源和未知边界留在侧录，并未完整进入训练帧。因此：

- 训练整任务策略时，这种语言可能合适，但仍需检查教师信息是否可由学生输入恢复；
- 训练局部恢复技能时，需要恢复正确局部目标和片段完成标签；
- 整回合成功，不保证其中每个动作都是优质示范；
- 整回合失败，也不否定其中某个独立验证的恢复片段有训练价值。

### 6.5 怎样证明增长，而不是挑容易任务或增加技能条目？

我建议先做两项先导，再考虑长期课程研究。

#### 先导一：筛查“发现能力”与“获得能力”

选 3 个通过独立规格审查、场景与工具确实支持的未列目标，每个 3 个新初态，比较裸 VLA 与冻结组合系统，共 **18 个回合**。

前置条件是新目标有正确的运行时语义与独立判据。测整目标、原子目标、调用／动作成本和 unknown。

- 裸 VLA 已会：属于覆盖发现，不必为“获得该技能”训练。
- 组合系统会而裸 VLA 不会：属于编排或工具扩展，再判断是否值得内化。
- 两者都不会，且诊断支持底层缺口：进入数据与训练准备。
- 只是环境目标或评分未接通：先修实验定义，不计为能力失败。

三次初态只适合筛查，不能宣布“已掌握”。

#### 先导二：比较机会选择能否改变外部收益

前提是至少有一条真实可执行的更新路径。θ 未闭环前，可以研究 φ／ρ 带来的系统成长，但不能声称已经证明 VLA 主动学习效率。

先给各方法相同的起始系统、合法先验、候选范围和资源上限，比较固定课程、学习进步／简单 VOI、拟议用途价值法。先用少轮任务流确认：

- 它们确实选择不同机会；
- 反馈会改变下一次选择；
- 成本可完整计账；
- 差异能够由具体机制解释。

随后才扩展独立学习运行。评价应包括三个互相补充的集合：

1. **固定旧能力锚点**：检测遗忘和代价上升；
2. **独立未见条件与组合任务**：检测复用和迁移；
3. **外部长期任务流**：测累计完成效用、学习成本与接管负担。

新任务协议可以增加，但比较新旧版本时必须让两者接受同一新协议；不能通过改变分母制造成长。最终保留评价不能反复回流为课程选择反馈；需要另设开发验证流。

关键结果解释是：

- 简单课程达到相同增长：保留主动成长工程能力，不把复杂选目标算法作为方法贡献。
- 只在自己选的目标上分数上升：检查容易目标偏好。
- 优势来自更多教师、重试或计算：支持资源增加的作用，尚不支持选择效率。
- 预测的后续用途能对应实测解锁、迁移或未来学习成本下降，且等资源优于简单方法：才支持继续研究价值驱动的主动成长。

在投入更多采集前，还可以先对一条带局部指令或恢复的 episode 做端到端数据审计：

> 预测输入 → 局部指令 → proposal → 发送动作 → 返回转移 → 局部／整任务结果 → 拟训练样本。

这项工作成本较低，却能决定现有数据是否值得继续积累。

## 一、问题 7：哪条科学主线最值得集中研究？

### 1. 四个方向的优先级，应按“还剩什么问题”排列

[`02`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/02_科学问题与创新路线.md) 已经保留了四个方向，并明确列出了升级后再适应、证据与修复失真、主动成长、ψ 迁移等候选。因此，下面是在已有设计上进一步确定实验顺序和取舍条件，并非把这些候选重新命名为新发现。

| 方向 | 机器人场景中值得研究的具体困难 | 最强的竞争解释或简单解法 | 我的当前判断 |
|---|---|---|---|
| **F1：可靠自主诊断与修复** | 部分可观测、接管后看不到未接管结果，同一种失败可能对应不同修复 | 补齐观测、纠正工具语义、保存关键片段、有限规则诊断就足够 | **最先筛查。** 它决定后续研究是否建立在正确证据上；若剩余问题只是接口缺陷，直接修复 |
| **F2：Agent–VLA 长期协同进化** | θ 改变后，旧的分解、路由、接管和恢复经验可能失效，也可能继续有效 | 将相关记忆标为待确认，再做少量复测或阈值校准 | **有条件的论文首选。** 需要证明简单方案之后仍有显著的物理试验成本 |
| **F3：有限物理预算下高效自进化** | 诊断、采集、复位、训练、验证竞争同一预算；获得某能力还可能解锁后续任务 | 固定课程、失败优先、普通 Bandit／信息价值方法 | **作为主线的优化目标和共同约束。** 单纯加入预算调度或信息价值公式不足以构成新方法 |
| **F4：研究策略自身进化** | 从历史中学到怎样诊断、怎样设计实验，并迁移到新的改进问题 | 固定研究流程加事实记忆、等预算搜索，已经解释全部进步 | **保留真实研究努力和独立考试。** 证据要求最高，不能由系统多轮运行成功代替 |

### 3. 当前最有潜力的具体问题：哪些协作经验需要重新验证？

考虑一个尚待项目实验确认的情形：

- 旧 VLA 在某类抓取起态上不可靠，Agent 学会绕开它，先调整姿态或频繁接管。
- 微调后，这部分能力改善了，但旧策略仍继续绕行，增加调用、时间和中间状态转换。
- 若把全部经验清空，又会丢掉对其他技能仍然正确的限制和恢复方法。
- 若全量重新测一遍，成本可能高于这次升级带来的收益。

真正要研究的是：**能力变化是否具有可利用的局部结构，足以让系统少做物理试验，又能正确决定保留、修订或放弃哪些协作建议。**

当前实现提供了一个基础，但尚未解决这个问题。`fixed_route()` 只在状态对应的版本签名一致时使用已学习路由，否则退回允许的默认调用；`relation_learning.py` 要求独立起点／交接反馈和匹配版本。这能防止明显不兼容的证据直接混用，但不等于已经学会跨版本判断哪些经验仍有效。[源码：`cooperation.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/cooperation.py)、[`relation_learning.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/relation_learning.py)。

#### 可以实现的候选机制

我建议先研究一个小而明确的表示，不急于引入新的大型网络：

1. **把经验表示为有适用条件的证据。**  
   每条记录包含技能、可观测入态、任务阶段、调用方式、执行者版本、结果与成本。历史事实保留；“当前版本仍应避免该技能”等操作建议另行记录其确认状态。

2. **估计干预的净价值，而不仅是失败概率。**  
   对合法可见的上下文 \(x\) 和执行版本 \(v\)，关心的是：

   \[
   \Delta_v(x)=
   \mathbb E[U\mid do(\text{辅助}),x,v]
   -
   \mathbb E[U\mid do(\text{直接执行}),x,v]
   \]

   这里 \(U\) 是预先定义的任务效用。一个状态失败概率高，并不意味着 Agent 的现有干预能改善它；一个状态容易成功，也可能因不必要干预而变差。

3. **优先验证会改变决定的区域。**  
   例如，同一技能在不同入态下的证据，是否足以改变“直接执行还是先恢复”的选择。选择实验的依据是预期减少错误决策的程度与成本，而非异常程度或模型自述的不确定性。

4. **在没有值得改变的决定时停止。**  
   新 θ 未改变相关能力、旧建议仍有充分支持、或者验证成本高于预期使用收益，都应允许保持现状。

这个方案里的版本标注、信息价值、局部估计本身都有成熟思想来源，不能分别声称创新。**可能的方法贡献**在于：利用机器人技能的入态、交接和干预结构，预测能力更新会使哪些历史证据失效，并在相同信息与预算下，比普通窗口、校准、Bandit 或通用信息价值方法更省试验。

它还有明确的可识别限制。接管后的成功不能提供“未接管会失败”的标签；固定 seed 也不等于恢复了同一个中间状态。仿真反事实需要先验证物理状态、控制器、随机数、策略历史与队列的恢复范围。做不到时，应采用完整策略之间的随机化比较或有明确假设的估计，保留未知区域。当前先以可执行的工具调用和片段边界为干预单位，不假设已有任意时刻的中断能力。

#### 哪些结果才能支持这套机制？

我会要求至少出现以下几种可区分的现象：

- **收益集中在能力确实发生变化的技能与入态。** 如果任何地方都同样上涨，更可能来自整体提示改写或更多信息。
- **不变区域确实少测了，同时旧能力保持。** 只减少验证次数，却增加错误复用，不算提高效率。
- **简单校准之后仍有剩余收益。** 若阈值调整、短窗口或“标为待验证＋均匀复测”追平，就采用它们。
- **没有 θ 变化时，方法不会频繁制造更新。** 这是检验过度反应的重要负对照。
- **在预留的能力变化或任务家族上仍有效。** 仅记住“这个任务升级后要重测”，不足以支持可迁移研究策略。

强基线应按阶段加入：先比较旧协作策略、普通记忆修订和简单校准；看到残余后，再比较具有相同特征、相同数据和相同预算的上下文 Bandit、通用信息价值选择，以及轻量重训或 GEPA 式规则优化。无需一开始同时实现十几个方法。

### 4. 四种能力必须分别测量

当前项目最容易混淆的是：系统最终成功了，究竟是谁变强了？

| 研究对象 | 应固定什么 | 主要评价 | 不能替代它的证据 |
|---|---|---|---|
| **组合系统能力** | 外部任务分布、允许工具与预算 | 独立任务成功、长期任务流效用、全流程成本、旧能力保持 | 单个工具成功或候选通过 |
| **裸 VLA 能力** | 观测、指令方式、控制时序、执行预算；移除额外规划与恢复 | 原任务及目标技能表现、条件泛化、旧能力回归 | Agent 补救后的系统成功 |
| **编排能力** | θ、技能池、工具权限、信息可得性与调用预算 | 相对直接执行、静态计划、简单规则的净收益；有益与有害干预 | 增加重试、额外视角或额外工具后上涨 |
| **研究能力 ψ** | 被改进系统起点、合法事实、允许更新集合和考试预算 | 新改进问题上的独立收益、达到目标的成本、错误修复和未完成问题 | 多轮成绩上升、更多记忆、更多候选 |

这与 [`03` 的系统评价及 H3 协议](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/03_实验设计与验收协议.md) 一致。落实时还要区分两类实验：

**共同数据实验**让各方法访问同一份合法证据，回答谁更会解释证据、选择修复。**交互实验**允许方法主动取证，回答整个研究过程是否更有效；此时内部访问的状态和获得的数据可以不同，但外部任务流、权限和预算要固定。

同预算也不意味着强迫每个方法花完所有资源。应固定可用预算，记录实际消耗；物理交互、GPU、模型查询、人工和墙钟无法总是同时完全相等，可以固定主要约束、给其余资源设上限，并报告成本曲线。不能只匹配一次模型调用数，却让某方法免费多采集数据、多复位或多用教师。

面对标准任务高分，任务分布也应分层：

- 熟悉任务作为旧能力和不必要干预的检查；
- 同任务的新条件，检验观察、接口与执行能力的边界；
- 已有技能的组合与交接，检验编排；
- 至少一个经验证确实需要学习的能力缺口，检验 θ 更新；
- 预留的改进问题，检验 ψ。

“同任务换 seed”只能支持相应的新初态泛化。公开记忆或训练范围是否覆盖该任务，也必须登记，不能把“本协议第一次运行”自动写成“系统从未见过”。

### 5. 元改进应成为这条主线上的独立考试

你的 H3 目标应保留，而且现在就应开始保存 ψ 快照和形成它们的历史。它不必立即扩展成任意算法创造。

一个可实施的研究策略，可以在受约束动作集合中决定：

> 检查入态 → 比较指令／调用方式 → 复测技能 → 校准协作 → 采集数据 → 更新 θ → 停止或转向。

每次决定记录预期能区分什么、预计收益和成本，以及实际结果。ψ 可以是选择规则、收益预测参数或受约束程序；关键在于反馈是否改变了后续研究行为。

当前 ρC 的反馈还很窄：已加载开发试验的 screening checks 被转成观察性通过率，`fixed_research_step()` 据此继续或暂缓。源码明确标记 `observational_not_causal`。这能支持“存在反馈消费者”，不能支持“已经学会更有效地研究机器人”。它还有一个值得检验的偏差：**提高 screening 通过率，可能只是越来越会回避难问题。** 因此不能只奖励少失败、少拒绝或少做实验。[源码同上：`relation_learning.py`、`cooperation.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/cooperation.py)。

考试至少比较：

- 早期 ψ＋共同的合法晚期事实；
- 晚期 ψ＋同一事实库；
- 固定诊断流程或等预算通用搜索＋同一事实库。

如果检索选择本身属于 ψ，就让双方访问同一事实库和相同检索预算，不必强迫最终检索结果相同。若程序性记忆与 ψ 无法兼容拆分，则先建立公共事实接口；做不到时，只能声称“策略与记忆联合包更强”。

主要量可以写为：

\[
\Delta U_i(B)=
U_{\mathrm{独立评价}}\!\left(S_i^{\psi}(B)\right)
-
U_{\mathrm{独立评价}}\!\left(S_i^0\right)
\]

每个 \(i\) 是一个完整的**改进问题**，包含共同起点、合法初始事实、允许操作、预算与独立评价分布。一个问题的二十个测试初态，不是二十个独立改进问题；同一策略多次模型采样，也不是多条独立演化历史。

考试冻结 ψ，但允许它更新被研究系统和工作记忆。形成晚期 ψ 的开发成本另外报告。若晚 ψ 的优势在给早 ψ 相同事实后消失，就采用简单记忆方案；若优势能跨机制或任务家族迁移，再扩大独立历史和真实 θ 更新的验证。

## 二、额外问题一：长期反复验收后，系统是否只是越来越会通过验收？

这是比“评价模块独立”更进一步的问题：**候选、研究方向、停止时间和下一轮协议，是否已经依赖了反复看过的评价结果？**

### 1. 仓库已提出正确原则，缺口在跨轮落实

`03 §7`、`06` 已明确区分开发、可复用发布回归和最终封存测试，也明确工程阈值不是统计保证。因此，这不是文档遗漏了独立性要求。

当前实际 Gate 路径做的是：核对冻结槽位、身份、原生结果、硬条件和点估计，再依据 `min_gain`、anchor 等规则接受或拒绝。`assignment_metrics()` 和 `evaluate_matrix()` 不把缺失、unknown、invalid 随意移出分母。这些机制支持有限协议的可审计验收；已读生产路径中尚未看到跨候选错误率控制、置信序列或最终封存确认消费者。[`evaluation.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/evaluation.py)、[`evaluator.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/evaluator.py)。

例如，protocol10 的每侧八个正式槽位与 `.02` 改善阈值，只定义了该工程比较的规则；`.02` 不是 2% 精度或置信保证。重新解析、重新计算 Gate、导入部署资格，也不会增加执行样本。[`pilot_5a_protocol10.json`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/config/pilot_5a_protocol10.json)、[`upgrade_bridge.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/upgrade_bridge.py)。

还需要避免一个相反的误判：**本轮没有从源码确认正式评价详细分数自动进入 Research 的真实模型输入。** 已读的 `prepare_request()` 链路主要经 `query_development()` 取合法开发结果。但正式 baseline 会影响程序是否继续，协议也允许相应公开反馈；主持者是否据此修改下一轮任务或候选，要靠真实请求、读取和主持决定记录确认。[`research_tools.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/research_tools.py)、[`improvement_protocol.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/improvement_protocol.py)。

### 2. 为什么这可能改变整篇论文的结论？

软件独立性回答“谁能改标签、谁能读数据”；统计独立性回答“最后选择是否依赖这些数据”。即使 evaluator 完全诚实、只能返回 accept/reject，反复查询也可能逐渐泄露足以影响选择的信息。

自适应数据分析与 reusable holdout 的原始研究已经证明，普通 holdout 的反复自适应复用可能产生过拟合；其有效复用方法依赖特定信息释放机制、样本条件和预算，不能直接套在当前少量异质机器人槽位上。genui{"citation":{"ref":"turn113view0"}}

因此，“独立验收连续接受了多个版本”还不足以推出“系统持续改善了总体能力”，更不足以推出 ψ 变强。

### 3. 近期最小调整：记录评价暴露，再做一次新的确认

我建议增加一个跨轮的**评价暴露记录**，复用现有 run、bundle、protocol 身份：

- 哪些任务、真实初态和结果被谁看过，返回了多细的信息；
- 候选与 ψ 何时冻结，之前接触过哪些评价输出；
- 哪些数据仍封存，哪些已经用于回归，哪些已参与开发或选择；
- 所有候选、拒绝、停止、重启与协议变更；重新解析明确不算新样本。

随后保留三个用途不同的集合：开发充分反馈、发布回归、最终新样本确认。现有工程硬阈值可以保留，论文结论另增加统计证据。

最简单的辨别实验是：**冻结最终候选与强基线，在预先声明的新初态或新任务分布上做一次确认**，同时报告配对收益、成本、分任务结果和全部槽位。

- 回归集上涨、独立确认不涨：支持选择效应或分布特化，应收窄结论。
- 两者都稳定上涨：增加对实际改进的信心。
- 区间很宽：结论未定，不能直接判为无效。

若成本要求边测边停，可以研究适用的置信序列；但它只解决满足条件的序贯估计问题，不能自动修复在同一 holdout 上不断换候选造成的选择偏差。genui{"citation":{"ref":"turn114view4"}}

这个问题会直接影响 Autoloop：持续运行时，调度器应知道某批评价数据还能支持什么主张，而不只是知道还有多少次运行预算。

## 三、额外问题二：物理世界不会自动清空，谁负责制造下一次有效学习起态？

问题是：

> **任务结束后，系统应继续利用当前状态、执行恢复、复位，还是换一个适合当前场景的任务？这些选择怎样改变学习成本与能力评价？**

这既影响自主运行，也影响“有限物理预算下更高效”的方法排名。

### 1. 当前并非完全没有复位记录，但记录范围有限

LIBERO 的 `EnvironmentJournal.costs()` 已记录 reset 次数、完成情况、耗时，以及 setup 与 policy 的动作计数。因此不能把“补充复位计费”说成从零开始。[`runtime_evidence.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/runtime_evidence.py)。

另一方面，`runtime.py` 的 `manual_seconds=0` 明确属于当前非交互调度尝试的记录口径；它不能证明整个研究流程没有人工，也不涵盖真机摆场、清理和重新放置物体。[`runtime.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/src/rsi_vla/runtime.py)。

更关键的是，软件任务可以从 checkpoint 续程，物理环境未必仍处于 checkpoint 假设的状态。服务重启后，应先依据实际观测确认机器人和场景状态，再决定续接、恢复或重新开始。

### 2. Piper 的接口差异，已经足以改变实验设计

本轮进一步核查了同一 commit 中的 RLinf Piper 代码：

- 文档明确说当前指南用于硬件检查，尚未提供受支持的 Piper 真实任务／训练工作流；
- `PiperEnv.step()` 接收六个绝对关节角，单位为弧度，另加 `0—1` 夹爪开度；
- `reset()` 把机械臂送回预设关节姿态，没有把物体恢复到任务起态。

来源：[Piper 文档](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RLinf/docs/source-en/rst_source/examples/embodied/piper.rst)、[`base.py`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RLinf/rlinf/envs/real/piper/base.py)。

这与当前 LIBERO 的归一化 OSC 位姿增量动作不同。**同为七维，不代表模型输出、数据或控制接口兼容。** 加一个转换函数也不会自动解决 embodiment 与训练分布差异。[LIBERO 动作合约](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/RPent/robots/libero/action_spec.py)。

而项目计划中的实际 Piper 后端是库外 `lerobotv6` 服务。仓内 RLinf Piper 源码的存在，不能替代对那个实际后端、安装版本、checkpoint、processor 和数据合约的核查。[`01 §2`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/01_系统设计与框架复用.md)。

### 3. 为什么这会改变算法，而不只是多几个成本字段？

假设两种研究策略取得相同任务成功率：

- A 每次成功后把物体留在难以恢复的位置，需要人工重新摆场；
- B 单次稍慢，但多数结束状态可以直接进入下一任务或由既有技能恢复。

在持续工作中，B 可能具有更高的实际吞吐量。反过来，若系统总挑当前最容易完成的任务，也可能表现为长时间自主成功，却没有获得新的能力。

所以必须同时保留两类评价：

1. **固定起态考试**：回答能力是否提高，排除只选择容易状态。
2. **连续物理任务流**：状态不免费清空，回答系统实际能否持续工作与学习。

第二类实验的重复单位通常更接近完整任务流或实验时段，而不是其中每个相互依赖的 episode。

已有研究提供了相关思路：R3L 通过扰动策略创造后续学习状态；SOAR 根据当前场景提出有语义、可执行的任务。这些结果支持把“下一起态”作为决策的一部分，但不能推出开放桌面上的 Piper 已能自动恢复所有状态。genui{"citation":{"refs":["turn106view0","turn114view3"]}}

### 4. 与当前条件相称的辨别实验

先做 **6—10 个完整物理循环的操作性审计**，规模仅用于估计流程，不用于宣称统计优势。记录任务执行、恢复、摆场、人工操作、等待和可继续状态；墙钟与并行计算不要重复相加。

之后按结果决定：

- **复位成本小且稳定**：沿用简单人工或固定程序，不为它另开研究主线。
- **一两类恢复占据主要成本**：比较人工／固定复位、已验证恢复技能，以及 Agent 在同一技能目录中按状态选择。
- **大量状态无法自主恢复**：先解决任务可持续性和数据采集条件；增加推理复杂度未必有帮助。

这项工作服务于同一篇论文：让“更少物理预算”对应实际的机器人使用成本，并检验方法是否依赖仿真提供的免费起态。

## 四、怎样让真实 θ 更新、长期实验、迁移和 Piper 支撑同一篇论文？

我建议把证据组织成四层，每层回答前一层无法回答的问题。

### 第一层：确认需要解释的现象

在可靠接口、足够观测和强简单基线下，测量 Agent 的净价值。动态 Agent 若没有超过简单规则，应保留简单执行方案；Research Agent 的诊断、采集和训练价值仍可继续研究。

这一层也应排除“工具返回结束被当成子目标完成”“Research 实际没收到所需图像”“更改控制时序导致基线吃亏”等前两轮已识别的解释。

### 第二层：用真实 θ 更新确认升级后的协作问题

先获得一个有独立能力收益的新 θ，再比较 θ 与协作策略的组合。当前 5B 的短步训练配置应首先用于验证数据读取、训练、保存、加载与动作合约；它本身不足以回答学习效果。[`04`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/04_实施路线与待决事项.md)、[`OFFLINE_CHECKS`](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/core/OFFLINE_CHECKS.md)。

最初的四格比较是旧／新 θ 与旧／重新校准的协作规则。这里有一个实现上的注意点：现有版本不匹配会触发默认路由，必须记录**实际消费了什么规则**。受控评估要建立合法绑定的实验配置，不能把因不兼容而退回默认行为的运行，当作“旧策略在新 θ 上的表现”。

θ×协作出现交互效应，说明两者的作用不能简单相加；它仍不能单独证明某个反馈通道或三ρ联动具有因果贡献。

### 第三层：验证选择性再验证与 ψ 迁移

先固定 θ 更新，比较不同再验证方法，避免同时改变训练数据、模型和协作算法。先做共同数据比较，再做允许主动取证的交互比较。

看到收益后，再进入多轮：不同更新会让系统遇到新的协作适用性问题，ψ 从中形成方法，最后在预留改进问题上考试。这样，长期运行提供研究策略的形成过程，独立考试负责检验它是否变强。

### 第四层：有限迁移与 Piper

第二种动作生成类型应只验证选定的关键结论，使用它自身的动作、观测和数据合约，不再完整复制整套实验。

Piper 则承担一次有意义的物理改进闭环：有基线、有可追溯更新、有独立评价、有部署继承，并记录人工、恢复和复位成本。如果论文核心是 θ 更新导致协作适用性变化，真机部分应尽量验证同一机制；若实际条件只支持接口和有限能力验证，就明确其范围。

这可以让硬件证据成为主线的压力测试，而不是最后补一个与方法无关的演示视频。

## 五、三轮综合后，当前最应优先回答的三个问题

### 优先级 1：强直接执行与简单监督之后，Agent 还剩多少可重复的净价值？

这决定动态 Agent 是否应常驻执行环，哪些任务直接交给 VLA，哪些只在事件出现时介入，以及研究投入应更多放在执行编排还是后台学习。

最有价值的结果不一定是 Agent 全面胜出，也可能是找到清楚的使用边界。

### 优先级 2：真实 θ 更新后，旧协作策略是否造成重要失配，简单再校准是否已经足够？

这决定论文是否围绕 F2 投入，也决定需要局部适用性估计、通用记忆修订，还是普通版本管理即可。

如果没有失配，不应人为构造一个糟糕旧策略来证明方法有用；如果仅在受控合成条件下存在，应把结论限定在那里。

### 优先级 3：晚期研究策略的优势，能否超出更多事实和普通搜索，并迁移到新问题？

这决定是否有资格提出元改进主张，ρC 应学习什么，以及是否值得增加研究策略的表示与更新复杂度。

如果早 ψ 加同一事实库就追平，采用简单记忆方案是合理研究结果；完整 RSI 系统目标可以继续推进，但论文中的能力主张需要相应收窄。

以下是待执行方案，不改写现有协议，也不恢复当前暂停任务。先导规模用于决定是否继续；正式样本量应由效应、方差、相关性和拟作主张确定。

## 七、哪些可以直接采用，哪些必须验证，哪些继续开放？

### 可以直接采用的工程调整

这些工作有明确作用，无需先证明一种新算法：

- 让调度续程同时核对预算、任务状态和实际环境状态；等待资源、技术恢复、候选拒绝和研究停滞使用不同状态。
- 记录实际模型输入与消费者，按需要补齐图像、新观测和任务状态，而不是只增加字段或媒体引用。
- 完成合格数据到训练、checkpoint、真实加载、独立评价和继承的最小往返；不把未准入自主轨迹直接当合格示范。
- 保留历史事实与版本依赖，区分“历史上失败过”和“当前仍应避免”。
- 增加跨轮评价暴露、人工与物理恢复记录。

这些是本次方案建议，尚未由本轮分析实施。

### 值得验证的研究假设

最值得投入的是三项：

1. θ 更新造成的协作适用性变化具有局部结构，可以用它减少重新验证成本。
2. 选择能改变修复决定的实验，比按异常强度、最低成功率或普通不确定性排序更有效。
3. 形成的研究策略在共同起点和事实下，能够迁移到新的改进问题。

主动成长中“某技能能解锁哪些未来任务”的价值预测，也值得保留；但应先与固定课程、失败优先和简单机会选择比较，不能由目标目录变大证明能力增长。

### 应继续开放的架构选择

- **单体持续更新还是专家／Adapter／技能池**：依据真实遗忘、覆盖与路由成本决定。
- **ψ 用规则、程序还是学习模型表示**：先证明决策问题和反馈足够有效，不预设必须训练大型研究 Agent。
- **固定、事件触发还是不确定性触发监督**：取决于延迟、可用观测与有效干预窗口。
- **是否需要同时学习三ρ**：先固定不相关通道，确认依赖后再增加联动。
- **机制解释驱动的局部权重修复 H4**：保留为有前提的分支，不作为基本闭环的依赖。

角色职责也不必对应三个持续运行的大模型进程。确定性调度、执行推理、研究决策和独立验收，可以按实际需要使用不同实现。

## 八、结论强度与最小证据缺口

### 已有充分依据的判断

**工程完整性、自动化程度和科学贡献必须分开。** 固定版本中已有实际消费者、身份与预算控制、独立原生评价和部分闭环机制；`04` 也记录了真实仿真进展。但最新状态仍为 `five_a_complete=false`，没有当前项目的 H1—H4 科学结论或 Piper 闭环证据。历史原始产物未入库的部分，本次不能升级为直接读取过的实验事实。[`04` 当前状态](https://github.com/Xuruiyi/RSI-Agent-VLA/blob/1850ab1aceb5c4d22dba503ba0e778653f7bed63/项目文档/04_实施路线与待决事项.md)。

**宽泛的“自主实验、按需训练、记忆进化、升级后重新适应、改进器改进自己”都已有相关先例。** 项目的贡献需要体现为具体机制、可区分预测和强基线之后的收益。

**独立模块重新核对同一份证据，不会增加统计样本；系统继承了 ψ 引用，也不会自动证明研究能力继承。** 这两条会影响最终论文中所有“持续改进”的表述。

### 仍然未决的判断

目前尚不能确定动态 Agent 的净收益是否超过简单监督；真实 θ 更新后是否出现重要协作失配；选择性验证是否超过普通校准；ψ 是否具有超出事实积累的迁移能力；主动目标是否带来独立能力增长；以及 Piper 上的完整成本与可持续性。

这些不是需要靠更多架构讨论解决的问题，必须由上述辨别实验回答。

### 真正需要库外补充的材料

无需补交整个本地目录。最有价值的是以下几组最小绑定证据：

1. **一个代表性真实闭环的完整绑定**：实际源码／安装版本、模型与 processor 身份、真实输入、执行与独立结果，用于连接当前源码和历史运行。
2. **真实 θ 更新往返证据**：合格数据、训练配置与产物、实际加载记录、独立能力比较。尚未发生的部分应作为后续产出，不能假定已经存在。
3. **实际 Piper 后端与物理流程证据**：库外服务版本、动作／观测合约、匹配模型与数据，以及执行—恢复—复位的成本记录。
4. **若已有 ψ 演化历史**：早晚快照、事实记忆、候选选择和评价暴露记录；若尚无，则从下一条合法研究历史开始保存。

**下一步最值得投入的实验，是先取得一次真实、可独立确认的 θ 能力提升，再检查旧协作规则是否造成了简单校准也无法消除的代价。** 这项结果会直接决定：继续围绕升级后的有限预算再验证下注，采用简单协作方案，还是把论文主线转向更有证据支持的诊断或研究策略问题。
