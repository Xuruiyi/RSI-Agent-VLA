## 一、最终判断与证据边界

### 1. 核心结论

**completion11 补证使一次有限 φ 更新的工程闭环获得了直接运行材料支持，但没有把它升级为 θ 学习、三关系学习或 ψ 元改进证据。** 已关联 Research 真实响应、候选、实际提示规则、16 个正式指派槽、独立比较、独立部署资格、真实激活以及后续继承运行。继承运行的结论必须完整保留为 **技术 valid、任务 failure**。

正式比较由 6/8 成功变为 7/8，J 从 .7625 变为 .825；**加权增益来自旧抽屉任务，目标扰动任务 position_swap_salad 仍为 1/2，只是两个 seed 的成败互换**。因此，这些数据不支持“目标识别提示已稳定解决位置交换任务”或“提出的诊断因果机制已验证”。两臂均为 Planner＋VLA，也不是纯 VLA 与 Agent 的价值对照。

推荐研究主线继续保持为候选：**真实 VLA 能力更新后，怎样以有限物理试验判断哪些协作经验仍有效、哪些需要重新验证，并学习可迁移的研究决策规则。** 推进前须依次确认：有效 θ 更新、旧协作失配、简单校准之后的重要残余。当前没有这三个前提均成立的项目证据。若简单解法已足够，应采用简单方案并转移研究投入。

最先需要回答的三个问题是：强直接执行及简单监督之后 Agent 还有多少净收益；有效 θ 更新后是否需要超过普通校准的再适应；晚期 ψ 是否超出更多事实和普通搜索、在新改进问题上更强。具体实验和取舍条件见配套实验方案。

### 4. 三层闭环与模块职责

系统状态沿用 $S_k=(\theta_k,\phi_k,\psi_k,\rho_{A,k},\rho_{B,k},\rho_{C,k})$。三层闭环依次回答“怎样完成任务”“怎样产生和继承更好的系统”“怎样改进寻找更好系统的方法”。

| 对象 | 主要职责 | 可继承内容 | 不应混淆的边界 |
|---|---|---|---|
| VLA θ | 视觉／语言条件下的动作生成 | 权重、Adapter、processor 与动作归一化 | 外层恢复成功不等于 θ 学会 |
| Runtime／执行 Agent φ | 任务解释、技能组合、监督、恢复与调用逻辑 | 提示、规则、技能、阶段程序 | 提示变更不自动属于 ψ |
| ρA | 信息交互：取证、保留、压缩与传递 | 证据选择和信息路由规则 | 保存路径不等于图像进入模型 |
| ρB | 职责分配：Worker、调用、交接与接管 | 版本和状态相关的选择策略 | 工具结束不等于交接条件成立 |
| ρC | 学习更新：改什么、怎样改、顺序与预算 | 更新和实验选择策略 | 可以是 ψ 的组成，不能重复计算贡献 |
| Research／ψ | 诊断、假设、区分实验、收益预测和研究方法更新 | 规则、参数、程序及程序性记忆 | 一次实验或更多事实不等于研究策略变强 |
| 独立评价／发布 | 按冻结协议重算结果、保护旧能力、资格与激活 | 不可变评价及发布回执 | 重算同一轨迹不会增加样本量 |
| Autoloop／确定性调度 | 持久状态、事件、等待、续程、去重、预算与停止 | 作业与版本绑定、账本、待办状态 | 定时重复叫模型不等于形成研究闭环 |

这些是职责划分，不要求每一行对应一个持续运行的大模型。ρB 可与 φ 共用实现，ρC 可属于 ψ；运行身份与实验修改范围必须明确，避免同一个变化被宣称为多个独立创新。[D00] [D01]

### 2. Research 看到了什么，真正决定了什么？

`request.json` 为 `rsi-lossless-json-v1` 可逆业务编码，本次按字段／共享表规则解码，核对其与 permit 中输入绑定。它包含一个 valid 原生开发失败、一份证据视图、**741 条可用事件中选入的 40 条 L0**，以及 **78 个媒体路径**。未选事件仍被引用为宿主留存，不代表全量进入模型；路径并非图片字节。响应自己也明确承认未查看视觉内容，目标身份、释放、稳定等过程标签未知。[A01-S01]、[A01-S04]

实际准入记录从 HTTP JSON body 取得 `gpt-6.1-sol/high` 和空 `tool_catalog=[]`；终态为 `response.completed`。用量为输入 32,155、输出 1,900，其中 reasoning 957 已包含在输出内。历史调用点为 `thread.turn(model_prompt(transport), ... output_schema=...)`。这些能确认业务输入生产路径、真实模型／强度／无工具设置和响应，**不能把 request.json 称作完整 HTTP 请求，也不能用 token 归因补出 SDK 增补消息的全部字节**。[A01-S05]、[A01-S06]、[A01-S07]、[A01-S08]；[A07-S04]、[A07-S05]

研究空间已被预先限制：输入登记了对象身份、干扰物和可见后置条件方向；唯一允许修改算子是最长 1,200 字符的启动提示；两个开发槽已固定。Agent 实际生成了具体提示、三个竞争解释、区分预测和 `prepare_rule_trial` 决定。宿主负责 schema 与范围校验、规则和 diff 构造、bundle 物化以及后续执行。由此可支持“Agent 在限定研究问题内提出了一个有限 φ 候选”，不能支持“Agent 独立发现研究方向并在 φ／θ／ρ／ψ 间自主选择更新对象”。

原 SDK `final_response` 解析结果与 `validated-response.json` 相同；其中 **699 字符**的 hint 与实际规则逐字一致。它要求从观察识别目标、区分 dressing bottle 与 soup can、不要由已发指令推断抓取／放置成功，并以入篮、释放、稳定、夹爪离开等观察后置条件为目标。提示同时包含多种可能作用，成败不能区分具体是哪项有效。[A01-S03]、[A01-S04]；[A02-S03]、[A02-S04]

## 三、问题1：Autoloop 如何成为三层闭环的运行机制？

### 1. 具体来源与已经接入的部分

这里的 Agent Autoloop 是 **KKKKhazix/agent-autoloop**，不是名称相近的自主研究脚本。仓内 package 与 README 指向该官方项目。聚合 commit 下子树为 `af8920e824dd141ab142de9380669cec6d7e544e`；与已取得的上游 commit `c9ec4a187cab49627947e7e33db265ec143db3b8`（2026-11-13）的根 tree 完全相同，因此可精确对应所读源码树。源码没有静态 package version，`host/version.ts` 从独立git/release或部署变量取版本。tree一致不等于历史安装／运行版本已核，也不能把网页最新release自动当作历史使用版本。[KAUTO] [WAUTO]

其关键机制包括持久事件日志、事件与指令分离、Agent单轮退出后挂起、定时／事件唤醒、会话续接、幂等和跨复查仍保留的跳数限制。上游README的测试与平台范围属于上游报告，不等于本项目实际接入全测。[WAUTO]

本项目 `AutoloopBridge.consume()` 把登记过的外部身份转换为固定core操作；`Coordinator`持久保存意图、pending、receipt，先reconcile后派发；`run_protocol10_autoloop.py`和独立host连接已有执行／评价角色。事件文字不能决定命令、cwd、权限、预算或发布对象。这些静态接线及仓库检查记录支持工程可行性；**completion11附件没有Autoloop守护服务、定时触发及完整自动续程的原始触发链，不能把本次core闭环直接归功于Autoloop。**[KAUTOBRIDGE] [KCOORD] [DCORE]

当前接线还有两个具体缺口：较新的TaskCompletion执行路径仍依赖operator登记操作序列，不能仅把`allow_advance`设为true就得到通用的结果驱动下一步；桥接`render()`主要输出`ask`，映射`later/events`还须接通事件登记与`_signal`身份校验。完成、资源就绪和定时复查应有实际消费者，不能只改回执文本。[KAUTOBRIDGE] [KCOORD] [KTASKCOMP]

### 2. 哪些直接复用，哪些改造，哪些不适合

直接复用事件身份、持久pending、幂等、等待期间释放Agent进程、显式唤醒时间、预算／期限检查与可追溯回执。它们降低重复派发和人工盯守的工程风险，不需要包装成机器人方法创新。上游至少一次交付不能推出机器人副作用恰好执行一次；响应丢失或租约过期时，应核对原操作而非直接重发。因果链深度是防止事件自激的机制，不能充当科学预算，也不能靠重置深度规避限制。[KAUTO] [KAUTOBRIDGE] [KCOORD]

机器人改造重点是：续程前确认物理状态；训练与推理资源竞争；数据与候选版本绑定；原生任务结果与技术完成分开；新θ发布后处理协作经验适用性；把资源等待、技术故障、候选拒绝和研究停滞分别处理。

不宜照搬任意最后回复中的命令执行、无界自动重试、任意代码上线流水线或把自然语言审批提示当权限边界。上游CLI Agent的会话续接也不能保证对机器人状态、完整媒体和过往预算的可靠记忆；权威状态应在程序账本与证据库中。

### 3. 四类职责与故障处理

| 职责 | 应做的决定 | 不应承担 |
|---|---|---|
| 确定性调度 | 是否有授权、预算、资源、合法待办；何时等待／复查；幂等恢复 | 由LLM叙述直接改变权限或评价规则 |
| 执行Agent | 在现有动作与观察能力内解释任务、调用、恢复 | 自行认定整任务原生成功、长期研究选型 |
| Research Agent／ψ | 解释合法开发证据、提出区分实验和有限候选，必要时更新研究方法 | 覆写正式标签或自行授予更多预算 |
| 独立验收与发布 | 按冻结协议重算、保持检查、资格与受控激活 | 把候选自述当成功标签 |

资源不足进入带期限的wait并订阅资源事件；技术故障保留已计费尝试，按预留恢复身份与预算处理；有效任务failure正常成为证据，不无限重试；候选拒绝回到研究问题队列；研究停滞则检查证据不足、算子能力不足或假设错误，而不是简单提高调用频率。截止或人工暂停停止派发，历史许可不因“继续讨论”续期。

近期还应比较**薄的core事件守护程序**与完整Autoloop：两者共用相同core状态机、授权和账本，在相同负载下测恢复正确性、人工操作次数、等待／探测开销、未闭合请求与维护负担。少量单机作业未必需要完整平台；是否采用它保持开放，不承担预设论文创新。

### 4. 最小推进方案

先为既有core阶段建立可持久的下一步与receipt状态，并验证进程重启、重复事件、延迟回执不会重复物理动作或双重计费；再加资源与时间事件；最后让Research在已登记动作集合中决定下一实验并接受独立结果反馈。任务完成、发布接受和继承运行终结均有各自回执，下一层才触发。研究停滞保存候选语义签名、已否定假设和预期信息增益，避免换措辞重复同一实验。

自主研究分支的验收应至少包含两个合法后继，且结果真实改变下一步选择；同一路径重复调用模型不足以满足这一点。新ψ在研究作业边界切换，在途作业继续绑定原ψ。验收分开看：一次闭环能跑；无人盯守下能等待并正确续程；相同预算下研究决定更好。前两项自动化成立不推出第三项。具体任务和权限边界见03文档。

## 四、问题2：强 VLA 下 Agent 的价值在哪里？

### 1. 95.3%的来源与可比性

95.3%的直接文献来源为 **Harness VLA v5（arXiv:2607.08448v5，2026-09-24）表2**，第一轮原文实际采用的也是v5；本次重新核对该表与附录C.1。它也见于官方RPent排行榜及仓内`results.json`的`paper-table-2`来源：Spatial99/100、Object96/100、Goal97/100、Long89/100，共381/400=95.25%，表中四舍五入为95.3%。四套件各10任务×10初态。Harness的记忆在seed0构建，评价使用seed1—10，整任务以环境原生判据计分；表中的CC是Claude Code，不是本项目gpt-6.1-sol。它不是Hugging Face模型卡里的普遍性能保证；此前定稿核对的权重页没有model card。[WHARNESS] [WVLA] [KLEADER]

模型为`RLinf/RLinf-Pi05-LIBERO-130-fullshot-SFT`，本项目登记的revision为`6222623f635769bfc73c9472e29fab9b7fd8e027`；HF该固定revision可访问。实际加载记录指向对应本机checkpoint路径，并有后续预测证据，但未取得权重字节，不能独立认证加载内容与HF revision完全一致。公开评测使用同名LIBERO-130 SFT权重，并不自动证明其完整环境、随机性、动作时序与本项目一致。本次C11主要是4任务、公开seed0/1的有限比较，含position swap，且两臂都有Planner；实际`num_steps=5`等参数可核，不能仅凭同权重名称把两种成绩直接相减。[WMODEL] [A03]

即使总体已有95.3%，剩余改进空间也不等于“Agent必然无用”或“必然能补齐4.7个百分点”。它可能集中于VLA不可恢复的动作缺口，也可能是Agent适合处理的目标绑定和阶段转换；还可能因Agent干预而降低原本成功的任务。

### 2. 六类价值与边界

| 维度 | Agent可能提供的可验证价值 | 主要上限与竞争解释 | 最小比较 |
|---|---|---|---|
| 熟悉任务 | 发现异常、恢复、减少无效重试或耗时 | 不必要分解、错误目标重述、延迟使原本成功变失败 | 直接VLA／静态计划／规则监督／动态Agent，同工具信息预算 |
| 条件泛化 | 重识别目标、重述语言、使用合法新观察或工具 | 图像坐标映射、接触动力学、严重视觉域移不一定靠文字解决 | 保持动作模型，分别增加信息、调用权限、规划；剩余再测θ学习 |
| 任务迁移 | 组合已具备技能，处理前提与交接、外部约束 | 技能不存在或起态不可达时，推理不能创造底层运动能力 | 独立测原子技能、组合任务；给同样工具的静态／规则对照 |
| 学习效率 | 分辨失败、选数据与训练目标、组织诊断和验证 | 只是多花调用、教师或人工，或只挑容易问题 | 固定总预算与初始事实，比较最终独立收益和达到阈值的成本 |
| 长时序与工具 | 跨阶段状态、知识查询、约束变更、人机澄清 | 只有更多工具或信息而非更好推理 | 统一工具目录与访问权限；必要时单独报告增加能力的总效应 |
| 任务覆盖 | 处理多种目标和例外、按需调用专业技能 | 任务名称变多但底层能力未增长 | 独立未见组合／任务流，记录覆盖率和未解决任务 |

当前C11不能回答Agent相对纯VLA是否有价值，因为比较的是相同Planner＋VLA上的一段提示。它说明受约束φ候选可以进入真实运行；目标组未升与继承失败则提醒：仅把“看清目标、确认后置条件”写进提示，不等于系统获得了可靠的过程标签和新执行能力。

### 3. 更合理的定位：可退出、可少干预的协作层

直接VLA对照须由确定性驱动循环调用同一VLA、观测处理、动作前缀与原生终止消费者；静态方案须有冻结计划和固定切换程序。现有direct_vla标签或固定首技能均不能替代这些完整消费者。执行时，熟悉且已校准的任务优先让VLA在适当时域内直接执行；Agent在任务语义、长程组合、证据获取或可恢复异常确有价值时介入。触发依据应指向“现有干预能否带来净收益”，不能只用失败风险高低。恢复成功只能说明组合系统的结果；若要估干预收益，要有配对策略实验或可验证的仿真分支。

静态对照也应给合理的开发机会，必要时加入**充分开发后冻结的程序**。ASPIRE v2在LIBERO-Pro以seeds51—65开发、将每任务一个程序用于seeds1—50评价，提供了强固定程序的近邻；该程序可按固定分支处理观测，不等于开环重放动作，也不能直接把其成绩移到本项目。实际比较仍匹配信息、工具和开发成本。[WASPIRE]

研究时，Agent可以在不常驻动作环的情况下组织诊断、数据和更新。若简单执行器已经足够，研究Agent仍可能通过减少物理试验和人工获得价值。系统能力、编排能力、裸VLA能力、研究能力分别测量；任何一类不应替另外一类领取贡献。

新颖性也需谨慎：Harness VLA已使用固定解析技能与冻结VLA互补，AdaRSI与Robo-COP已研究编排和权重更新。有效的新问题要落在现成方法之后的残余，不能只以“Agent指导VLA”作为论文主张。[WHARNESS] [WADA] [WCOP]

## 五、问题3：怎样从改进机器人走向改进研究方法？

### 1. 三种“变好”需要三种证据

任务循环变好，可以来自当前观察、更好的恢复或更多重试；系统版本变好，需要冻结候选在独立评价上的收益与保持；研究策略ψ变好，需要在共同被改进系统起点、可比事实和考试预算下，更有效解决预留改进问题。

自动做实验证明流程能执行；积累记忆证明信息可继承；修改提示或代码要看改变的是执行φ还是研究ψ；形成新版ψ也只是产生候选，尚需考试。C11明确是φ提示更新，ψ对象固定，因此不提供早晚ψ比较或元改进结果。

### 2. ψ应学习可执行的研究决定

优先学习：症状对应哪些竞争解释、哪项检查最能区分、何时应补观察而非训练、哪类数据能修复何种能力、何时继续／暂缓／转向，以及收益和成本预测如何校准。ρC可实现其中的更新对象、方法、次序与预算选择；诊断和假设组织等更广部分仍属于ψ。[D00] [D02] [D03]

初期可用小型结构化规则或有约束程序：输入为合法证据、版本、可用算子、预算、未决假设；输出为下一项检查／实验、预期可区分结果和停止理由；反馈为实际实验结果、独立收益、误修复及全成本。模型权重学习不是必要前提。相反，若动作集合只含hint，系统偏向提示更新首先是动作空间限制，不能被解释为已经学会“提示比训练更合算”。

当前较新的`relation_learning.py`对ρC的反馈仍是开发screening yield，明确为观察性而非因果；`fixed_research_step`可据历史低通过率暂缓。这支持有限反馈消费，却可能奖励回避困难问题。具体地，当前以`task_key`汇总`bounded_experiment`的screening反馈，经验均值不高于0.5即可暂缓；没有其他样本时，一个0反馈就足以触发该条件。不同算子、版本或数据条件可能被合并，而技术有效的候选失败也可能有诊断价值。保守准入同时可能确实节省浪费，不能凭直觉删除，应比较固定准入、当前学习准入及按证据／算子／版本区分的简单策略。历史回放只能发现决策分歧，未执行分支的收益仍需有界实际比较。未来应把未完成问题、错误拒绝、旧能力损失及相同总预算下最终收益一起纳入，不能以“拒绝更少”或“永不更新”获胜。[KREL] [KCOOP]

### 3. 共同起点考试与记忆耦合

把一个改进问题定义为：初始系统、合法初始证据、可修改字段、允许实验、资源预算和独立评价分布。冻结早晚ψ，使用相同θ、φ及不属于ψ的配置；若ρC属于ψ，就让它随快照变化并记录。早ψ＋晚期事实、晚ψ＋同一事实、固定流程／通用搜索＋同一事实是主要比较。

事实记忆和程序性记忆先划分。若检索是ψ的一部分，应共享可访问corpus和访问预算，不能强制相同最终检索结果从而去掉待测机制；若表示不兼容，应建立共同事实接口，否则只报告策略＋记忆联合包更强。冻结的是研究策略，它仍可更新目标系统和工作记忆；考试期间ψ自修改另列在线元适应实验。[D03] §6

应按改进问题、任务流与独立演化历史重复；同一任务新seed只是新初态。指标包括固定预算独立净收益、达到目标成本、收益曲线、错误修复和未完成覆盖。产生晚ψ所花开发成本单独报告。Hyperagents v2已有冻结元代理及迁移实验，EmbodiedRSI v2有真实学习的记忆管理策略；本项目不能声称元改进思想空白，也不能把它们等同于本项目尚未做的机器人考试。[WHYPER] [WEMB]

### 4. 停滞处理和机制创造的限度

研究停滞至少区分：关键标签缺失、现有检查没有辨别力、执行器缺动作能力、训练数据不合格、优化方法失效、假设已被否定。保存候选的实际差异／语义签名、已检验前提和否定结果；相同假设若无新证据，换措辞不应获新一轮物理预算。预算内可以换实验或暂缓，越过领域／权限或到期则停止。

受约束程序搜索可以探索新方法，但生成代码不等于算法创造；需要超出预置候选的机制、可运行实现、强基线收益和新颖性复核。H3研究努力保留在唯一论文计划，当前没有历史不得补造。若考试未支持，应报告不支持或未决，不用多轮上升曲线替代。

<a id="q4"></a>
## 六、问题4：应改 Agent、VLA，还是协作关系？

### 1. 先区分失败解释，再选更新对象

一条失败轨迹通常无法唯一指定修复对象。观察不足、目标绑定错误、技能起态不满足、局部动作能力不足和控制时序不合适，可能产生相似终态。先问哪项低成本实验能改变更新选择，而不是先写提示或先开训练。

| 竞争解释 | 有辨别力的检查 | 若结果支持该解释 | 若结果不支持 |
|---|---|---|---|
| Agent看不到关键事实 | 给同一状态的额外合法视角／明确状态证据，保持动作工具不变 | 修ρA／观测接口，再比较规则与推理 | 继续查权限、执行能力；不能无限加图 |
| 目标或语言映射错误 | 全任务原指令、重述指令、经独立验证的目标绑定对照 | 修φ／提示或知识绑定 | 若绑定正确仍失败，查动作与起态 |
| 分解和交接不合适 | 整任务执行与不同粒度分解；检查合法起态和交接判据 | 修φ／ρB或恢复技能 | 若独立技能从正确起态仍失败，考虑θ |
| 底层动作能力不足 | 从已验证起态调用同一技能，控制信息与时序；再试合格示教更新 | 学θ，并测裸模型收益与旧能力保持 | 若训练不增益，检查数据/模型/配方而非默认再调Agent |
| 控制接口或时序问题 | 相同政策在正确动作单位、相同chunk与RPC时序下比较 | 先修合约，重新建立基线 | 才进入研究方法归因 |

诊断上界可以使用仿真特权状态，但应单列：它说明“若有这些信息是否可解决”，不是正常Agent的公平性能。仿真任意中间态分支目前没有已验证完整接口；同seed reset不能代替。无法精确分支时，使用预注册策略分配与新初态配对，并报告剩余随机性。[D02] [D03] [KENV]

completion11 的预置动作集合只允许hint，所以本次选择φ并不能证明提示更新比θ或ρ更划算。当前训练主要仍在独立准备／执行脚本，而非与所有Research动作对称可选。后续比较更新对象时要给各合法路径合理的开发、数据与验证机会；“易改项先成功”的工程便利不能冒充研究策略的最优性。[KRESEARCH] [KTRAIN]

### 2. 外部修复与选择性内化

长时序任务分配、用户语义澄清、外部知识和工具协调通常适合保留在Agent层。重复出现、局部可执行、起态与结果可标注、控制时延敏感的动作补救，则可能值得写入VLA。不是所有外部修复都应蒸馏：特权状态、不可执行教师、错误动作或仅在少数状态成立的恢复，不能直接作为普适示范。

建议路径是：先外部修复并验证 → 测量调用频率、成本、跨场景复用与实际动作质量 → 选择可内化片段和合格目标 → 更新θ → 分别评价裸VLA、组合系统、旧能力和总成本 → 重新确认外层规则是否还需保留。内化后Agent减少接管并不一定退化；它可能说明执行者确实获得了能力。组合成功率不变且裸VLA未升，尚无内化收益证据；若成功仍依赖相同补救，再检验是否持续依赖高成本编排，并同时评价成本、覆盖和分项能力。更新无效或评价精度不足也是竞争解释。

成本判断需要预期使用量：一次昂贵训练若只节省极少未来调用可能不划算；高频技能即使单次收益小也可能值得。现阶段使用明确的成本向量和部署频率情景，不能由未经校准的“未来价值分”直接决定大额物理投入。

### 3. 单体与专家池保持比较关系

| 方案 | 可能优点 | 重要代价 | 应触发采用的证据 |
|---|---|---|---|
| 单体VLA持续更新 | 调用简单、共享表示、无额外专家路由 | 遗忘与相互干扰，回归成本 | 小规模回放/正则即可保持旧能力且覆盖增长 |
| Adapter／有限专家 | 更新隔离、可回退、特化能力易保留 | 路由错误、显存/加载成本、版本组合膨胀 | 存在清楚异质能力且隔离收益超过路由维护成本 |
| 技能池（含程序技能） | 可组合、可解释、逐技能验证 | 入态碎片化、交接失败、能力标签可能虚增 | 真实组合任务收益和复用，而非仅技能条目增长 |

先用一个真实VLA加少量受控技能足以做判别，不预设专家池为用户决定。若训练同时重算归一化或修改processor，应明确标为θ＋processor联合升级；要归因于权重，需固定处理器或另设分离比较。θ变化后，动作归一化、processor、相机与工具接口、技能前提、路由置信、接管和恢复建议需要按依赖重新确认；静态任务定义与不可变历史事实可以保留。当前ρB的严格版本签名是合理防误用基础，但“全部拒用旧证据”与“全部继承旧策略”之间是否需要新的选择性机制仍待实验。[KCOOP] [KREL]

<a id="q5"></a>
## 七、问题5：具身接口能否让 Agent 发挥推理能力？

### 1. 语言子目标必须对应可执行合约

子目标写得更细，不必然更好。VLA若在完整任务轨迹上训练，过细分解可能把它送到训练中少见的中间起态，或者丢掉终点语义。技能记录至少应明确：合法指令／目标、可观测入态条件、动作与时域、完成判据、终态与交接条件、适用模型及版本、失败和未知语义。它们是可验证调用契约，不是仅有名字和自然语言说明的目录。

先比较整任务、较粗语义阶段和较细动作子目标，保持θ、允许工具和总执行预算一致；记录是否因分解产生新的起态分布。若细分失败而整任务成功，应减少分解；若只有具备合法恢复／定位工具后分解才有效，则收益应归于那项接口能力，而非语言推理本身。

### 2. 工具结束、技能完成与整任务成功分开

Agent应维护带时间和来源的任务／信念状态：当前目标与候选对象、已观察事实、推断及不确定性、技能起止、物体持有／接触可能性、最近一次新观测、待确认后置条件。历史“曾抓住”不等于现在还持有；工具返回正常不等于动作目的实现；Planner finish不等于原生任务success。

当前`TaskState`有实现，但已读Runtime并未形成完整实际消费者；关键推进审计中相应项也有N/A。C11提示要求检查抓取、释放与落稳，但独立process labels仍未知，说明仅改提示不足以落实状态合约。优先接入能改变下一动作的少量状态与独立判据，并保存unknown，不让模型凭叙述把未知变真。[KEVIDENCE] [KCRITICAL]；[A05-S07]

观察应在信息可能改变行动时触发：目标歧义、接触后状态变化、预期效果未出现、交接前提不明等。重复查看同一缓存帧不提供新的物理信息。`view_env_state`读取已有record；若要主动移动视角或刷新传感器，需要实际后端操作与成本记录，不能把只读图片工具当作已实现主动观察。

### 3. 时序与控制权：当前监督有明确边界

内部配置为`action_horizon=10`；本次继承`model_load.last_action_shape=[1,5,7]`，80次服务返回／客户端提案与派发均为5步，不把内部配置当成已经取得10步原始输出；一个`vla_execute`可含1—24个chunks，最长120环境步后才回到Planner。环境`chunk_step`是整块RPC，工具／环境锁串行。预算取消可在chunk边界发生，不代表LLM能在已派发RPC内部语义接管。[KTOOLS] [KENV]；[A05-S02]、[A05-S04]、[A06]

低延迟执行层适合处理动作合约、边界、预算终止、可直接测量的异常；Agent适合跨技能语义、证据解释和较慢恢复选择。固定频率、事件触发和不确定性触发应比较同样可用的信息、干预集合和总预算。改变chunk或观察频率后，要重建同一控制时序的纯VLA与规则基线，否则“Agent更好”可能仅来自更短的开环时间。

### 4. completion11 补证使接口边界更清楚

本次对继承动作链进行了数值核对：80次推理均引用当时最新的`observation_update`序号；400个客户端派发动作通过`rpc_link`与环境侧对应槽逐项相同；80个RPC各五槽反馈完整。30初始化步加400策略步等于430，不把RPC次数或模型请求再加成动作步。两个reset都在首个策略RPC前，不是失败后重试。[A05-S04]；[A06-S01]、[A06-S02]

这些记录排除了“只有规划文字、未向环境派发动作”以及“客户端与环境侧动作普遍未对上”的解释，并支持后续预测与最新观测更新序号的消费链绑定。但它们没有直接证明传感器质量、目标对象身份、控制器内部最终应用动作或实际关节运动。`controller_applied_action`和内部physics ticks仍明确缺失。Planner的视觉描述也不是独立过程标签。

图像消费者有历史源码、工具返回大小和后续视觉叙述相互支持；原图／视频和完整SDK媒体返回未随附件提供，不能称本次逐像素核对了模型所见。Research02则更明确地只有文字／路径、无图像查看和工具。这两类角色的信息条件必须分开，不能因为Planner能看图就推断Research也看到了视频。

### 5. 若 Agent 没收益，怎样定位瓶颈？

用逐项增加能力的诊断梯度，而不是一次换更强模型：先确认已有输入和调用语义；保持模型只增加真实可用观测；保持信息只增加合法干预机会／较短交接间隔；保持接口只更换推理策略；最后检验从正确入态执行的VLA能力。

- 新观察让简单规则也追平：优先修信息接口。
- 信息足够但当前调用无法及时改变结果：优先修粒度／权限，重建公平基线。
- 可控接口下更好的规划仍有效：再研究推理与协作策略。
- 正确目标、起态和调用下所有编排都失败：检验底层动作与训练。

这是一组诊断上界，不预设每种增强都应进入产品。实际增加接口后还需证明收益覆盖延迟、调用和错误干预成本。

<a id="q6"></a>
## 八、问题6：没有明显失败时，怎样主动获得有价值的新能力？

### 1. 能力认识应是经执行校准的状态

建议每个能力条目区分已掌握、证据不足、可由已有技能组合、需要学习、当前不可实现，并记录适用起态、版本、测量次数、不确定性与最近验证。自然语言自评和目录中存在技能名，只能形成假设。组合是否可达、先决技能是否可靠，要由真实执行校准。

当前`goal_value.py`／task policy使用带类型的目标catalog和witness，已有完整目标图的结构检验；其中value=1不等于任务效用、成功率、可行性或新能力收益。领域内新目标虽有提议入口，排名、派发、合格数据、训练和独立增益尚未形成完整闭环。不能把C11或后续goal-only输出写成主动能力增长。[KGOAL] [KTASKPOLICY] [D04]

新目标还必须同时绑定**环境实例化、独立成功判据与运行时终止语义**。只改语言却沿用旧目标native success会评错；只换末尾评分，仍可能被旧目标提前终止。实际执行和独立评价应消费同一目标语义，再判断能力是否不足。[KTASKPOLICY] [KRUNTIMEPY] [KENV]

### 2. 预算分配需要未来任务价值，也需要强简单基线

候选机会包括修弱点、扩条件覆盖、学习新技能、改研究方法。价值可以来自预计解锁的后续任务、可复用技能组合、减少未来学习／编排成本；预测应乘以可学习性与实际使用频率，并计入数据、训练、验证、复位和遗忘代价。结构性的“解锁关系”有助于提出假设，但没有真实执行校准时不能直接转成确定收益。

近期比较固定课程、失败优先、轮转／随机、实测学习进步及普通Bandit／信息价值规则，统一初始技能、外部任务流、权限与预算。没有失败时，失败优先也须有预先登记的fallback，例如覆盖不足区域轮转，不能让它停机形成弱对照。SAGG-RIAC以能力进步驱动参数化目标探索，是学习进步基线的一手依据；其连续任务空间不直接等同开放语言目标。[WSAGG]

保持一部分预算给证据不足但潜在价值高的区域，不能把全部预算给容易成功的任务。份额和触发阈值需要先导数据决定，不能现在凭空设成固定比例。

长期外部任务分布应由独立协议固定；系统可以提出新目标，但不能把未完成任务移出评分分母，或不断改测试集合来显示成长。真正新增能力应提升预留任务、组合任务或未来任务流的表现，同时保持旧能力。

### 3. 从能力缺口推导数据需求

| 数据类型 | 可可靠支持的用途 | 不能自动支持 |
|---|---|---|
| 失败轨迹 | 找失败条件、负例、诊断和离线回放 | 将失败动作当正确BC标签 |
| 恢复片段 | 学习从特定失败起态恢复；验证恢复是否可复用 | 把恢复动作当正常起态的最优动作 |
| 成功轨迹 | 经检查的示范、局部技能和保持数据 | 整段每步都高质量，或全任务标签适合所有局部动作 |
| 教师纠正 | 经动作合约和状态对应验证的目标动作 | 把特权信息或不同robot坐标直接蒸馏到学生 |
| 自主探索记录 | 状态覆盖、失败类型、训练候选筛选 | 无审核的自我模仿和模型自报成功 |

当前flywheel／collection已能记录输入、局部指令、动作提议／发送／环境返回等；但controller-applied action仍未知，导出训练language沿用整回合任务，局部指令在sidecar中。若研究局部技能内化，需要明确重新标注和片段起止，不能假设现有导出已生成合格子技能示范。[KCOLLECT] [KFLYWHEEL]

缺少controller-applied遥测不自动使数据不可训练：若学生输出本来就是同一控制接口命令，经过验证的命令—观测对可以适用；仍须区分proposal、已发送命令与实测运动，保留未知执行片段。`validate_dataset_manifest()`主要核查声明来源与本地契约，不保证示范质量；质量、学生信息充分性和片段标签另验，不能修改`source_kind`把自主轨迹冒充教师示范。[KTRAIN] [KCOLLECT]

先查已有合法示教是否覆盖目标起态；不足时进行针对性采集／教师纠正；可用成功／恢复片段必须经过独立质量与动作语义检查。训练和诊断数据可来自同一原轨迹，但用途、准入、权重和评价隔离应不同。当前7episode数据的`not_admitted`状态保留，不把“已导出NPZ”当准入通过。

### 4. 主动成长的独立验收

用预留的新任务实例、组合任务、连续任务流评价实际解锁、复用、迁移和旧能力保持；同时测裸VLA与外层辅助。对系统自提目标设置领域／可检验性筛查，学习后由独立任务评估价值。若新目标只是已有公开记忆内容的复用，应报告已有能力重组；若需要新动作且训练后裸VLA提升，才支持相应能力获得。

公开`RLinf/RPent-memory`的来源与固定revision已在前轮核对，本轮也确认其公开dataset入口；特定历史目录页此次访问失败，不等于文件不存在，不将其作为必须由用户补交的新前置材料；真正仍缺的是历史运行实际读取了什么，以及后续系统新增了哪些经执行验证的能力。这两种证据不能混为一谈。[WMEM] [A02-S09]

## 九、问题7：一篇论文应聚焦什么？

### 1. 有条件推荐与现有工作界线

四方向仍开放。F1最先筛查，排除标签、信息和接口错误；F2是有条件的主问题；F3规定有限物理预算的目标；F4保留可迁移研究方法的实质考试。完整系统与论文不是同一验收：系统可以完整但主假设失败，论文也不能以局部算法结果代替整个项目完成。[D00] [D02]

推荐的问题为：**当θ真实提升但历史协作建议的适用范围发生变化时，能否利用技能入态、交接和干预结构，少做物理验证而正确更新协作，并使选择验证实验的方法在新改进问题上迁移？**

宽泛主题已有直接近邻：Robo-COP已修订更新后旧建议；AdaRSI已有诊断后按需微调及“最低成功率优先”等对照；EmbodiedRSI v2有信息价值与学习式记忆；Hyperagents v2已有元代理迁移；SEAR区分重试与继承库。故“升级后重新适应”“主动实验”“研究者会变”均不足以独立作新颖性主张。[WCOP] [WADA] [WEMB] [WHYPER] [WSEAR]

### 2. 拟议机制、区别预测与强对照

候选机制先使用版本条件化的技能—入态—调用证据表，保留历史事实与当前建议的区别，估计直接执行和辅助执行的净价值差；优先复测会改变最优决定的上下文。可采用带不确定性的分层估计或小型可解释规则，不预设必须训练新网络。若取证操作会改变物理状态，后续价值必须按取证后的状态计算，并计入恢复和时间。

真正可能的新机制是：某种可观察的机器人结构能预测跨版本失配位置，减少错误复用和无用复测。通用信息价值公式、版本标签和日志本身不是新算法。至少应预测：优势集中在真实改变的技能／入态；不变区域少测且旧能力保持；无θ变化时不会频繁更新；优势在预留问题上仍存在；切断所称关键反馈后收益减弱。若切断反馈同时减少信息，要说明测到的是该信息通道总效应，不能声称所有条件仍完全相同。

强基线依次包括：旧B直接沿用；旧建议标待验证＋均匀复测；阈值／温度校准；短窗口／变化检测；同特征的上下文Bandit或普通信息价值；等预算轻量重训／GEPA式规则优化。固定周期训练也应保留相同数据质量与独立采用门槛，不用取消验收做弱对照。凡未重现原论文者，写明机制适配范围，不能宣称直接击败其原始结果。

### 3. 决定性实验与转向

先确认裸θ在独立目标技能上提升，再做θ×协作四格。四格中的新B先在θ1的开发／适应预算下产生并冻结，再将同一个B用于两种θ；分别适应所得的两个B另列实验。旧B触发版本签名拒绝／fallback时，测到的是门控行为；若研究旧内容的迁移，必须建立合法的受控比较绑定，不能把fallback当成旧策略，也不能关闭准入。初步若没有协作失配，保留旧B；简单校准已恢复收益，则采用校准；存在重要残余且可按结构定位，才进入选择性再验证方法比较。共同数据实验分离估计／决策能力，交互实验测主动取证总效应。

若候选方法仅靠更多信息、重试、计算、教师或人工获胜，应将这些资源增量归因并补强匹配基线。若局部结构在新任务上无效，应缩小范围或转向F1/F3的另一个真实残余。若晚ψ只在旧任务上好、共同晚期事实使早ψ追平或固定搜索追平，则不主张可迁移元改进。

近期预算和样本量尚未冻结。三轮中24次、少量历史或若干新问题都是筛查示例，不是足够精度或执行许可。先估计效应、方差、任务内相关性和单位成本，预先登记最小有用收益与停止规则；无信号或精度不足分别解释。完整设计见02文档。

### 4. 一条论文证据链容纳完整目标

真实θ更新提供能力变化；长期多轮任务流检验继承及协作再适应；主动成长提供不只来自失败的新改进问题；ψ共同起点考试检验研究方法迁移；第二动作类型检验一个核心机制的有限外推；Piper检验物理起态、反馈延迟、恢复和实际成本。各项应解释同一机制，不要求每项都成为独立新算法。

如果只有有限φ更新和工程闭环，价值可以如实报告为系统或实证进展；不能预先写成持续θ学习／元改进论文。若H3最终未支持，仍保存负结果和系统目标，并调整论文主张。

## 十、额外问题1：独立验收被反复使用后，如何防止选择偏差？

这是软件隔离之外的统计问题。evaluator不能改标签，不等于候选、停止时刻和下一轮协议没有依赖验收集。只返回accept/reject也可能逐步影响选择；完整诚实的工程Gate仍会成为调参反馈。`03 §7`已经提出开发／发布回归／最终封存分离，本次建议是落实跨轮暴露与最终确认，而非声称文档未考虑独立性。[D03] [D06]

C11使用公开seed0/1，开发和继承均涉及seed2；正式矩阵到部署资格是同一证据复用。原生标签与冻结分母支持有限工程验收，不证明总体提升或未来成功概率为1。未发现Research02实际输入自动包含全部正式分数的证据；它取合法开发事实。跨轮主持者／规则作者如何利用已公开结果，还需读取与决策记录，不能凭schema指控泄漏，也不能凭角色隔离宣称从未暴露。

最小工程对象是跨协议评价暴露记录：任务／初态身份、协议与版本、候选和ψ冻结时刻、谁读过何种粒度反馈、所有拒绝／重启／停止，以及数据何时转为开发或回归。保留当前工程门槛，论文另设冻结最终候选后的新样本确认。若回归上涨但新确认不涨，应考虑选择或分布特化；区间宽则未决，不把它叫负结果。

重复使用holdout的风险与受约束信息发布已有统计研究；Ladder的具体分数发布规则也不等于简单设置`.02 min_gain`。置信序列可处理适用过程的边看边停，但不能自动修复在同一有限集合上自适应选择候选的偏差；事后简单Bonferroni也不能修复原本无效的检验。近期更可靠的方案是充分开发反馈、回归与一次新的最终确认，按任务／历史而非帧数计独立样本。[WADAPT] [WLADDER] [WCS]

<a id="extra2"></a>
## 十一、额外问题2：谁负责制造下一次有效物理起态？

物理世界不会在任务结束后自动清空。下一步可能是继续利用当前状态、恢复、复位或换任务；这些选择改变学习分布、人工成本和方法排名。系统只选择容易的后续状态，能表现得长期成功却没有新增能力；每次都需要人工摆场的“低交互次数”也未必低成本。

当前LIBERO已有reset次数、时间、setup／policy动作分区，C11继承80次RPC的动作链可核；不能说项目完全没有复位计费。`manual_seconds=0`只对应非交互运行窗口，不代表数据准备、部署或真实机器人全流程无人参与。软件恢复前还应重新确认物理状态，避免继续执行已失效的动作意图。[KRUNTIMELOG] [KRUNTIMEPY]

Piper相关证据目前受限。仓内RLinf有硬件检查代码，但其文档明确尚无受支持任务／训练工作流；`PiperEnv.step`为6个绝对关节角（弧度）＋0—1夹爪，`reset`只回机械臂rest pose，不恢复物体。当前LIBERO是归一化OSC位姿增量＋夹爪，同为7维不能直接互换。实际计划后端是库外lerobotv6，需独立核对版本、控制频率、动作/观测、模型与数据匹配，不把另一个源码目录当现场可用链。[KPIPER] [KACT] [D01]

近期先做完整循环的操作性审计，估计摆场、执行、恢复、人工介入与等待；具体规模由现场资源决定。若复位便宜稳定，保留简单程序或人工；若少数恢复占主要成本，比较固定恢复与Agent在同一恢复目录中选择；若大部分状态不可自主恢复，先解决数据采集可持续性。不要为一个边界尚未测量的问题立即另开无复位RL项目。

独立固定起态考试回答能力是否提高，连续物理任务流回答系统是否能持续工作；后者按任务流／时段重复。R3L和SOAR分别提供利用扰动产生学习状态、依据当前场景提出任务的先例，但其受控条件不证明Piper开放场景能全自动恢复。[WR3L] [WSOAR]
