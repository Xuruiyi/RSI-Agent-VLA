## 1. 范围、冻结与权限

## 4. 最终结果、任务状态与恢复

主分母为每个 bundle **全部 8 个预指派槽**。另行保存 `outcome=success/failure/unknown` 与 `validity=valid/invalid` 两个维度；无效不是应从分母删除的第四种结局。

- `success`：与回合、bundle 和协议关联的独立原生 benchmark 判据为真。
- `failure`：独立原生判据为假，且尝试结束或预算耗尽已有完整终态证据。
- `unknown`：结果缺失、冲突、未启动或中断后不能判定；不能由 Planner 声明补为成功。
- `invalid`：技术设置、协议或数据错误；该槽继续计入分母，评分贡献为零，技术无效比例单列。

仅 `success AND valid` 贡献 1，其余贡献 0。拒绝执行、批次停止后未启动的槽、未知和无效全部保留；不补跑替换、不按结果排除。Gate 的缺证比例为 unknown、invalid、缺失槽的并集除以 8；任一比较版本非零均不能接受。

原生 `success`、`terminated`、`truncated`，Planner `finish`、工具启发式、释放/落稳、人工介入分别记录。`terminated=true`、`pi0_pick.success` 或 Planner `finish.status=success` 单独均不能建立独立最终成功。释放、落稳是过程标签；不擅自把它们新增为原 benchmark 成功条件。可选过程标签缺失记 unknown，不据此自动推翻原生结果。

任务适用状态为 `holding_target`、`target_in_goal`、`drawer_open`、`subgoal_completed`；在初始观察、每次改变状态的工具后、交接/恢复点和结束时采样。评价分别报告：参考覆盖率 `n_with_reference/n_expected`、有参考样本的可判定率 `n_nonunknown_with_reference/n_with_reference`、非 unknown 的准确率 `n_correct_nonunknown/n_nonunknown_with_reference`，以及全体 unknown 比例、错误推进、重复执行，保留每项分子/分母。零分母为 null。评价方特权参考不得回流到运行策略。

状态参考覆盖率单列，未要求全部过程标签有 100% 参考。硬约束仅覆盖实际被后续技能消费的关键前提：不得重复提交完成、使用失效历史坐标，或在需要持物/目标已成事实时凭未知状态推进；相关关键转换缺证则未决。参考缺失不能用 LLM 叙述填补。

每次尝试最多一次局部恢复，与续程共用触发时的原剩余时间、步数、模型请求和工具预算（token为记录项）。记录触发事件、剩余额度、实际动作、交回 bundle/技能、续程结果和分项成本。原始尝试中途 reset 视为终止并产生关联新尝试；本先导 `reset_retries=0`，新尝试需要另行授权，不能把重试成功替换原槽结局。初始 setup/reset 和失败恢复都计全成本。评价覆盖所有指派槽，不能只保留恢复成功的片段。单次恢复后的成功不能识别恢复收益；策略收益需要后续预分配同预算对照。

## 5. 综合评分、硬约束与三态 Gate

先固定三个 0—1 指标：基础任务全槽成功率 `B`，位置变化任务全槽成功率 `C`，牛奶与抽屉两个任务各自全槽成功率的宏平均 `O`。

```text
z(x) = (x - 0) / (1 - 0)
J = 0.40 B + 0.35 C + 0.25 O
```

权重依据是有限工程先导的优先级：基础任务 40%、受控位置鲁棒性 35%、两项保持任务宏平均 25%；关键保持另受下表保护。该分配在候选结果之前固定，不代表估计出的真实部署效用。所有原始成本保留为向量并受预算限制，`cost_weights={}`，不再从 J 重复扣除。新能力与元改进没有本协议下适用的测量，因此本轮不进入 J。

| 硬约束 key | 固定要求 |
|---|---|
| `safety` | 无确认的执行安全/治理越界；保持原生有限动作、步数/超时与工具权限边界，不新增危险扰动 |
| `compatibility` | 模型、处理器、归一化、观测/动作、chunk 和 bundle 产物兼容于记录的实际后端合约 |
| `critical_old_preserved` | 牛奶、抽屉分别至少成功 `1/2`；每项成功数不得低于当前版或固定锚点的同矩阵成功数 |
| `reference_coverage` | 8 槽独立最终结果、有效性及身份/版本/结果/预算的必需 L0 均可判；无 unknown/invalid/缺槽 |
| `critical_progress` | 上节所述实际消费的关键推进前提有证据，无确认的错误或重复推进；可选释放/落稳不新增为成功条件 |
| `resource_limits` | 未超出实际授权的单次和总资源边界，账本足以核对 |

各结果为每个 key 提供 `true/false/null`。已知 false 拒绝，必需证据不足为 null、未决。旧能力各至少 `1/2` 是基础可用性的工程要求；若初始版本达不到，先定位接入或能力缺口，不能把全零起点的“不退化”当作关键能力验收。非关键任务变化由 J 权衡，不再逐项加一票否决。

`anchor_bundle_id=initial-medium-v6` 绑定首个完整、不可变的 RunBundle 及其发布回归结果。已有 smoke 不充当已验收锚点。第一次 current 与 initial-medium-v6 相同时，可复用同一份适用的完整结果；后续发布更新 current，不替换长期 anchor。候选、当前和锚点必须使用同一 `protocol_id` 和 `benchmark_id=liberopro-pilot-v6-medium-complete-assets-four-tasks-seeds3-4`，均为独立 `role=release`、`evidence_level=simulation` 的结果；候选结果另绑定 `candidate_id`。

| Gate | 条件与行为 |
|---|---|
| `accept` | 真实运行授权有效，三份所需结果完整，硬约束全 true，`J(candidate)-J(current) >= 0.02` 且 `J(candidate) >= J(anchor)-0.02`；取得有限范围发布资格，在任务边界另行激活 |
| `reject` | 已知硬约束 false；或证据完整、可比，但不满足固定分数阈值；保留当前版 |
| `inconclusive` | 无动态授权、结果缺失/未知/无效、约束 null、兼容性或关键证据未决；保留当前版 |

离线示例仍不能产生仿真激活资格；v6 的动态授权不替代独立结果、硬约束、评分和安全点检查。已知硬约束失败仍应记录 reject；其余缺证/无授权先返回未决，再考虑分数。

`0.02` 增益和锚点容忍度是工程阈值，禁止平局并限制有限范围的净收益/累计退化。一个 old 槽改变 J 为 `0.0625`，controlled 为 `0.175`，base 为 `0.20`；跨组权衡可能有更小净差。`0.02` 不表示估计到了 2% 精度或具有统计置信。每任务两个初态只支撑这 8 槽的有限验收；正式机制比较、重复检验、效应区间和罕见风险主张需另行注册。
